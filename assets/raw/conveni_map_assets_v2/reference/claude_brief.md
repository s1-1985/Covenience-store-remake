# 建物アセット生成ブリーフ(ChatGPT画像生成用)

作成日: 2026-09-22
用途: このファイルの内容をそのままChatGPTに貼り付けて、町マップ用の建物スプライトを発注するための仕様書。
データ出典: `reference_sim/conveni_sim/baseline_data.py`(`TOWN_BUILDINGS`、攻略本DATA4表 書籍92-95頁からの転記、CONFIRMED_OFFICIAL)。
footprint(タイル数)・建物属性・名称は原資料からの確定データ。ピクセルサイズ換算・見た目の方向性は本ドキュメントで新規に定義した提案値(後述)であり、原作の再現ではない。

---

## 0. なぜ今までうまくいかなかったか(推測)

これまでChatGPTに漠然と「建物のアセットを作って」と頼むと支離滅裂な結果になっていたのは、おそらく次の理由による(私の推測です、断定はできません):

1. 「原作を模写するな」という制約だけが独り歩きし、代わりに**具体的な見た目の指示が何もない**状態でChatGPTに投げていた → ChatGPTは何を描けばいいか分からず迷走する。
2. 建物ごとのサイズ比率(タイル数)が伝わっていなかった → 正方形/縦長/横長の区別がつかず、ゲームのマップに置いたときにサイズ感が合わない。
3. 生成のたびにスタイル(視点・塗り・線の太さ)がリセットされ、統一感のないアセット群になっていた。

この仕様書は、上記3点を解消するために「原作を参照させず、代わりに具体的な仕様(サイズ・用途・外観の方向性)を渡す」形で構成している。

## 1. 共通スタイル指定(ChatGPTへのプロンプト冒頭に毎回貼り付けること)

以下を、どのバッチを発注する際も**プロンプトの先頭に必ず含める**こと。生成のたびにこれを貼ることで、複数回に分けて発注してもスタイルが揃う。

```
あなたは架空のコンビニ経営シミュレーションゲーム(特定の実在タイトルを参照しない、完全オリジナルの新規タイトル)向けに、
町マップ上に配置する建物のドット絵アイコンを作成するイラストレーターです。

【視点・様式】
- 真上から見た「見下ろし型」(トップダウン)の建物アイコン。等角投影(アイソメトリック)ではなく、平面的な建築アイコンとして描く。
- 1990年代後半の家庭用ゲーム機で見られたような、粗すぎない中解像度ドット絵(擬似ドット絵/pixel-art風)。
- 影は左上から差す想定で軽くつける程度。過度な陰影・過度なディテールは避け、遠目のマップ上で建物の種類が一目で判別できることを優先する。
- 線画はやや太めの輪郭線、彩度はやや高めのポップな配色(コミカルな経営シムのトーン)。
- 背景は透過(アルファチャンネルあり)、または単色の無地背景(#00FF00などのクロマキー色)で統一すること。

【禁止事項】
- 特定の既存ゲーム・アニメ・キャラクターのロゴ、看板文字、意匠を模倣しないこと。
- 実在の企業ロゴ・商標を描かないこと(仮想のオリジナル店名・看板でよい)。

【出力形式】
- 各建物は指定されたキャンバスサイズ(px)の正確な比率で出力すること(後述の表を参照)。
- 複数建物をまとめて発注する場合は、1枚の画像内にグリッド状に並べ、各セルの直下に建物の英語ID(例: kindergarten_building)をラベルとして明記すること。
```

## 2. ピクセル換算ルール(本ドキュメントで新規に定義、原作の値ではない)

原作の町マップにおける建物1マスあたりの実ピクセル寸法は資料からは分からない。ゲーム内で使う際にどのみち拡大縮小するため、**アセット作成用の基準値として1タイル=64pxを採用する**(この場を新設。将来変更可)。

- キャンバスサイズ(px) = footprint(幅タイル数 × 高さタイル数) × 64
- 例: footprint (3, 2) の建物 → 幅192px × 高さ128px

以下の表の「footprint」列は `(幅, 高さ)` の順(横方向タイル数, 縦方向タイル数)。

## 4. 発注の進め方(推奨ワークフロー)

1. 上記表をカテゴリ単位(3.1〜3.8)でバッチに分けて発注する(1回のプロンプトに詰め込みすぎるとChatGPT側の精度が落ちるため)。
2. 各バッチのプロンプトは「第1節の共通スタイル指定」+「そのカテゴリの表(ID・footprint・キャンバスpx・外観の方向性)」をそのまま貼り付ける。
3. 出力された画像(グリッド状・ラベル付き)を受け取ったら、そのままこのセッションに投げてください。私の方で:
   - 各セルが対応する`ID`に対応しているか
   - footprintの比率(縦横)が仕様通りか
   - スタイルがカテゴリ間で大きく乖離していないか
   を確認し、ズレがあれば再発注用の修正プロンプトを作ります。
4. 個別に1枚ずつ切り出す作業は、まとまった数が揃ってからで構いません。
