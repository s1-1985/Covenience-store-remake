# Gemini総合解析レポート差分監査 2026-09-05

対象: ユーザー提供のGemini『ザ・コンビニ ～あの町を独占せよ～』総合解析・経営戦略報告書。

目的: 既存Remake研究との差分を取り、実装へ追加できる新規事項と、推測を事実化している箇所を分離する。

## 判定

Gemini報告の大部分は、既に回収済みの初代PS/SS専用Wiki・PS/SS実プレイ記録の再構成である。新しい完全マスターテーブルは含まれない。一方、既存repoで明示していなかった実装境界/テストケースが2件見つかった。

## 1. 新規採用: 23時以降の臨時休業0%トラップ回避

初代専用Wiki FAQには以下が明記される。

- 日付変更時の顧客独占率でその日の客入りが決まる。
- 内装/改築のため臨時休業のまま0時を迎えると0%で計算され、その日1日は客が来なくなる。
- 臨時休業への変更は0時を過ぎてから行う。
- **23時を過ぎていた場合は、営業時間を7時〜23時へ変更することでも回避できる。**
- 臨時休業店を再開する場合は日付変更直前に営業再開すると翌日から客が戻る。
- 日中の天候変化でも独占率は再計算される。

Source: https://wikiwiki.jp/theconveni1/FAQ

Confidence: `CONFIRMED-COMMUNITY-FIRST-TITLE`

実装上の意味:
- `temporary_closed` と `outside_business_hours` は需要計算上同一状態ではない。
- 0時時点で通常営業時間外でも、営業時間設定そのものが有効なら独占率0へ強制されない。
- 営業時間変更は翌日需要スナップショットの入力となる。

回帰テスト候補:
```text
23:30 temporary_close -> 00:00 => next_day_share = 0
23:30 set_hours(07:00-23:00) -> 00:00 => next_day_share != forced_zero
```

## 2. 新規採用: 初級は「コンビニを営業せず」クリア可能なエッジケース

初代専用Wikiの初級小ネタでは、概ね以下の攻略例が示される。

- 最安値2000万円級の土地に複数支店を先行出店。
- 全店を臨時休業。
- ライバルの出店/町発展を利用して地価上昇を待つ。
- 自店を順次売却し、売却資金を施設誘致へ投入。
- 町人口2万人到達で都庁条件を満たす。
- 自社+ライバル合計10店舗上限のため、自社店を売却しないとライバルの新規出店を阻害する。

Source: https://wikiwiki.jp/theconveni1/%E3%82%B2%E3%83%BC%E3%83%A0%E3%83%A2%E3%83%BC%E3%83%89%E6%94%BB%E7%95%A5

Confidence: `CONFIRMED-COMMUNITY-FIRST-TITLE / STRATEGY-EDGE-CASE`

これはバランス値ではなく、以下のシステム分離を示す受け入れテストとして有用。
- 初級クリア判定は店舗営業実績を要求しない。
- 休業店舗も店舗数上限を消費する。
- ライバル活動による町発展は自社営業を必要としない。
- 店舗売却価値は地価上昇の恩恵を受ける。

## 3. Gemini報告で過剰断定されている事項

### 3.1 人口15000はhard capではない
Gemini: 「1万5000人付近で完全に頭打ち」。

原資料: 「誘致をしないと1万5000人辺りから**ほとんど増えなくなる**」。

採用: 自然成長鈍化点として保持。hard capにはしない。

### 3.2 天候で毎時再計算、ではない
Gemini: 「天候によって顧客独占率は毎時再計算」。

原資料: **日中に天候が変化した時**にも再計算される。

採用: `onWeatherChanged` を再計算トリガとする。毎時tick再計算は根拠なし。

### 3.3 改築1.5倍は独占率ではなく売上観測
Gemini: 大規模化で「顧客独占率は最大で1.5倍程度」。

原資料: 改築で品揃えが増え独占率が上がるが、**売り上げはせいぜい1.5倍程度**という攻略観測。

採用: `sales uplift ~1.5x` を provisional observation とし、share係数1.5にはしない。

### 3.4 本店デバフはhardcodedと断定しない
Gemini: 「マイナス補正がハードコーディング」。

原資料: 「何故か本店はどこに建てても顧客独占率があまり上がらない」という観測。

採用: `main_store_weak_competition_bias` 候補。原因・係数・実装形態は未確定。

### 3.5 大型ワゴンのついで買い効果は推測
Gemini: 大型ワゴンは内部注目度が高く、クロスセル確率が高いと断定。

原資料: 注目度が少し高いことは記載されるが、「注目度は**おそらく**ついで買いの確率に影響」と推測形。

採用: `attention > small_wagon` は候補、`cross_sell_probability_bonus` は未確定。

### 3.6 雑誌紹介はexact +2と断定しない
Gemini: 体力以外の全パラメータ一律+2。

既存監査: Wiki表現は「2ほど」。

採用: approximate +2。攻略本/実機検証待ち。

### 3.7 体力は「一切成長しない」ではない
Gemini: 体力上限は固定で一切成長しない。

原資料: 「わずかに増減する」とも記載。

採用: base staminaとruntime/long-term variationを分離して保留。

### 3.8 サービス設備の効率説明に算術上の誤り
Gemini: ベンチは「面積あたりサービス上昇値が最も高い」。

原資料値:
- 観葉植物: +2 / 1マス = 2 per cell
- ベンチ: +3 / 1マス = 3 per cell
- 噴水: +25 / 4マス = 6.25 per cell

面積効率は噴水の方が高い。ベンチの長所は**維持費あたり**の効率と小分け配置の柔軟性。

また、噴水2個は設備効果だけなら+50であり、「噴水2個だけでサービス100」とは言えない。Wikiは「最初から噴水2個は置いておきたい」と攻略推奨しているだけ。

### 3.9 タワー駐車場比較の「お釣りがくる」は誤り
Gemini: タワー4800円で2階建20基（80台）を維持してお釣りがくる。

実際:
- 2階建1基 = 240円/日
- 20基 = 4800円/日

同額であり、お釣りは出ない。

原Wikiの比較は、タワー1基20台/4800円を**2階建3基12台/720円**へ置換し、大幅節約する例。

### 3.10 0%一般時を「完全に客が途絶える」と固定しない
Geminiは0%で完全停止と説明するが、既存パラメータ抽出では一般論として「0%ではほぼ来店しない」としている。

ただし、臨時休業のまま0時を跨いで0%スナップショットになったケースについては、FAQが「その日1日は客が来なくなる」と明記している。一般0%と休業0%スナップショットは区別する。

## 4. 既知情報の有力な再整理（新規数値ではない）

Gemini報告は以下を一つの因果モデルとして整理しており、実装設計上は有益。
- 日付境界の需要スナップショット
- 価格・営業時間・天候による顧客独占率変化
- 店員の教育/敏捷性/社交性と実務能力上限の分離
- 店舗規模拡大と清掃/警備要求負荷のトレードオフ
- 休業中の固定費停止と補充原価継続
- ライバル排除、地価上昇、誘致を跨ぐマクロループ

ただし、これらを数式化する際はGeminiの戦略解説を係数へ変換せず、原資料の直接数値と観測値を分離する。

## 5. 結論

今回のGemini報告から新しくrepoへ昇格する価値があるのは主に:
1. 23時以降は7:00-23:00営業時間へ切替えることで臨時休業0%トラップを回避できる。
2. 初級は全店休業+地価上昇+売却+誘致でもクリア可能であり、営業実績がクリア条件に依存しないことの強い受け入れテストになる。

それ以外の大部分は既知情報の再整理であり、攻略本待ちの大穴（店舗6種完全表、全什器、全商品、35店員、許可料金/距離、町施設完全表、数式類）を直接埋める新データではない。
