# 月内シミュレーション区間と人気低下境界 2026-09-06

対象: 1997年PS/SS版『ザ・コンビニ ～あの町を独占せよ～』のみ。

## 目的

月内の時間進行が実際にどこまで連続シミュレーションされるかを明確化し、人気・経済・AI・イベント処理を暦日ベースで誤実装しないための境界を記録する。

## 新規確認事項

### 1. 月内で実時間進行するのは月初から4日目まで

初代PS/SS版専用攻略WikiのFAQでは、ゲーム内で通常の時間進行が行われるのは「月初から4日目まで」で、5日目から月末までは一気に次月へスキップすると明記されている。

- 証拠レベル: **B+ / FIRST-TITLE-DEDICATED-COMMUNITY-OBSERVATION**
- 適用範囲: PS/SS版共通情報として掲載されているが、PS版・SS版それぞれの一次画面比較は未実施。
- 出典: https://wikiwiki.jp/theconveni1/FAQ

このため、内部時間モデルを「1か月=現実の暦日数だけ逐次シミュレーション」として作ると原作から外れる。少なくとも表示・runtime上は、1〜4日目がアクティブ区間、5日目〜月末が圧縮区間として扱われる。

### 2. 5日目〜月末のスキップ期間でも、人気は日数分まとめて低下しない

同FAQでは、5日目から月末までをまとめて飛ばす際、人気パラメータは「1日分しか低下しない」とされる。

- 証拠レベル: **B+ / FIRST-TITLE-DEDICATED-COMMUNITY-OBSERVATION**
- 出典: https://wikiwiki.jp/theconveni1/FAQ

別ページでは人気は最大100で、店の総合評価が低いと1日ごとに最大15低下すると説明されているため、月末圧縮区間で「残り日数 × 日次低下」を一括適用する実装は不整合となる。

- 補助出典: https://wikiwiki.jp/theconveni1/%E9%A1%A7%E5%AE%A2%E7%8B%AC%E5%8D%A0%E7%8E%87

### 3. 宣伝イベントの日時はアクティブ区間内に集中している

初代専用Wikiの宣伝表では、宣伝イベントは1〜3日目に発生する。確認済み時刻は以下。

- ラジオ: 1日目17時
- TV: 1日目19時
- 新聞広告: 2日目7時
- ダイレクトメール: 2日目10時
- 飛行船: 3日目15時

したがって、少なくとも既知の有料宣伝イベントは4日目までのアクティブ時間区間だけで完結する設計になっている。

- 証拠レベル: **B+ / FIRST-TITLE-DEDICATED-COMMUNITY-DATA**
- 出典: https://wikiwiki.jp/theconveni1/%E5%AE%A3%E4%BC%9D

## 実装上の含意

月進行は次のように分離できる。

```text
month_start
  -> active_day_1
  -> active_day_2
  -> active_day_3
  -> active_day_4
  -> compressed_month_tail
  -> next_month_start
```

`compressed_month_tail` では、少なくとも人気低下を残日数分ループさせない。

現時点で推奨できる境界は以下。

```text
active_runtime_days = 1..4
calendar_tail = 5..month_end
popularity_decay_on_tail = one_daily_step_observed
```

ただし、この圧縮区間で売上・仕入・給与・維持費・建物建設・人口増加・ライバルAI・店員成長・顧客独占率・イベント抽選がどう集計されるかは未確定であり、今回の証拠から一括して推定してはならない。

## 未確定事項

1. 5日目〜月末の圧縮区間で経済収支が何日分として処理されるか。
2. 店員能力成長、清掃、警備、体力などが圧縮区間で進行するか。
3. ライバル店の出店・撤退・買収関連AIが圧縮区間で評価されるか。
4. 誘致施設や町建物の完成判定が4日目終了時か次月1日か、内部で別処理されるか。
5. 人気以外の「日次低下/上昇」パラメータに同じ1日分ルールがあるか。
6. 2月・30日月・31日月で圧縮処理に差があるか。
7. PS版とSS版で完全に同一か。

## 実装開始可否

**月内時間軸の骨格実装は開始可能。**

ただし、圧縮区間を「残日数分の通常日次tick」として処理するのは避けるべきである。まず `active_days` と `month_tail_transition` を別イベントとして実装し、人気についてのみ今回確認した単発低下を反映できる構造にする。その他の経済・AI・イベント処理は、追加観測が揃うまで差し替え可能なまま保つ。
