## 原処理と本体

`8003C628..3CB78` は0.5マスを上から行順に走査する。現在のグリッド値が0、対応する床コードをsigned8で読んだ値が0～15なら、`trunc(code/5)*5+rand()%4+1` へ書き換える。1タイルに属する複数の空セルが順に同じ床を書き換え、それぞれ乱数を消費する。15から16～19になる場合も元処理のまま扱い、独自に上限を14へ丸めない。

bit31のあるアンカーはkindを取り出し、53未満かつ分類下位byteが4/6以外なら、元の幅・高さ×2の占有矩形を0にする。原方向2/3では幅と高さを交換する。アンカー自体へ戻って床を書き換え直す処理はないが、後のセルは消去後の0を見る。レジ37～42、控え室48/49は残る。53以上の壁マーカー等まで同じ分類で消さない。

`program_fire.gd` で、この可変走査を実装した。ネイティブの配置・壁・人物位置から、ここで読む空/非空・アンカー・kind・方向だけを一時グリッドへ構成する。アプリの回転0/1/2/3は原0/3/1/2へ対応させる。全メモリーや画像ビットを本体の常設モデルにするものではない。

焼失した什器に属する商品のみ、返金せずに除去する。旧 `_withdraw_product` や改装の再経路設定は店員の仕事状態を変えてしまうため使わない。原と同じく、客の行動を無効化し、配属店員の体力0・人気5を適用する。店員のID・仕事・目標・経路、評価、売上、現金をこの後処理で独自に初期化しない。被害表示額は事件前の現在売上×8であり、消えた商品の原価合計ではない。

## ネイティブ表現と制約

アプリは原20固定スロットではなく可変の人物オブジェクトを使うため、有効客へsource_state=0/phase=doneを反映する。生きたオブジェクトの買物額・所持金・座標等は保持し、来客履歴の全消去はしない。ただしセーブは非活動人物の32byte全てを保存する原カード形式ではなく、従来の完了人数等を保持する形式である。

駐車占有は派生値であり、原事件末尾に即時再集計を足さない。一方、非活動の客による永久占有を残さないため、次の営業更新で有効な自動車客から派生カウンターを再集計するアプリ上の接続を置いた。途中保存にはsource_fire_recountを保持する。この次更新の再集計を原関数の命令として確認したと主張しない。
