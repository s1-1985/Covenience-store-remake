# 初代店員「体力」固定/増減の資料内矛盾 2026-09-05

対象: 1997年PS/SS版『ザ・コンビニ ～あの町を独占せよ～』。

目的:
- 初代専用店員Wiki内にある `体力は固定` と `わずかに増減する` の表現衝突を明示し、Remakeで誤って最大体力を成長値として確定しない。

Source:
- https://wikiwiki.jp/theconveni1/%E5%BA%97%E5%93%A1

---

## 1. 実務パラメーター説明では「上限値は一切増減しない」

同ページの `体力` 説明:

- 初期から固定。
- 上限値は一切増減しない。
- レジ、補充、清掃で現在体力が減る。
- 0になると休憩室へ行き、全回復まで待機する。

証拠レベル: CONFIRMED-COMMUNITY（ページ記載）

---

## 2. 雇用画面パラメーター側の説明では「わずかに増減する」

同じページ後半、雇用画面の `体力` 説明には:

- 高いほど休憩するまで長く働ける。
- 高体力ほど休憩時間自体も長いが、移動を考えると効率が良い。
- `わずかに増減する`。

とある。

証拠レベル: CONFIRMED-COMMUNITY（ページ記載）

### 矛盾

同一ページ内で:

```text
A: max stamina never changes
B: stamina slightly increases/decreases
```

が併存している。

---

## 3. 現時点の安全な解釈候補

可能性:

1. `現在体力` が勤務/休憩で増減することを後半が簡略表現した。
2. 雇用時表示値と実務上限値が別概念で、表示値だけ微変動する。
3. 年齢/イベント等により本当に最大値が微変動する例があり、前半の「固定」が不正確。
4. Wiki編集時の表現矛盾。

どれかは未確定。

### baseline方針

データモデルでは必ず:

```text
Staff
- stamina_max
- stamina_current
```

を分離する。

初期実装では `stamina_max` を固定値として扱うのが第一候補だが、PS実機/1997攻略本で確認するまで「永続的に絶対変化しない」と仕様書へ昇格させない。

---

## 4. 既に強く確定している体力挙動

同ページと複数初代資料で強いもの:

- 作業で current stamina が減る。
- 0で休憩へ向かう。
- 原則全回復まで休む。
- 敏捷性が休憩中の回復量（+2になる確率）へ影響する観測がある。
- 解雇→再雇用で体力満タンに戻る原作裏技がある。

したがってスタミナ状態機械そのものはbaselineへ入れてよい。

未確定なのは主に `stamina_max` の長期変動。
