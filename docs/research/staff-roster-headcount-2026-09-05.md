# 初代店員名簿・店舗人数追加調査 2026-09-05

対象: 1997年PS/SS版『ザ・コンビニ ～あの町を独占せよ～』。

目的:
- 35人の店員名簿を初代専用証拠だけで復元する。
- 「1店舗3人」の意味を、開店時人数・通常運営人数・上限に分けて再検証する。
- PS/SS差や資料内の誤記を勝手に統合しない。

---

## 1. 店員候補は35人

初代専用Wikiで明記:

- 店員候補は計35人。
- 10店舗運営では35人中30人を雇う必要があるとされる。

Source:
- https://wikiwiki.jp/theconveni1/%E5%BA%97%E5%93%A1

証拠レベル: CONFIRMED-COMMUNITY

### 意味

店員は無限生成ではなく、有限の固有候補プールとして作るべき可能性が非常に高い。

---

## 2. 新規出店時は「店長 + 従業員2名 = 3名」

初代PS版レビューは新規出店フローについて:

- 店長1名
- 従業員2名
- 計3名

を雇うと明記する。

Source:
- https://codevis.nobody.jp/review-ps/the_convini.html

証拠レベル: CONFIRMED-COMMUNITY-SINGLE-SOURCE / PS-SPECIFIC

### 現時点で確実に言えること

`新規出店時の標準構成 = 店長1 + 従業員2` は非常に強い。

ただし、これは「営業中は常に3人未満にできない」という意味とは限らない。

---

## 3. Saturn実機プレイでは2人体制で小型店を運営している

2013年のSaturn版実機プレイ記録では、新店舗の立地をテストする方法として:

- 最小規模の店舗
- 従業員を2人にする
- 2日目以降、補充/清掃/レジが追いつかない程度に客が来るなら成功立地と判断
- 成功と判断したら店舗を拡張し、従業員を3人に増やす

という運用が明記される。

Source:
- https://reverend.blog-fps.com/%E3%82%B2%E3%83%BC%E3%83%A0%E9%9B%91%E8%AB%87/%E3%82%B6%E3%82%B3%E3%83%B3%E3%83%93%E3%83%8B%E3%80%80%EF%BD%9E%E3%81%82%E3%81%AE%E8%A1%97%E3%81%A7%E3%81%AE%E3%82%93%E3%81%B3%E3%82%8A%E3%82%84%E3%82%8D%E3%81%86%EF%BD%9E

証拠レベル: CONFIRMED-COMMUNITY-SINGLE-SOURCE / SATURN-REAL-PLAY

### 重要な修正

以前の研究で「1店舗3人固定」に近い表現をした箇所があるが、現時点では厳密には:

- 新規出店時の標準: 3人
- 通常/最大運用人数: 3人の可能性が高い
- 2人体制で営業可能: Saturn実機記録で強く示される
- 1人体制が可能か: 初代では未確認
- PSでも2人へ減員可能か: 未確認

とする。

baseline実装で `staff_count == 3` をハードコードしない。

データモデル候補:

```text
StoreStaffing
- manager: 0..1
- workers: 0..2
- max_total_staff: 3  // strong candidate, not yet PS-visual confirmed
```

`minimum_total_staff` は未確定。

## 4. 「10店舗で30人必要」の解釈

初代Wikiでは「10店舗にすると35人中30人を雇う必要がある」とされる。

これは1店舗3人体制を前提とした攻略上の記述であり、3人が実用上の標準/上限であることを強く補強する。

ただしSaturn実機記録の2人体制と矛盾しない。

解釈:

- 10店を高評価で本格運営するなら3人×10店 = 30人
- 店を最低人数で一時運営できる可能性は別

証拠レベル: CONFIRMED-COMMUNITY

同記事後半の4号店従業員一覧:

- `小宮千明` と記述

Source:

## 10. 店員の運営AI: 3人全員が同時休憩する

Saturn実機記事の冒頭で:

- 店員3人が全員同時に休憩室へ入ってしまい、レジが無人になる

という実挙動が明記される。

Source:
- 上記Saturn実機記事

証拠レベル: CONFIRMED-COMMUNITY-SINGLE-SOURCE

### 実装上の意味

原作店員AIには「最低1人をレジへ残す」といった完璧な協調制御がない。

baselineでは完全なバグ再現は不要だが:

- 各店員が個別体力を持つ
- 各自が独立に休憩判定する
- 複数人が同時に休憩状態へ入れる

という状態モデルは必要。

---

## 11. 立地テストから分かる初日/2日目の挙動

Saturn実機記事では:

- 新店の初日はほとんど客が来ないことが多い
- 2日目以降の作業負荷で立地の良し悪しを見る

と記録される。

証拠レベル: PROVISIONAL（単一プレイヤーの経験則）

これは顧客独占率の日付境界計算や開店初日処理と関係している可能性があるが、内部式へはまだ入れない。

## 12. 周辺施設と品揃えの実例

同記事:

- 本店: 駅 + 会社が近い → 客入りがそこそこ
- 2号店: 中学校隣 → 学生をメインターゲット
- 4号店: 会社隣 → 酒・煙草・電化製品を多めに配置

証拠レベル: CONFIRMED-COMMUNITY-SINGLE-SOURCE

初代の建物データは単なる買い物人口だけでなく、客層/商品需要ウェイトを持つ可能性をさらに補強する。

## 14. baseline実装へ反映する暫定インターフェース

固定3人を前提にせず:

```text
StaffAssignment
- store_id
- staff_id
- role: MANAGER | WORKER

Store
- staff_ids: list
- staff_capacity: 3  // strong candidate
```

新規出店フロー:

```text
select manager
select worker #1
select worker #2
open store
```

開店後の異動/解雇で2人以下にできる可能性を残す。

1人運営可否と0人店舗の扱いは未確定。
