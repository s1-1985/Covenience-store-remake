# 初代と『ザ・コンビニ2』の境界 — 公式差分監査 2026-09-05

目的: 検索結果に『ザ・コンビニ2』の完全データが大量に混ざるため、公式情報で「2で追加/変更された要素」を固定し、初代baselineへ逆輸入しない。

## 1. 公式Console Archives『2』が明示する変更点

2026年9月配信の公式Console Archives『ザ・コンビニ2 ～全国チェーン展開だ！～』説明では、前作から次の変更/追加が明記される。

- グラフィックを一新
- マップ数を増加
- **斜め見下ろし視点へ変更**
- 商品アイテムに**ゲーム**を追加
- **倍速モード**を追加
- **店舗マークのオリジナル作成機能**を追加

Source:
- https://www.consolearchives.com/title/csa-0029/

証拠レベル: CONFIRMED-OFFICIAL

---

## 2. 初代baselineへ入れてはいけない要素

上記から、少なくとも次を「初代に元からあった」と扱ってはいけない。

### 斜め見下ろし店内

初代は公式スクリーンショットでも真上からのトップダウン2D。

`2` 公式が「斜め見下ろし視点への変更」と明記するため、斜め視点は続編要素。

baseline:
- top-down 2D = YES
- isometric/diagonal = NO

---

### 倍速モード

`2` 公式が「うれしい倍速モード」を追加要素として説明。

したがって初代PS baselineに倍速機能を原作仕様として入れない。

Android版では後にmodernizationとして追加してよいが、`docs/decisions/` に原作差分として記録する。

---

### 店舗マークのオリジナル作成

`2` 公式が追加機能として明記。

初代baselineで店舗ロゴ/マークエディタを必須仕様にしない。

---

### ゲームソフト商品

`2` 公式が「商品アイテムにゲームも加わり」と明記。

初代の商品完全表を復元する際、`ゲームソフト` を検索で見つけても初代商品として採用しない。

これは非常に重要な汚染防止ルール。

---

## 3. 『2』データ表で特に誤採用しやすいもの

検索で非常に見つかりやすい『2』Wikiには以下の完全表がある。

- 設備リスト
- 商品一覧
- 誘致施設
- 客層
- おすすめ配置
- 操作方法

これらは研究用比較には便利だが、初代baseline数値としては使わない。

### 具体的な危険例: サービス設備

初代専用Wiki:
- 観葉植物 +2
- ベンチ +3
- 噴水 +25

『2』では同名設備でも数値が異なる記録があり、名称一致だけで値を流用すると壊れる。

### 具体的な危険例: 操作方法

『2』にはSELECT倍速があるが、これは公式に続編追加要素。

### 具体的な危険例: ゲーム商品

『2』攻略では「自社6店舗でゲーム棚解禁」等があるが、初代へ逆輸入しない。

## 6. baselineとmodernizationを分離する

原作をまず再構築した後、Android向けには以下を追加候補とする。

- 2x/4x等の速度変更
- タッチジェスチャー
- 自動セーブ
- ズーム
- 高解像度UI
- 操作ショートカット
- アクセシビリティ

ただしそれらを「初代仕様」と呼ばない。

構造:

```text
ORIGINAL_BASELINE
  + MODERN_TOUCH_CONTROLS
  + MODERN_SPEED_CONTROL
  + MODERN_SAVE_QOL
  = Android remake
```

原作ルール検証用テストではmodernizationをOFFにできる設計が理想。

## 8. 現時点の結論

「初代をまずほぼ再現する」という本プロジェクトでは、続編の便利な完全データを使うより、値が欠けても初代専用証拠だけでモデルを作る。

不足値は:

```text
unknown -> provisional approximation -> verified original value
```

の順で昇格させ、`2` の数値を `unknown` の代替にはしない。
