# 初代SS仕様追加調査 — 駐車場接続制約と人気の日次減衰 2026-09-06

対象は1997年SS版『ザ・コンビニ ～あの町を独占せよ～』。PS版へ自動昇格させず、後続作の仕様は混入させない。

## 結論

今回、既存researchに未収録だったSS実機プレイ由来の挙動を2件追加する。

1. 駐車場は歩道と接続していなくても問題なく使用できる。
2. 宣伝等で上昇した店舗人気は恒久値ではなく、店舗評価（★数）に応じて日次で低下するという観測がある。

どちらも単独の後年実機プレイ記録によるため、PS/SS共通の確定仕様にはせず、`DIRECT-PLAY-SS` として保持する。

---

## 1. 駐車場は歩道への接続を要求しない

### 証拠

SS版をCD-ROM実機系で約30時間プレイした記録の「豆知識」に、駐車場について「歩道と繋がっていなくても問題ない」と明記されている。

Source:
- ゲーム＊やおよろず Retro「ザ・コンビニ ～あの町を独占せよ～」SSプレイ記録
  - https://mimora.mimoza.jp/yao_game/retro/contents/ctg_main/memorandum/SS/detail/gmr_SS-0001.php

### 証拠レベル

`DIRECT-PLAY-SS / B+`

理由:
- 対応機種がSSと明記されている。
- 管理人自身のプレイ記録で、プレイ年月・プレイ時間も記録されている。
- ただし説明書・原作内部データ・複数実機での再現確認ではない。

### 実装上の意味

初代の駐車場配置判定に、以下をハード条件として入れない。

```text
parking.must_connect_to_sidewalk == true
```

少なくともSS版再現では、駐車場が歩道ネットワークへ直接接続しているかどうかを、設置可否または稼働可否の必須条件にしない方が安全である。

なお「歩道に接続不要」から、駐車場利用客が実際にどの座標へ出現するか、駐車場から店舗入口まで歩行経路探索を行うか、完全に抽象化された集客補正なのかまでは分からない。これらは別の未確定項目とする。

### 後続作との混同注意

『ザ・コンビニ4』では、オンラインマニュアル由来の記録として、駐車場を店外辺へ接触させ、さらに降車可能な空きマスを確保する制約がある。検証記事自身も「ザ・コンビニ1ではなかった仕様と思う」と区別している。

Source（後続作の差分確認専用。初代仕様の根拠には使わない）:
- https://henamap.doorblog.jp/archives/82418898.html
- https://henamap.doorblog.jp/archives/82417227.html

したがって、後続作由来の `outer_edge_connection` / `disembark_clearance` 制約を初代へ逆輸入しない。

## 2. 人気は店舗評価に応じて日次減衰する可能性

### 証拠

同じSSプレイ記録では、宣伝により全店舗の人気が一時的に上昇し、その後、店舗評価（★数）に応じて毎日人気が下がると記されている。

Source:
- https://mimora.mimoza.jp/yao_game/retro/contents/ctg_main/memorandum/SS/detail/gmr_SS-0001.php

### 証拠レベル

`DIRECT-PLAY-SS / B`

宣伝が人気へ作用すること自体は既存資料で強く裏付けられているが、「★数に応じた日次減衰」の正確な式・方向・各★段階の減少量はこの記録だけでは分からない。

### 実装上の扱い

人気を単純な固定値として持たず、少なくとも将来以下を表現できる構造にしておく。

```text
Popularity(t+1) = clamp(Popularity(t) + event_delta - daily_decay(store_rating), 0, 100)
```

ただし `daily_decay()` の具体値は未確定であり、現時点で数値を捏造しない。

既に確認済みの「5日目～月末スキップでは人気低下が1日分しか適用されない」という初代専用FAQの情報と組み合わせると、人気低下は通常の日次境界処理に属し、月末高速集計では例外的に1回だけ適用される構造が自然である。ただしこの統合モデルは推論なので、証拠そのものとは分ける。

## 3. 未確定事項

### 駐車場

- PS版でも歩道接続不要か。
- 駐車場から顧客NPCが実際に降車・歩行するか。
- 駐車場利用客の出現位置。
- 店舗入口までの経路切断時に利用可能か。
- 駐車場ごとの集客効果と駐車台数の具体式。
- 白線・2階建・タワーで経路判定が共通か。

### 人気減衰

- ★評価の正式名称と表示範囲。
- ★1～最大評価までの各日次低下量。
- 評価が高いほど低下量が小さくなるのか、一定閾値で0になるのか。
- 0時以外のタイミングで減衰する可能性。
- PS版でも同一か。
- 月初1～4日と5日目以降の高速処理における正確な適用順。

## 4. 実装判断

今回の追加だけで調査完了とはしない。

駐車場については、初代互換実装で後続作型の接続制約を入れない判断材料として十分有用である。一方、顧客の駐車場利用AIまでは復元できていない。

人気については、値を `0..100` の静的パラメータとして扱うのではなく、日次減衰関数を差し込める設計にしておく。ただし減衰量は証拠回収まで未実装または仮パラメータ扱いとする。

調査全体は継続。優先度の高い未確定領域は、全商品・全什器、6店舗全寸法/価格、販売許可料金/距離、35店員完全表、顧客AI・店員AI、町建物完全表、買い物人口・経済式、イベント発生条件である。
