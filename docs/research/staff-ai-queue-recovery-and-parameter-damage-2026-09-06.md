# 初代PS/SS版 店員AI：レジ競合・体力回復・能力低下の証拠整理（2026-09-06）

## 対象範囲

1997年PS/SS版『ザ・コンビニ ～あの町を独占せよ～』のみを対象とする。後続作の仕様は採用しない。

今回の主資料は初代専用攻略Wikiの「店員」「FAQ」。数値やAI挙動は実機観察由来のコミュニティ資料であり、説明書・原画面の直接確認ではない。そのため、確度は項目ごとに `B`～`B+` とし、PS/SS両機種での完全共通仕様とはまだ断定しない。

## 1. 客に怒られた時の店員能力低下

### 観測

初代専用攻略Wiki「店員」では、レジ打ちが遅く客に怒られると、店員の **教育・体力を除く能力が各2低下**すると説明されている。

対象になる能力は少なくとも次の5項目である。

- レジ
- 補充
- 警備
- 清掃
- 接客

同ページの雑誌紹介イベント説明でも、上限を超えて上昇した値を含め、怒られることで教育・体力以外が2低下するとされている。

### 証拠レベル

`B+ / FIRST-TITLE-COMMUNITY-REPEATED`

同一初代専用資料内で複数箇所から整合するが、原画面の数値変化をこちらで直接フレーム確認したわけではない。

### 実装上の安全な扱い

```text
on_customer_anger(staff):
  register -= 2
  restock -= 2
  security -= 2
  cleaning -= 2
  service -= 2
  education unchanged
  stamina unchanged
```

ただし下限値、1回の怒りイベントで複数店員へ同時適用されるか、怒らせた担当者だけが対象かは未確定。

## 2. 店員の体力と休憩室

### 観測

店員はレジ、補充、清掃の作業で体力を消費し、**体力が0になると休憩室へ戻り、全回復するまで待機**する。

初代専用Wikiでは通常の休憩中の体力回復は1ずつで、敏捷性が高いほど2回復する確率が上がると説明される。さらに **敏捷100では約9割の確率で2回復する**という実機観測が記載されている。

### 証拠レベル

- 体力0 → 休憩室 → 全回復まで待機：`B+`
- 通常1回復／敏捷で2回復確率上昇：`B`
- 敏捷100で約9割：`B- / OBSERVATIONAL-APPROXIMATION`

### 実装上の安全な扱い

休憩回復量を固定1にせず、敏捷依存の確率補正を差し込める構造にする。

```text
recovery_tick = 1 + agility_bonus_roll()
```

ただし約90%という観測値をそのまま確定式にしない。

## 3. 店長の教育と店員成長率

### 観測

初代専用Wikiでは、**店長の教育パラメータが、その店舗の店員能力の成長率へ影響する**とされる。店長教育が低い店舗では、長期間営業しても店員が能力上限まで育ちにくいという観測がある。

### 証拠レベル

`B / FIRST-TITLE-COMMUNITY-OBSERVATION`

具体的な倍率・式は未確定。

### 実装上の意味

店員成長を各店員の個人教育値だけで完結させず、所属店舗の店長教育値を別係数として参照できるようにする。

## 4. 能力上限の対応関係

初代専用Wikiでは、雇用画面と異動画面で表示されるパラメータが異なり、次の対応が示されている。

| 雇用画面 | 店内能力側との主な対応 |
|---|---|
| 学歴 | 教育と連動しやすい。教育はレジ・警備の上限 |
| 敏捷性 | 補充の上限 |
| 社交性 | 接客・清掃の上限 |
| 給料 | 異動画面にも反映 |
| 体力 | 異動画面にも反映 |

雇用時表示値は多くの場合、店内能力の現在値ではなく **成長上限に近い情報**である。

### 証拠レベル

`B+ / FIRST-TITLE-COMMUNITY-STRUCTURED-DATA`

例外店員が存在すると資料自身が明記しているため、単純な完全一致式にはしない。

## 5. レジ待ちAIの具体的な不具合・優先順位

FAQには、客に怒られる原因として以下のAI挙動が記録されている。

1. **2人の店員が同時にレジへ向かうと、片方が休憩室へ戻り、しばらく出てこない場合がある。**
2. レジを開始した店員の体力が残りわずかだと、その店員もすぐ休憩室へ戻り、レジが無人になる。
3. **客がレジに並んでいても補充など別タスクが残っていると、店員はぎりぎりまでレジへ向かわない。**
4. レジ処理中に、**後から並んだ客を先に会計する場合がある。** つまり完全なFIFOではない。

### 証拠レベル

`B+ / FIRST-TITLE-FAQ-REPEATED-PLAY`

### 実装上の重要点

原作忠実再現を優先する場合、現代的に最適化された店員AIへ置き換えてはいけない。

特に次を避ける。

- レジ待ち客が1人でもいれば必ずレジ最優先
- 2人がレジへ向かった場合に自動で別レジへ綺麗に分担
- 客列を完全FIFOで処理
- 体力切れ寸前の店員を自動でレジ担当から外す最適化

これらを実装すると、原作で発生した「客が怒る」「レジが一時無人になる」という経営上のリスクが消えてしまう。

## 6. 給料と営業時間

店員ページでは、雇用画面に表示される給料は **24時間営業時の1日給料**であり、営業時間を短くしてから異動画面を見ると給料表示も安くなるとされる。

FAQでは、営業時間外・臨時休業中は人件費を含む多くの維持費が発生しない一方、店員は清掃・補充を続けると説明されている。

このため、人件費は「雇用したら固定日額を毎日徴収」というより、少なくとも営業時間との連動がある。

### 証拠レベル

`B+ / FIRST-TITLE-COMMUNITY-CONSISTENT`

正確な按分式は未確定。

## 7. 未確定事項

- 客に怒られた際、能力-2の対象は担当店員のみか、その店舗の全店員か
- 能力値の下限
- 店員の作業1回あたり体力消費量
- 休憩回復のtick間隔
- 敏捷性から2回復確率へ変換する正確な式
- 店長教育による成長倍率
- レジ／補充／清掃の優先順位テーブル
- 複数レジ時の担当決定ロジック
- 後客先会計がバグなのか、列座標判定の仕様なのか
- PS版とSS版で完全に同一挙動か

## 8. 実装判断

店員AIについては、今回の証拠により「必要な状態変数」と「意図的に最適化してはいけない挙動」はかなり明確になった。

ただし正確な数式と全35名の初期値・上限値テーブルは未完成であるため、**AI状態機械の骨格実装は開始可能、バランス固定はまだ不可**と判断する。
