# 初代PS/SS版 店員成長・能力低下・休憩回復の仕様整理（2026-09-06）

対象: 1997年 PlayStation / Sega Saturn版『ザ・コンビニ ～あの町を独占せよ～』のみ。

初代専用攻略Wikiの店員ページを再確認し、これまでの「雇用画面値と実務値が別」「店長教育が成長に関与する」という高レベル整理より一段深い、能力成長・低下・回復の具体的挙動を記録する。後続作の数値は採用しない。

## 1. ソース

### S1: 初代PS/SS専用攻略Wiki「店員」
- https://wikiwiki.jp/theconveni1/%E5%BA%97%E5%93%A1
- WikiトップがPlayStation / Sega Saturn用ソフトを対象と明示: https://wikiwiki.jp/theconveni1/

証拠レベル: **B+ / FIRST-TITLE-DEDICATED-COMMUNITY-DATA**

一次説明書・原作画面そのものではないためAには上げない。ただし初代PS/SS専用を明示した攻略資料であり、複数の数値・長期育成挙動を具体的に記録しているため、実装境界を決める根拠として利用する。

## 2. 店員能力は単純な一組のステータスではない

S1では、雇用時に見える値と、異動時に見える実務値が別に存在する。

雇用側の代表項目:
- 給料
- 体力
- 学歴
- 敏捷性
- 社交性

実務側:
- レジ
- 補充
- 警備
- 清掃
- 接客
- 教育
- 体力

特に重要なのは、雇用画面の高数値が「現在の実務能力」を直接意味しない点である。

実装では最低でも以下を分離する必要がある。

```text
StaffCandidateProfile
  displayedSalary
  displayedStamina
  displayedEducationLike
  displayedAgility
  displayedSociability

StaffRuntimeStats
  register
  replenishment
  security
  cleaning
  service
  education
  stamina
```

証拠レベル: **B+**

## 3. 成長上限の対応関係

S1の記録では、通常ケースで次の対応が強く示される。

- 学歴 ≒ 教育
- 教育 → レジ上限
- 教育 → 警備上限
- 敏捷性 → 補充上限
- 社交性 → 接客上限
- 社交性 → 清掃上限

ただし雨中星人のような例外が存在するため、単純な数式変換ではなくキャラクター別overrideを許容する必要がある。

証拠レベル: **B+**

未確定:
- 雇用画面値と内部上限が完全一致する店員の範囲
- 例外店員の完全一覧
- 内部値の最小・最大値

## 4. 作業ごとの成長

S1では以下の作業成長が明記される。

- レジ: レジ打ちをするたびに上昇し、教育値が上限
- 補充: 補充作業ごとに1上昇
- 清掃: 床を掃除すると1上昇
- 警備: 時間経過で上昇する可能性が示唆されるが、上昇条件は未確定
- 接客: 店舗サービスへ影響するが、上昇トリガーはこの資料だけでは確定できない

証拠レベル:
- レジの作業成長: **B+**
- 補充 +1/作業: **B+**
- 清掃 +1/作業: **B+**
- 警備の時間成長: **C+ / SOURCE-QUESTIONED**

実装上、`staffSkill += elapsedTimeRate` の一括成長は避け、作業完了イベントを入力にできる構造が必要である。

## 5. 客の怒りによる能力低下

S1では、レジ処理が遅く客に怒られた場合、**教育と体力を除く実務ステータスが各2低下**すると記録される。

対象として解釈できる値:
- レジ -2
- 補充 -2
- 警備 -2
- 清掃 -2
- 接客 -2

低下しない:
- 教育
- 体力

証拠レベル: **B+ / EXPLICIT-NUMERIC-COMMUNITY-DATA**

これは単なる「売上ペナルティ」ではない。接客失敗が将来の処理能力まで悪化させる負のフィードバックを持つ。

### 実装候補

```text
onCustomerCheckoutAnger(staff):
  register -= 2
  replenishment -= 2
  security -= 2
  cleaning -= 2
  service -= 2
  # education, stamina unchanged
```

ただし下限値が0か、別の最低値があるかは未確認なので固定しない。

## 6. 雑誌紹介イベントは上限突破を可能にする

店の清掃パラメーターが高い場合、店長が雑誌で紹介されるイベントが発生することがある。

発生時、店長は**体力を除く全パラメーターが約2上昇**し、通常成長上限に到達済みの能力もさらに上げられると記録される。

つまり通常成長上限と、イベントによる最終実値上限は同じ概念ではない。

証拠レベル: **B / FIRST-TITLE-DEDICATED-COMMUNITY-EVENT**

未確定:
- 発生に必要な正確な清掃値
- 発生確率
- 判定タイミング
- 「約2」が常に2なのか
- 100超えが可能か、100でcapされるか

### 重要な相互作用

雑誌イベントで通常上限を超えた能力も、その後客に怒られると-2されるため、イベントによる上積みは恒久保証ではない。

## 7. 体力の消費と休憩

S1では、レジ・補充・清掃で体力が減少し、0になると休憩室へ戻って全回復まで待機するとされる。

証拠レベル: **B+**

未確定:
- 各作業1回あたりの体力消費量
- 歩行による消費有無
- 休憩室まで移動中の作業中断仕様

## 8. 敏捷性と休憩中の体力回復

S1では敏捷性は補充上限だけでなく、休憩室での体力回復量にも関係するとされる。

通常は1ずつ回復するが、一定確率で2回復し、敏捷性が高いほど+2回復の確率が上がると観測されている。

敏捷100では、資料筆者の体感で**約9割の確率で2回復**。

証拠レベル:
- 敏捷が回復量に関与: **B**
- 敏捷100 ≒ 90%で+2: **C+ / PLAYER-ESTIMATE**

したがって、正確な確率式はまだ実装固定しない。

実装用には、

```text
recoverStaminaTick(staff):
  base = 1
  bonus = probabilityByAgility(staff.agility) ? 1 : 0
```

のように確率関数を差し替え可能にしておく。

## 9. 給料は営業時間に連動する

S1では、雇用画面に表示される給料は24時間営業時の1日給で、営業時間を短くした後に異動画面で確認すると安くなると記録される。

証拠レベル: **B+**

ここから安全に確定できるのは、少なくとも店員人件費が固定日額ではなく、営業時間設定に応じて変動すること。

未確定:
- `24h給与 × 営業時間/24` の完全線形か
- 端数処理
- 臨時休業時
- 月末高速スキップ中の給与計算

## 10. 店長教育の効果

S1では店長の教育値が、同店舗の店員の能力成長速度に影響する。

教育が低い店長の店舗では、長期間経過しても部下が上限へ届かないケースがあると記録される。

証拠レベル: **B+**

現時点では倍率式を固定せず、作業成長判定へ `managerEducation` を入力できる設計に留める。

## 11. 店舗パラメーターへの集約

S1では少なくとも以下が明記される。

- 店員の警備合計 → 店舗警備へ影響
- 店員の接客合計 → 店舗サービスへ影響
- 店員の清掃 → 店舗清掃へ影響
- 交番・消防署は店舗警備を上げるが、店員個人の警備値そのものは上げない

証拠レベル: **B+**

したがって個人能力と店舗能力を同一フィールドにしてはいけない。

## 12. 今回の実装判断

### 実装開始可
- 雇用表示値とruntime能力の分離
- 個別能力上限
- キャラ別override
- 作業完了を起点とする成長イベント
- checkout angerによる5能力-2イベント
- 雑誌イベントによる上限突破可能な能力加算
- 休憩回復ロジックへ敏捷を入力するインターフェース
- 店長教育を成長判定へ入力するインターフェース
- 個人能力から店舗パラメーターを集約する別レイヤー

### 数値固定不可
- 警備/接客の成長トリガー
- 体力消費量
- 敏捷→回復+2確率式
- 雑誌イベントの発生条件と正確な+値
- 給与の時間比例式と丸め
- 全35人の完全初期値/上限値

## 13. 調査完了度への影響

35店員の完全データ表は未完成であり、店員調査全体を完了扱いにはしない。

ただし、**店員runtimeの構造と主要な成長・低下・回復イベントは、原作挙動を壊しにくい形で実装を始められる水準に到達した**と判断する。

次の優先検証:
1. 原作画面/動画で「客の怒り直前・直後」の店員能力を比較し、-2を一次観測化する。
2. 休憩中の体力回復をフレーム/時刻単位で観測し、敏捷別の+2確率を定量化する。
3. 営業時間を変えた同一店員の給与表示を比較し、時間比例式と丸め規則を確定する。
4. 雑誌紹介イベントの発生直前・直後を動画で確保し、対象能力と上昇量を確認する。
