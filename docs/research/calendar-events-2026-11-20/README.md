## 本体の変更

- ネイティブの入店経路から、旧「万人ちょうど」assertを通さず、原の符号なし32bit境界比較へ接続。保留は件数キューではなく最新の万人商1個。ライバル子シミュレーションの入店を自社累計へ加えない。
- 午前0時に祭りフラグを消去。8月・区分4なら祭りを優先し、記念保留と記念用乱数を消費しない。区分は既存4代表日を保持し、独自の30日暦へ変更しない。祭りフラグは画面から戻った後に1になる。
- 祭り以外の午前0時に正の保留を消費し、原RNGを1回引いて表示人物を選ぶ。表示人数は活動自社店の入店累計を別集計し直す。グローバル累計3万人でも現在の活動自社店が1万人なら1万人と表示する。
- 表示から戻った後、自社スロットと活動ライバルの人気を100へ代入する。評価C68と現金は記念によって変更しない。集計が10000未満で画面を出さず早期復帰した場合にも親の人気更新は実行する。
- 原の「稼働OR自社」を「活動自社だけ」へ狭めない。未出店の既存自社スロットも対象に含む。本体に存在しない未使用原10枠の全メモリー構造を再現したとは主張しない。
- 月境界では宣伝・寄付・店舗評価の後、記念画面へ入る。決算と日次の需要再配分は画面終了後に続行する。中断した決算用の金額・営業実績を保存し、途中保存/読込から支払・評価・決算・需要更新を重複させない。
- 演出中は時計、客、従業員、ライバルを停止し、16倍速でも描画待機を早送りしない。メイン時計の経過時間を切り、演出時間分の営業tickを後から一気に消費しない。演出前の未処理時間は既存仕様を維持する。
- 旧保存の未消費記念予約だけを最新保留へ移行。消費済み予約や過去の未観測境界を推定して追加しない。
