## 本体との差と修正

旧本体は予約時に年次評価を計算して `last_owner_review` へ固定し、各店の当年売上を0にした後、表示時に固定値を再投入していた。原8003F7FCは**表示時の活動自社店舗**の前年売上D0Cと現在評価C68、消費時の累積入店・町人口を使う。通知待ちに売却された店や評価変更を無視する旧本体とは異なる。

店舗ごとに前年から3年分の売上を保持し、月売上の加算は原符号付き32bitの折返しへ接続。原29FC8の年次繰越に合わせ、当年→前年→前々年→3年前へ送り当年を0にする。本体の年度ガードをJSONへ保持し、途中読込や同年度の重複呼出しで帳簿・既存賃金更新・加齢処理を繰り返さない。表示中の結果は既存通知状態と `last_owner_review` に保存する。

年末の月次会計・年次繰越が終わってから月次mode2、年次mode3を予約する。先に予約された店長等の通知を追い越さない。原3CEACの2予約はまれな雑誌/コンテスト抽選より前にある。本体は既存の月末継続内で2予約を作り、その後の町抽選を維持する。自社0店で年初評価を呼ぶ原作の未確定前提や、ゲーム開始直後の通知全制御列までは再現したと扱わない。

年次消費時は前年帳簿と現在の活動店を列挙し直し、既存 `ProgramProgression.owner_rating` / `ProgramNotifications.consume` の原集計・正数加算の飽和・採点を使う。クリア条件も表示時点の100点で判定する。現在年の新規売上を前年へ混ぜない。原の3年分×5会計欄を全て保存したという主張ではなく、今回接続するのは年次評価が読む売上欄である。
