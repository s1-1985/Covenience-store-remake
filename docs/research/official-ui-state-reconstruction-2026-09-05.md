# 公式PS実画面からのUI状態復元 2026-09-05

対象: 1997年PlayStation版『ザ・コンビニ ～あの町を独占せよ～』。

最優先ソース:
- https://www.consolearchives.com/title/csa-0023/

HAMSTERの現行Console Archives公式ページは、1997年家庭用版を忠実に再現する方針を明記し、日本版ROMを収録している。掲載スクリーンショット6枚をPS baselineの高品質な視覚証拠として扱う。

証拠レベル: CONFIRMED-OFFICIAL / CONFIRMED-VISUAL

---

## 1. 常時トップHUD

6枚のうちゲームプレイ画面すべてで画面最上部に1本の情報バーが表示される。

確認できるフィールド順:

```text
年目 / 月 / 日 / [天候] / 時刻 / 所持金
```

公式画像上の具体例:

```text
01年目01月01日 [快晴] 00:00 ¥200,000,000
01年目01月01日 [快晴] 00:00 ¥103,787,435
01年目01月01日 [曇]   09:16 ¥153,718,510
01年目01月01日 [曇]   15:04 ¥153,723,970
01年目02月02日 [快晴] 10:46 ¥78,533,204
01年目03月02日 [晴]   06:48 ¥25,015,711
```

### baseline要求

Town/Store/Interior/Promotion等の主要状態でトップHUDを共通コンポーネントとして保持できる構造にする。

```text
TopHud
- game_year
- month
- day
- weather_label
- hour_minute
- cash
```

現代化UIでも情報の常時可視性は維持する。

## 2. 店舗位置決定状態

公式 ss01:

中央ダイアログ:

```text
本店の位置を決定してください
L1・・・サイズ変更
```

背景は町マップ。

カーソルをマップ上で動かして出店位置を選ぶ状態であることが視覚確認できる。

### 確定事項

- 出店位置選択は町マップ上で行う。
- `L1` が店舗サイズ変更。
- 本店を指定する明示的な出店状態が存在。
- 画面遷移先を別画面へ切り替えるのではなく、町マップ上へ指示ダイアログを重ねる。

### 未確定

- 決定ボタン
- キャンセルボタン
- サイズ変更順序
- 向き変更操作
- 土地価格/許可情報の表示タイミング

これらは説明書/実機で確認する。

## 3. 内装編集状態

公式 ss02:

右側メニューの文字を直接確認:

```text
配置
移動
入れ替え
売却
終了
```

左側には店舗内装・店外設備の小さな編集領域、残りは緑色のゲーム背景パターン。

### UI上の特徴

- 内装編集はゲーム世界を全面的な別シーンへ置換するのではなく、同じゲーム画面の枠内で店舗編集領域とコマンドメニューを並べる。
- コマンドは縦リスト。
- 選択中項目はピンク系の帯で強調。
- トップHUDは編集時も残る。

### baselineの編集コマンド

```text
INTERIOR_EDIT_ROOT
  PLACE
  MOVE
  SWAP
  SELL
  FINISH
```

名称は上記日本語を原作baseline表示名として保持できる。

## 4. 通常営業・店内観察状態

公式 ss03 / ss06:

- 個々の客と店員が店内/店外に表示。
- 店舗を上から見下ろすトップビュー。
- 店舗下部に半透明のステータスバーが常時表示。

### 下部バーで直接読めるもの

中央:
- `本店`
- 別画像では `4号店`

右:
- `¥1,200`
- 別画像では `¥29,640`

左:
- 店名/チェーン名らしい文字列

中央付近:
- 鉛筆/ペンのようなアイコン
- 黄色い容器状アイコン
- 赤い十字のアイコン

### 重要なUNKNOWN

以下は画像だけでは意味を確定できない:

- 右端の金額が「現在売上」「日次売上」「商品価値」等の何を意味するか。
- 3アイコンの意味。
- 左端文字列の正式なチェーン名/表示項目。

**UIを見ただけで意味を推測して実装値へ昇格させない。**

### 確定できる構造

```text
StoreStatusBar
- chain/store label
- selected_branch_name
- status_icon_slots[]
- numeric_yen_field
```

意味は別資料で確定してからフィールド名を具体化する。

## 5. 宣伝選択ダイアログ

公式 ss04 から直接読める文言:

```text
宣伝方法を選択して下さい(複数選択可)
ダイレクトメール  ¥100,000/月
費用合計          ¥9,600,000/月
終了・・・START
```

5個の宣伝アイコンが横一列に並ぶ。

既存初代専用資料と照合すると5方式は:

- ダイレクトメール
- 新聞広告
- 飛行船
- ラジオ
- TV

### 公式画像だけで確定

- 複数選択可能。
- 月額表記 `/月`。
- 合計費用欄がある。
- STARTで終了。
- ダイアログは町マップ上へ重なる。
- 5方式を全部選ぶと合計9,600,000円/月になることが画像と既知費用の合計で一致。

### baseline状態

```text
PROMOTION_SELECT_MODAL
- selected_methods[]
- focused_method
- focused_method_monthly_cost
- total_monthly_cost
- close_action = START
```

## 7. UIの基本原則

公式6枚を並べると、初代は現代スマホゲームのような「機能ごとに全画面ページへ遷移」する設計ではない。

基本は:

```text
町/店舗という常時表示ワールド
  + TopHud
  + 必要時だけ中央/右側にモーダルメニュー
  + 店舗時はBottomStatusBar
```

という構造。

### Remakeで保持したいこと

- 世界を見失わない。
- メニューを開いても町/店が背景に残る。
- 情報密度は高いが、主要数値は常時見える。
- 90年代PC/家庭用経営シムらしい「ウィンドウを重ねる」感覚を残す。

### Android向け deliberate deviation候補

タッチ操作のため:
- ボタン/タップ領域を広くする
- 文字を高解像度化
- 必要に応じて下部シートを使う

ただし、機能ごとに世界を隠すフルスクリーンページ化はbaselineでは避ける。

## 8. 公式画像から現在確定できるUI state

```text
UiState
- TOWN_VIEW
- STORE_LOCATION_SELECT
- INTERIOR_EDIT
- STORE_LIVE_VIEW

ModalState
- NONE
- PROMOTION_SELECT
```

`INTERIOR_EDIT` はmodalというより専用編集状態。

今後説明書/実機記録から追加予定:
- 店員雇用
- 販売許可申請
- 営業時間
- 価格/利益率
- 調査
- ライバル情報
- アンケート
- 売れ筋
- 店舗成績
- 改築/買収

これらは存在証拠があるものも多いが、**公式6枚から直接UI形状を確認した状態とは分離して管理する。**

## 9. 公式画像の研究価値

公式ページは本作を忠実に再現するシリーズであると明記し、日本版ROMを収録している。

そのため、今回の6枚は:
- 色
- レイアウト
- HUD
- メニュー語彙
- 状態遷移
- 情報密度

を復元する際、コミュニティの記憶より優先する。

一方、現在のConsole Archives側が追加した外部エミュレーションUI/セーブ機能等は原作ゲームUIに混ぜない。
