# 初代PS/SS仕様追加調査 — 店員成長・評価・シナリオ補強 2026-09-05

対象は1997年PS/SS版『ザ・コンビニ ～あの町を独占せよ～』のみ。後続作の値は採用しない。

## Evidence labels
- `CONFIRMED-COMMUNITY-FIRST-TITLE`: 初代PS/SS専用Wikiに明記。
- `SS-DIRECT-PLAY`: SS実機プレイ記録に明記。
- `PROVISIONAL-COMMUNITY`: Wiki自身が推測・体感としているもの。

## 1. 店員成長・減衰ルールの追加確定
Source: https://wikiwiki.jp/theconveni1/%E5%BA%97%E5%93%A1

### 1.1 客に怒られた時の能力低下
`CONFIRMED-COMMUNITY-FIRST-TITLE`

レジ待ち等で客に怒られると、店員のステータスは **教育と体力を除く全項目が2低下** する。

実装候補:
```text
onCustomerAnger(staff):
  register -= 2
  replenishment -= 2
  security -= 2
  cleaning -= 2
  service -= 2
  education unchanged
  stamina unchanged
```

下限処理は資料に明記がないため未確定。

### 1.2 雑誌紹介イベントの能力上昇
`CONFIRMED-COMMUNITY-FIRST-TITLE`

店の清掃値が高いと店長が雑誌で紹介されることがある。発生時は店長の **体力を除く全パラメータが約2上昇**。教育など通常固定の値も上昇し、通常上限到達済みの能力も上限を超えて伸びるとされる。

Wiki表現が「2ほど」のため exact +2 と断定せず、実装時は攻略本/実機検証で最終確認する。

### 1.3 教育・体力の固定性
`CONFIRMED-COMMUNITY-FIRST-TITLE`

- 教育: 基本的に固定。通常減少せず、雑誌紹介イベント以外では上昇しない。
- 体力: 初期から固定で、通常の成長上限そのものは変化しない。ただしWiki後段では「わずかに増減する」とも記載があるため、長期経年で微小変動する可能性は残す。

この2記述は完全には整合しないため、`stamina_base` と `stamina_runtime` を分離する設計が安全。

### 1.4 レジ・補充の成長トリガ
`CONFIRMED-COMMUNITY-FIRST-TITLE`

- レジ: レジ打ちをするたびに上昇。教育値が上限。
- 補充: 補充作業をするたびに **1上昇**。
- 警備: 教育値が上限。上昇トリガはWikiでも「時間経過で上昇？」と疑問付きのため未確定。
- 清掃: 床掃除をすると **1上昇**。接客と同じ上限値を持つ。
- 接客: 社交性に対応する上限値を持つ。

## 2. 警備と事件リスクの補強
Source: https://wikiwiki.jp/theconveni1/%E5%BA%97%E5%93%A1

`CONFIRMED-COMMUNITY-FIRST-TITLE`

Wikiは、店舗警備が人気より低いと **強盗・火災が発生しやすい** と記載している。一方、警備99でも事件は起こり得るため、完全防止には100が必要とも明記される。

したがって現時点では:
```text
security == 100 -> practical prevention threshold
security < popularity -> elevated incident risk
```
という二段構造の可能性が高い。

正確な確率式・人気との差分係数は未確定。

交番/消防署の存在は店舗警備を上昇させるが、店員個人の警備値を直接上げるわけではない。

## 3. 上級評価条件の補強
Source: https://wikiwiki.jp/theconveni1/%E3%82%B2%E3%83%BC%E3%83%A0%E3%83%A2%E3%83%BC%E3%83%89%E6%94%BB%E7%95%A5

`CONFIRMED-COMMUNITY-FIRST-TITLE`

上級の総合評価は、人気・清掃・警備・サービスを高く保ち、利益を出した状態で月初を迎えると上昇するとの攻略記録がある。

さらに **星4の状態で各パラメータを全て100にすると星5になる** と記載される。

重要な追加点:
- 店舗サイズは小型でも星5到達可能。
- 最大店舗への改築は必須ではない。
- 大型化は清掃維持を難しくし、評価上げにはむしろ不利になり得る。

よって `OwnerEvaluation` に店舗サイズを必須条件として入れてはならない。

## 4. 初級人口成長の実用閾値
Source: https://wikiwiki.jp/theconveni1/%E3%82%B2%E3%83%BC%E3%83%A0%E3%83%A2%E3%83%BC%E3%83%89%E6%94%BB%E7%95%A5

`CONFIRMED-COMMUNITY-FIRST-TITLE`

- 都庁は町人口20,000超で自動出現との報告。
- 誘致を行わない場合、町人口は **15,000付近からほとんど伸びなくなる** という攻略観測。
- 大学は誘致コストパフォーマンスが高いとの記録。

15,000はゲーム内部のhard capとは断定せず、`PROVISIONAL-COMMUNITY` な攻略上の自然成長鈍化点として扱う。

## 5. 出店・道路接続ルール
Source: https://wikiwiki.jp/theconveni1/%E3%82%B2%E3%83%BC%E3%83%A0%E3%83%BC%E3%83%89%E6%94%BB%E7%95%A5

`CONFIRMED-COMMUNITY-FIRST-TITLE`

**店舗は道路に隣接していなくても出店可能** と記載される。

これは町グリッド実装で重要。建設可否判定に `adjacent_to_road == true` を必須条件としてはいけない。

## 6. ライバル妨害時の利益率設定
Source: https://wikiwiki.jp/theconveni1/%E3%82%B2%E3%83%BC%E3%83%A0%E3%83%BC%E3%83%89%E6%94%BB%E7%95%A5

`CONFIRMED-COMMUNITY-FIRST-TITLE`

ライバル本店近くに支店を置き、**商品利益率0%** に設定して顧客を奪う攻略法が明記される。さらに -20%程度の価格設定でもライバル出店ペースを遅らせつつ黒字化可能との攻略観測がある。

ここから少なくとも、営業方針UIが単純な固定価格選択ではなく **利益率/価格を0%やマイナス方向まで調整可能** なことが強く支持される。

正確なUI刻み幅・下限/上限は未確定。

## 7. SS実機プレイによるメニュー/調査補強
Source: https://mimora.mimoza.jp/yao_game/retro/contents/ctg_main/memorandum/SS/detail/gmr_SS-0001.php

`SS-DIRECT-PLAY`

SS実機プレイ記録では「調査」コマンドで以下を確認している:
- 各店舗の売上成績
- 売れ筋アンケート
- 収支グラフ
- ライバル店調査

ライバル店調査は **50万円**。確認できるのは営業時間・収益などの基本情報で、店内レイアウト/内部状況は見られない。

この50万円は現時点ではSS固有観測値として保持し、PS共通値へは昇格させない。

同プレイ記録は、レジを逆向きに置くと想定と逆方向へ客が並ぶこと、客が複数商品を合わせ買いすることも実機挙動として補強する。

## 9. 実装への反映判断
今回の結果により、以下は実装仕様として先行固定してよい:
- 道路非隣接でも出店可。
- 店員のレジ/補充/清掃は作業行為で成長する。
- 客怒りはスタッフ成長を巻き戻すペナルティを持つ。
- 小型店でも上級★5到達可能。
- 最大店舗化を評価条件に含めない。
- レジには向きがあり、待機列方向へ影響する。

数値式が必要な事件率・評価上昇率・雑誌イベント率はまだ仮実装に留める。
