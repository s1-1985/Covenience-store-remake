## 実装と操作

ProgramPricing.stepは26件の一括±1を全件検査し、1件でも範囲を外れると全件不変。
try_commit_source_pricesは26キー、数値の整数性、0～100、店舗UID、
編集開始時の26設定を確認してから一括反映する。設定が同じなら記録も増やさない。
個別設定APIもこの一括検査へ接続。旧試作向け全体価格APIは維持する。
価格変更は乱数や現金を消費しない。購入時は既存の原価格式を使う。

画面では全商品±1、個別6行×5ページ、各行の単価/設定/±、
確認/確定を用意した。個別画面の「戻る」はその画面の仮変更を捨て、
「設定して戻る」は親画面の仮設定へ残す。親の確定前は本体を変更しない。
店舗や実設定が途中で変わると確定を拒否し、別店舗/新設定への上書きを防ぐ。

原の個別編集は一時配列で確定/取消するが、一括編集は原親画面上で即時変更する。
スマホ版では誤タップ対策として両方を最後の確認まで仮編集にした。
これはユーザー承諾済みの操作再構成であり、原入力ループの完全一致とはしない。
プレビューは未確定なので保存には実設定だけを残す。店選びの再計算周期は従来の
本体方式を変えておらず、全価格関連処理が原作と一致したという結論にはしない。
