## 本体への接続

begin_renovation_editでサイズ・追加許可・合計資金・UID/元サイズを全て検査してから、
既存のサイズ移行と許可取得を行う。そこを内装前の保存点にする。
finish_renovation_edit(true)は編集した内装を保持し、仮会計を内装前へ戻す。
falseは内装を保存点へ戻し、サイズ・追加許可の負額記録を残し、元許可を復元する。
既にあった許可は追加費用/逆額の対象ではない。
取消後の画面はサイズ選択へ戻り、選択済サイズの再試行を可能とする。

確認画面に販売許可の選択を追加した。編集終了は「内装を続ける」「改築を確定する」
「改築を取り消す」。START、終了項目、メニューを閉じる操作も、この選択へ接続した。
初期選択は継続。編集途中で別店舗へ切り替えたり店舗を売却したりできない。
営業更新は停止する。元営業時間の復元は0.7.2のUID方式を継続する。

renovation_sessionはJSONの本体用チェックポイント。編集中の内装と保存点の両方を保持し、
保存再開後も確定/取消を選べる。UIは対象店舗を選び、内装画面を再開する。
会計キャッシュの既決済客IDも復元し、過去の同じIDを再決済できる状態に戻さない。

実際の配置試験で、原作型の休憩位置が控え室の占有領域内にあるため、
旧通路判定が配置を一律拒否する問題も確認した。原作型の休憩state0だけを
この通路判定から分け、全配置検査を通った後に新しい控え室へ結び直す。
通路が塞がる配置や不正な床への配置を許可する変更ではない。

## 本体互換部分・未完部分

本体のサイズ移行時には既存の自動什器再配置を使っているため、取消保存点も
その移行後のネイティブ配置になる。原5080バイトのコピーや未公開バイトを
そのまま再現したとは扱わない。原の選択済tier保持と会計/許可の戻りを接続したもの。
原カード互換、全controllerの入力タイミング、サイズ選択数のCD994の意味、
自動配置/倉庫を原作手動方式へ置き換える点は残る。
JSONへの会社会計全体のコピーは営業停止を前提とする。原RAM領域の同一コピーではない。
既存未解決6件は保留し、全移植完了とはしない。
