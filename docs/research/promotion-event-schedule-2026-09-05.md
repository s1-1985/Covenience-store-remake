# 初代PS/SS 宣伝イベント発生時刻 追加調査 2026-09-05

対象: 1997年PS/SS版『ザ・コンビニ ～あの町を独占せよ～』。

目的:
- 宣伝費と人気上昇値だけでなく、「いつ効果が発生するか」を初代専用資料から固定する。
- 月初4日だけを通常シミュレーションする原作時間モデルと宣伝イベントを正しく接続する。

## 1. 宣伝は「販促 → 宣伝」から設定

初代専用資料では、宣伝はメニュー `販促` → `宣伝` から設定する。

宣伝を実行すると:
- 出店中の全自店舗の人気が上昇
- 店舗数によって料金は変化しない
- 宣伝方法ごとに月1回
- 方法ごとに決まった日付・時刻でイベント発生

### UI/実装上の意味

宣伝は即時 `popularity += X` ではない。

```text
schedulePromotion(type, month)
 -> promotion event occurs at fixed in-game timestamp
 -> apply popularity gain to all currently eligible own stores
```

というイベントとして扱う。

---

## 2. 各宣伝の費用・人気上昇・発生時刻

| 宣伝 | 費用 | 人気上昇 | 発生日時 |
|---|---:|---:|---|
| ダイレクトメール | 100,000円 | +12 | 2日目 10:00 |
| 新聞広告 | 500,000円 | +20 | 2日目 07:00 |
| 飛行船 | 1,000,000円 | +30 | 3日目 15:00 |
| ラジオ | 3,000,000円 | +50 | 1日目 17:00 |
| TV | 5,000,000円 | +100 | 1日目 19:00 |

人気上限は100。

### 重要

この時刻は全て月初1〜3日内に収まっている。

原作は通常シミュレーションが1〜4日、5日以降を月末まで集約するため、宣伝イベント設計と4日代表シミュレーションが明確に噛み合っている。

これは「代表4日 + 月次集約」をbaselineで維持する追加根拠になる。

## 3. アイドル一日オーナー

初代専用資料:

- 全自店舗の累計来店者数合計が1万人増えるごとに発生。
- 無料。
- 効果はTVと同じで人気100まで上昇。
- `来店者数が○万人になりました` という通知が出た翌日の0時に宣伝イベント開始。
- その前に新店を出すと、新店にも効果を与えられるという攻略法がある。
- 店内にアイドルの姿が実際に表示されるわけではない。

証拠レベル: CONFIRMED-COMMUNITY

### 実装上の意味

イベント対象店舗一覧を「閾値到達時」ではなく「翌日0時の効果適用時」に評価している可能性がある。

ただし内部実装は未確定なので:

```text
onCumulativeVisitorsThresholdCrossed():
    scheduleIdolPromotion(nextDay00)

onIdolPromotion():
    applyPopularityToCurrentOwnStores()
```

を有力候補として保持する。

## 4. 初月人気100の攻略例

初期人気は20。

資料では初月に:
- ダイレクトメール +12
- 新聞広告 +20
- ラジオ +50

を組み合わせることで合計82上昇し、上限100へ到達できるとされる。

2ヶ月目以降は:
- ダイレクトメール
- 新聞広告
- 飛行船

で人気維持が推奨される。

店舗総合評価が上がるほど日々の人気低下が小さくなるため、後半は過剰な宣伝を減らす余地がある。

## 5. baseline実装要求

```text
PromotionType
- cost
- popularity_gain
- trigger_day
- trigger_time
- affects_all_owned_stores
- monthly_limit = 1

ScheduledPromotion
- type
- target_month
- trigger_datetime
```

宣伝費を支払った瞬間に効果を反映しない。

また、同月に複数方式を選択できることは公式PS画面から別研究で確認済み。
