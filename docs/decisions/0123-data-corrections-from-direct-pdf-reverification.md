# 0123: PDFの直接再読による2件のデータ是正(タスク#54)

## 背景

タスク#50〜#53を通じて、セッション終了時にアップロードされたPDFスキャン
(添付ファイル)へ引き続きアクセスできることを確認した。`PROJECT_MEMORY.md`
第21.4節に「未解決のCONTRADICTS」として記録されていた項目のうち、直接
PDFの該当ページを再読することで解決できるものを2件確認・是正した。

## 決定

### 1. 治安施設(交番/消防署)の警備加算値 — 矛盾ではなく「粒度の違い」と判明

「新人店長実習マニュアル」book pp.46-47と「クイックリファレンス」book
p.10を、それぞれ元スキャンから直接再読した:

- 実習マニュアル: 「交番の場合(セキュリティ40点アップ)」「消防署の場合
  (セキュリティ30点アップ)」、「自分のお店から半径7エリア以上の場所に
  誘致しても、それはムダ」「範囲内から建物がはみ出すと、それだけ警備
  能力が減少してしまう」。
- クイックリファレンス: 「店舗周囲16×16エリア内にセキュリティ施設が
  あれば...プラス効果」「消防署: 敷地面積2×3エリア。1エリアごとに警備値
  +5の効果。最大で+30」「交番: 敷地面積2×2エリア。1エリアごとに警備値
  +10の効果。最大で+40」。

検算すると、交番2×2=4マス×10=40、消防署2×3=6マス×5=30と、両方とも
クイックリファレンスの「最大値」と完全に一致する。つまり実習マニュアル
の「フラット+40/+30(範囲内に収まっている場合)」は、クイックリファレンス
の「1マスあたりの加算値×範囲内マス数」という詳細な公式の、全体が範囲内に
収まった場合の結果と数学的に一致する――これは矛盾ではなく、同じ公式を
異なる粒度で説明しているだけだと判断した。確定した公式:

```
警備加算 = (店舗から効果範囲内にある施設の敷地マス数) × 1マスあたりの加算値
(交番: 10/マス、最大40。消防署: 5/マス、最大30。)
```

**この時点でも未実装のまま**: このクライアントの`TownState`(`game/`)は
人口・店舗数のみのスカラー値で、施設の空間配置・距離計算の仕組み自体が
一切存在しない(決定書0095)。確定した公式そのものは、もはや実装の
妨げではない――妨げているのは「町の空間モデル」という、より大きな
未着手の前提システムである。`PROJECT_MEMORY.md`第21.3節を更新した
(コード変更なし)。

### 2. 小宮千明(`komiya_chiaki`)の`security_skill_growth_ceiling`誤記の是正

35名の店員候補データ(book pp.126-133)のうち、小宮千明のカード
(book p.127)を直接再読した結果、5つの「能力の分岐ポイント」列は
サービス44・レジ41・清掃44・補充41・セキュリティ**44**と読み取れた。

既存コード(`reference_sim/conveni_sim/baseline_data.py`の
`STAFF_CANDIDATES`、および`game/data/vertical_slice.json`の
`staff_candidates`)は`security_skill_growth_ceiling=41`となっており、
隣接するレジ/補充列と同じ「41」に引きずられた転記ミスだったと判断した
(サービス/清掃の「44」と、レジ/補充の「41」が交互に並ぶカードの中で、
セキュリティだけ「44」であるべきところを隣の値と混同しやすいレイアウト)。
`44`へ修正した。

この候補(`komiya_chiaki`)は現在`staff.members`(実働中のstaff-1/staff-2)
のどちらにも紐付けられておらず、採用候補プールのデータとしてのみ存在する
ため、この修正によるゲームプレイ上の即時の挙動変化はない。
