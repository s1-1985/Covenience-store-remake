# 0147: カレンダー表示を公式スクリーンショット準拠の年/月/日形式へ修正(タスク#77)

## 背景

タスク#76(UIテーマ)がマージされた後、ユーザーから直接の問いかけが
あった:「あのさ、今更だけど、ちゃんと初代ザ・コンビニを再現する方向
で動いてる？独自路線を突っ走ってない？」

これを受けて確認した結果、具体的で是正可能なギャップが見つかった:

`docs/research/official-screenshot-evidence-2026-09-05.md`(2026-09-05
付、既存の調査ファイル)第1節には、ハムスター公式「コンソール
アーカイブス」配信のPS版公式スクリーンショット(`ss01`)に基づく
CONFIRMED_OFFICIAL / CONFIRMED_VISUAL証拠が既に記録されていた:

> `01年目01月01日` / `[快晴]` / `00:00` / `¥200,000,000` / ...

つまり原作の日付表示は**年/月/日**形式であり、「月内の何日目/4日中」
のような表記も、通算日数のカウンターも画面上には存在しない。

一方、タスク#75で実装した`CalendarValue`ラベルは
`"Month %d · Day %d of %d (Day %d overall)"`——月と月内日数のみで
「年」の概念が完全に欠落しており、かつ「4日中の何日目」「通算日数」
という原作画面に存在しない情報を独自に追加していた。**このファイルを
確認せずに実装した**ことが根本原因である。

## 決定

### 年/月/日形式への修正

`main.gd`の`_refresh_ui()`を修正し、`"Year %d · Month %d, Day %d"`
形式に変更した。

- 年は`_evaluate_terminal_state()`が既に使っている
  `(month_count / MONTHS_PER_YEAR) + 1`と同じ計算式を再利用(新規発明
  ではない)。
- 月内の日(1〜4)は、この点は据え置き——`REPRESENTATIVE_DAYS_PER_
  MONTH`=4自体が「1月=4日間×8」という既にCONFIRMED_OFFICIALな引用に
  基づく仕様であり、この4日間のうち何日目かを表示すること自体は
  正しい代表日の値であって、発明ではない。誤りだったのは「year」が
  抜けていたことと、「of 4」「(Day N overall)」という原作画面に存在
  しない補足情報を付け足していたことの2点。
- 文言自体は英語のまま(このクライアントの他のUIラベルが全て英語の
  ため、統一感を優先し、原作の日本語表記`01年目01月01日`をそのまま
  移植することはしなかった)。

### 天気表示は対象外

公式画面には天気アイコン`[快晴]`も表示されているが、`game/`クライアント
には天気シミュレーション自体が一切存在しない(タスク#63の時点で
`reference_sim`側にのみ天候テーブルを移植し、`game/`への配線は明示的に
対象外とされていた、`PROJECT_MEMORY.md`セクション19に既存の記載あり)。
今回は「カレンダー表示形式の修正」という狭いスコープに絞り、天気機能
そのものの新規実装は含めない。

## テスト

- `reference_sim`フルスイート742件パス/1件xfail(新規コントラクト
  テスト1件、741→742)。`docs/research/official-screenshot-evidence-
  2026-09-05.md`に実際に`01年目01月01日`の引用が存在すること、
  `main.gd`が新形式を使い旧形式(`of 4 (Day N overall)`)を含まない
  こと、年/月の計算式が既存の`MONTHS_PER_YEAR`定数を再利用している
  ことを検証。
- `game/scripts/headless_smoke.gd`: 既存タスク#75のカレンダー検証
  シナリオ(`economy_ui_scene`)を新形式の期待値計算に更新。ローカルに
  Godot実行環境がないためCIで最終検証。

## 対象ファイル

- `game/scripts/main.gd`
- `game/scenes/main.tscn`(デフォルトテキストのプレースホルダーのみ)
- `game/scripts/headless_smoke.gd`
- `reference_sim/tests/test_game_vertical_slice_contract.py`
- `PROJECT_MEMORY.md`

## 明示的に対象外

- 天気表示・天候シミュレーションの新規実装(上記の通り、既存の
  タスク#63の対象外決定を維持)。
- UI全体のテキストを日本語化すること——他のラベルとの統一感を優先し、
  今回は日付の「構造」(年/月/日)のみを原作に合わせ、言語は変更しない。
- 内装編集画面の5コマンド構造(配置/移動/入れ替え/売却/終了)への
  対応——ユーザーへの回答時点で同時に指摘した別のギャップだが、
  こちらは既存の「タップで選択→タップで配置」という現行UIの再設計を
  要する、より大きなスコープの課題のため、別タスクとして扱う。
