# 0168: 店員が働く・動きを滑らかに・棚の絵と中身表示・任意補充(タスク#97)

## 背景

ユーザーの指摘(0.1.6を遊んで):

- 店員が動かない。
- 客の動きがカクカクする。
- 客が買い物しても、棚の商品の絵が変わらない。
- 什器を選んでも、中の商品が何か表示されない。任意に補充もできない。

実際にゲームを動かして確かめた原因:

| 症状 | 原因 |
|---|---|
| 店員が動かない | 補充に行くのは棚が**0個**になったときだけだった(`restock_trigger_stock_units_at_or_below=0`)。攻略本p.48の店の棚は40〜120個入りなので、何時間も空にならない。清掃の仕事はまだ無く、客がいる間は持ち場に立ったままだった。 |
| カクカク | 客・店員は1ティック(0.25秒)ごとに1サブセル(36px)ずつ瞬間移動していた。歩行の2コマ(A/B)のうちAしか使っていなかった。 |
| 絵が変わらない | 商品の絵は「多・中・少」の3種類で、在庫が66%と33%を下回ったときしか変わらなかった。 |
| 中身が見えない・補充できない | 補充ボタンは「在庫0のとき」だけ有効で、しかも店内に客が一人もいないときしか使えなかった。スマホではパネルが閉じているので、選択しても何も表示されなかった。 |

## 根拠

- 店員は棚が減ったのを見つけて自分で補充する(`inventory-restock-boundary` §2)。正確な開始水準は不明。
- 店員は自分で掃除もする。閉店中でも掃除・補充をする(初代FAQ)。
- 「清掃」の仕事で清掃力とセキュリティが伸びる(攻略本p.26「仕事内容とパラメータ変化の関係」)。CONFIRMED_OFFICIAL。
- プレイヤーも棚にカーソルを合わせて補充できる。ただし店員は育たない(攻略本PDF1 p.71、CONFIRMED_OFFICIAL)。
- ユーザー証言(決定書0149):「中身が減っていると補充のコマンドが出て、任意で補充できた」。0149ではこれを「在庫が閾値(0)以下」と読んでいたが、証言の言葉どおり「満杯でなければ」に直した。

## 決定

1. **補充(店員)**: 実際のゲームでは、棚が満杯の8/9以下になったら店員が補充に行く(1マスの棚の絵は9個なので、「1個分減って見えたら」)。REMAKE_BALANCED_DEFAULT。試作店のテストは従来の0のまま。
2. **清掃**: 客が歩いたマスを「汚れ」として最大24か所記録する。補充する棚が無いときは、レジ以外の店員が古い順に掃除しに行く。掃除にかかる時間は補充と同じ式で、清掃力が高いほど短い。掃除すると清掃力とセキュリティが伸び(p.26)、終わると持ち場に戻る。補充が優先。場所・時間・順番はREMAKE_BALANCED_DEFAULT。
3. **滑らかな移動**: 描画だけを変えた。前のマスから今のマスまでを1ティックかけて直線的に動かし、半分を過ぎたら歩行コマをAからBに切り替える。シミュレーションの位置と時間は変えていない。REMAKE_BALANCED_DEFAULT。
4. **棚の絵**: 「多」の絵にある3×3の9個のうち、在庫の割合に応じた個数(切り上げ、1マスあたり)だけを描く。数個売れるたびに1個減って見える。REMAKE_BALANCED_DEFAULT。
5. **中身の表示と補充**: 什器をタップすると、店の上に「小型常温棚：パン　在庫 38／40　[補充(¥300)] [閉じる]」を出す。その什器が店の上半分にあれば下端に、下半分にあれば上端に出し、什器を隠さない。補充は満杯でなければ使え、客がいても使える(在庫を足すだけで、客の経路やかごは変わらない)。満杯まで補充し、足りない個数×仕入単価を払う。これまでは初期在庫と同じ数を足していて、満杯を超えていた。

## テスト

- `headless_smoke.gd`: 絵の個数(40/40→9、35/40→8、1/40→1、0→0、2マス)、補充水準(40個→35)、実際のゲームで補充と清掃の両方が起きること、レジ係は掃除しないこと、試作店は従来の水準のまま、描画の補間(半分の時点で中間位置・Bコマ、動かなかったティックは静止)。満杯の棚は補充できず、3個減った棚は満杯まで3個分の代金で補充されること。
- `android_preview_smoke.gd`: 実際のゲームで棚を選ぶと「在庫 36／40」が出て、客がいても補充できること。「閉じる」で消えること。
- 契約テスト: 各REMAKE_BALANCED_DEFAULTの記載。
- 結果: Python 759件成功(期待失敗1件は既存)。Godotスモーク・Android previewスモークとも成功。

## 明示的に対象外

- 体力(作業で減り、0になると休憩室で全回復まで休む。コミュニティ資料B+)。
- レジ係の交代。
- 汚れの見た目と清掃値への反映。
- 客がいる間の、補充以外の操作(許可・広告・雇用など)。これらは今も「客が全員帰るまで」待つ。
