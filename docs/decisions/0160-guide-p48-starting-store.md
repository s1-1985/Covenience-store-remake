# 0160: 新しいゲームを攻略本p.48の店で始める(タスク#89)

## 背景

ユーザーの指摘「あらゆる面で初代ザ・コンビニからかけ離れている」のうち、最も目に見える
原因は店そのものだった。開始時の店は5×8マスに棚2つ・商品2種(試作用の`prototype-bread`/
`prototype-drink`)で、原作の画面写真のような「棚が並んだコンビニ」になっていなかった。

攻略本 p.48「未開の土地に開店するなら!」(PDF4 1ページ目)には、ゲーム内の真上視点の
什器画像で描かれた店の図が印刷されている。倍率6で描画し、137pxの格子を重ねて読んだ。

- 床は12×8マスちょうど(床の左端x=686、上端y=1253、1マス137px)。CONFIRMED_OFFICIALの
  大型店`large_bottom`(12, 8)と一致する。
- 入口: 床の外周で開いているのは、上辺の5〜6マス目に続く幅2マスの通路だけ。
  プレイ動画フレーム`video_900s.png`でも入口マットは店の上辺にある。
- 什器: 1×1マスの棚34台、2×2の休憩室、レジ(2マス)、観葉植物、ATM・コピー機らしき機械。
  休憩室とその下の2台は、格子から半マスずれている(このクライアントの半マス単位で表せる)。

## 決定

### 1. `guide_starting_store`ブロック

`game/data/vertical_slice.json`に、`tools/build_guide_p48_store.py`が表から生成する
`guide_starting_store`ブロックを追加した。表には各マスの位置と、描かれている商品の読みを
1行ずつ記録している。証拠の段階は項目ごとに異なる:

| 項目 | 段階 |
|---|---|
| 床の大きさ(12×8) | CONFIRMED_OFFICIAL(店舗データ) + CONFIRMED_VISUAL(図の実測) |
| 什器の位置・1×1の大きさ | CONFIRMED_VISUAL |
| 各棚の商品カテゴリ | PROVISIONAL(棚に描かれた商品絵をこのプロジェクトが読んだもの。自信の低いものは表に「uncertain」と記載) |
| 棚の種類(常温/冷蔵/冷凍の1×1棚) | DATA2(p.86-89)の対応表から、そのカテゴリを置ける1×1棚を選んだ(類推) |
| 開始時の在庫 | その棚のCONFIRMED_OFFICIAL収容力(新しく並べた棚は満杯、という類推) |
| 休憩室2 | PROVISIONAL(左上の斜めの絵がDATA2の職員休憩室2の小さい図と似ている) |
| 客が棚のどちら側に立つか、レジの客側、休憩室の出入口、店員の持ち場 | REMAKE_BALANCED_DEFAULT |

酒類に見える瓶が2台((11,5)と(11,6))にあるが、酒類の販売には許可が必要
(CONFIRMED_OFFICIAL)で、新しい店は許可を持っていないため、その2台には冷たい飲料を置いた。
図のATM(8,6)とコピー機(9,6)は、このクライアントにその仕組みが無いため置いていない。
店の外(駐車場・自販機・植木)も、屋外の敷地をまだ扱えないため置いていない。

### 2. `GuideStartingStore.apply()`と`main.gd`

`game/scripts/domain/guide_starting_store.gd`が、試作の店の設定の上にこのブロックを重ねた
設定を作る。`main.gd`は新しいゲームでも「続きから」でも常にこれを使う。自動テストは試作の
店の座標を前提にした台本が多いため、トップレベルの試作の店はそのまま残した。テストは
`Engine`のメタ情報`use_prototype_store_for_tests`でそちらを選ぶ(`--script`で動くテスト
からは`main.gd`をpreloadできないため、静的変数ではなくメタ情報にした)。

あわせて、この店では次の値も変える:

- 客の欲しい物: 固定の2品をやめ、既存の「来店ごとの無作為な3品」(REMAKE_BALANCED_DEFAULT、
  タスク#55)だけにした。34品のどれでも買われうる。そのため、内装を変えた時の到達確認は、
  全ての棚に入口から行けることを確かめる。
- 同時に店内にいられる客の上限: 3→8。プレイ動画フレーム`video_900s.png`で、1店に約8人の
  客が同時にいる(このプロジェクトの目視の数)。それを上限に使うのはREMAKE_BALANCED_DEFAULT。
- 開始資金: 2億円(Android previewと同じCONFIRMED_COMMUNITYの初期資金)。大型店の維持費で、
  試作の1,000円では初日で破産するため。

### 3. 画面

12×8の店を画面に収めるため、`main.gd`の`_fit_store_view()`が店の描画を縮小する
(拡大はしない)。タップ位置は`store_view.gd`が`to_local()`で変換するので、縮小しても
正しく取れる。スマホでは店を左、ショートカットを中央、パネルを右に並べ、パネルの
ボタン列と列幅の最小値を外して、右端からはみ出さないようにした。

## 見つけたが直していないこと

- `baseline_data.py`の`medium_refrigerated_shelf`(冷蔵棚 350円)の大きさは(1, 1)だが、
  DATA2(p.86)の該当行は縦1・横2。別タスクで照合して直す。

## テスト

- `headless_smoke.gd`:
  - `apply()`の結果が12×8で商品34品になること、元の設定を書き換えないこと。
  - 1営業日回して、破産しないこと、2人以上が同時に買い物すること、10人以上が買い物を
    終えること、10種類以上の棚から商品が売れること。
  - 開店時の客が帰った後は店員が休憩室で休むこと。
  - UIの台本シナリオは、メタ情報で試作の店を使う。
- 契約テスト:
  - 床が`large_bottom`と一致すること。
  - JSONのブロックが生成スクリプトの出力と完全に一致すること。
  - 各棚の種類がその商品カテゴリを置けること(DATA2の対応表)。
  - 在庫が棚の収容力と、価格が`product_catalog`と一致すること。
  - 許可が必要な商品が無いこと。
  - 什器が床からはみ出さず重ならないこと、出入口が隣り合うこと。
  - 入口から全ての棚・レジ・休憩室・出口・店員の持ち場へ行けること(幅優先探索)。
  - `main.gd`がこのブロックを適用すること、証拠の各タグが入っていること。
- 結果: Pythonは752件成功(期待失敗1件は既存)。Godotスモーク、Android previewスモークとも成功。
- スクリーンショット(スマホの配置)で、p.48の図と同じ並びの店に客と店員が動き、画面に
  収まることを確認した。

## 明示的に対象外(次の作業)

- 来客数: この店でも同時に2〜3人しかいない。上限ではなく、来店数の式(需要の係数、
  REMAKE_BALANCED_DEFAULT)が少ないため。原作の根拠をもとに見直す。
- 客の買う物の選び方(原作の客層ごとの傾向。`reference_sim`の客層・来店表)。
- 店の外(駐車場・自販機)と町マップ。
- ATM・コピー機・宅急便の仕組み。
- 棚の絵: 今の棚の絵は、このプロジェクトが描いたもの。p.48の図から、商品が載った状態の
  1マスの絵を切り出せる。
