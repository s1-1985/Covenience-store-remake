# 0162: 店員を店長+店員2人の3名体制にする(タスク#91)

## 背景

ユーザーの指摘:「このプロジェクトだとずっと店員が2名なんだけど、店員は3名な」。

資料を読み直すと、根拠は既にリポジトリにあった。

- クイックリファレンス p.6(CONFIRMED_OFFICIAL、`docs/research/quick-reference-guide-part1-2026-09-19.md`):
  「各店舗に店長が必ず必要。店員は2人まで雇用できる。スーパー社員は3人まで店員として数える。」
- `docs/research/staff-minimum-autovending-2026-09-05.md`: 「PS新規出店標準 = 店長1 + 店員2 = 3名」
  (PS版レビューの新規出店フロー: 店長1名・従業員2名を雇う)。

タスク#56(決定書0125)はこのp.6を読んでいたが、「店員は2人まで」だけを採り、
店長の枠を「情報源が無い」として追加しなかった。実際には店長の存在そのものが
同じ文に書かれており、この判断は誤りだった。PROJECT_MEMORY 21.3節も
「店長3枠目は未実装」と記録したままだった。

## 決定

- `staff.members`に店長枠`staff-3`(`role: "manager"`)を追加し、`staff.manager_staff_id`
  で店長を指す。レジ担当は従来どおり`staff-1`。
- 店長に置く人: 第三の攻略本「店長に求められるのは教育パラメータの高さ」に従い、候補35名の
  うち教育値が最も高い者(95)。同点の2名(福本孝仁・奥平康夫)のうち給与の低い福本孝仁に
  した(同点の決め方はREMAKE_BALANCED_DEFAULT)。攻略本の例示の横峰隆二は候補35名に
  含まれていない。
- 店長の働き方: 現状は`staff-2`と同じ(補充・休憩)。店長の教育値が部下の成長に効く
  仕組み(CONFIRMED_COMMUNITY)は、数式が無いため引き続き未実装。
- 持ち場: 試作の店は(8,3)、攻略本p.48の店は(8,6)。どちらもREMAKE_BALANCED_DEFAULT。
- 日給・評価値(警備値・清掃値・接客値)は、既存の計算がロースター全員を足しているため、
  3人分が自動的に入る。

## テスト

- スモーク: ロースターが3名で店長枠があること。評価値のテストは、2人分の固定値
  (57/51/25)をやめ、ロースター全員から計算する形にした。
- 契約テスト: 3名であること、店長の役割・教育値、evidence_noteの原文引用とREMAKEタグ、
  攻略本の店にも3人分の持ち場があること。既存の「2名」の検査3件を3名に更新。
- 結果: Python 755件成功(期待失敗1件は既存)、Godotスモーク成功。

## 明示的に対象外

- スーパー社員(発生条件・確率の記載なし)。
- 店長の教育による成長ボーナス、店長の解雇・異動の特別扱い。
