# 0164: 町マップを生成済みの地形・建物素材で描く(タスク#93)

## 背景

ユーザーの指摘:「マップ、ナニコレ？ さんざchatgptが生成したものが何も使われてないし、
建物も2種類くらいしかない。初代ザ・コンビニ自体こんな貧相なマップじゃない」。

タスク#90の町の画面は、攻略本p.11の画面写真から読んだ配置を、単色の四角と家の絵3種で
描いていた。`assets/raw/conveni_map_assets_v2`には建物52種に加え、地形・インフラ121種
(草地・土・木・道路・線路・踏切など)があるが、使っていなかった。README_V2_JA.mdを読んで
いれば分かったことで、これは見落とし。

原作の町の見た目は、プレイ動画のフレーム(`conveni_remaining_assets_v1/reference/
video_155s.png`・`video_189s.png`)で確認できる: 灰色の道路の格子、丸い木が点在する草地、
土の区画、小さな家並み、店舗は「本」「02」の平面マーク。

## 決定

- `tools/build_guide_town_map.py`の読み取りを増やした:
  - 草地のうち画面写真で暗い(下位4分の1)マスを「木」(`g`)とする。
  - 建物マスを`buildings`(マス位置・大きさ・絵のID)として書き出す。建物マスが2×2で
    かたまっている所は、2×2の建物の絵にする(白っぽければ会社、そうでなければ中型住宅)。
  - 1マスの建物は、画面写真の屋根の色で選ぶ。青→`house_small_a`、赤→`house_small_b`
    (素材のブリーフの色指定)、白→店舗の絵を順番に、その他→住宅A/B/Cを順番に。
  - 結果: 建物142棟、絵は20種類。
- `town_view.gd`は、`guide_town_map`のマス種別ごとに地形タイルを描く:
  - 道路は隣の道路とのつながりから、直線・T字路・十字路・行き止まりのタイルを選んで回転する。
  - 線路と道路が交わるマスは踏切のタイル。
  - その上に`buildings`の絵を重ねる。
- 自店: 区画にコンクリートのタイルを敷き、原作動画から切り出した「本」の平面マーク
  (`map_blue_hq`、CONFIRMED_VISUAL)を2×2マスの大きさで置く(動画上の大きさの実測)。
- 原作と同じく、町の一部だけを表示してスクロールする。1マス24px、ドラッグでマス単位で動かす。
  端で止まり、最初は自店を中心に表示する。
- 使う素材を`game/assets/town/`へ取り込んだ(地形10種、建物20種、本店マーク)。

## 証拠の段階

- 道路・線路の位置と格子: CONFIRMED_VISUAL(タスク#90のまま)。
- マスが木か草地か、建物か: PROVISIONAL(網点印刷の色からの自動分類)。
- 本店マークの絵: CONFIRMED_VISUAL(原作動画からの切り出し)。
- 地形タイル・建物の絵そのもの: 生成素材(原作の絵ではない)。
- どのマスにどのタイル・絵を置くか: REMAKE_BALANCED_DEFAULT。コードのコメント、
  JSONのevidence_note、契約テストの3か所に記載している。

## テスト

- 契約テスト:
  - 建物は必ず建物マスの上にあり、重ならず、建物マス全てを覆うこと。
  - 使う絵とタイルがすべて素材パッケージとゲームの両方にあること。
  - 建物の絵が10種類以上あること、本店マークの絵、REMAKEタグ。
  - タスク#72の「町に施設を捏造しない」テストは、「描く建物は全てデータの`buildings`から」
    に改めた。
  - numpy/Pillowがある環境では、画像を読み直した結果がJSONと一致すること。
- スモーク:
  - 1マス16px以上で、表示範囲がパネルの左に収まること。
  - スクロールが町の端(左上・右下)で止まること。
- 結果: Python 756件成功(期待失敗1件は既存)。Godotスモーク・Android previewスモークとも成功。
  スマホ配置のキャプチャで見た目を確認した。

## 明示的に対象外

- 建物の種類(学校・プール等)を画面写真から特定すること。
- 町の発展(建物が建つ)、他店の出店、店の場所の選択。
- 画面写真に写っていない、画面の外のマップ範囲。
