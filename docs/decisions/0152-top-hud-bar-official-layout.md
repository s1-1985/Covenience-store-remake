# 0152: ゲーム状態HUDを原作準拠の常時表示トップバーへ移動(タスク#82)

## 背景

ユーザーから「初代ザ・コンビニがどこにあるのか分からない、しょぼすぎる」
という直接の指摘を受けた。実際のプレイ可能クライアント画面を確認したところ、
`STORE STATUS`ヘッダーは付いているものの、ゲームの最重要状態(現在時刻・
日付・所持金)が右サイドの長いスクロール式アクションパネルの中に埋もれて
おり、常時見える位置になかった。

`docs/research/original-screen-visual-register-2026-09-05.md`(タスク以前
から既存のCONFIRMED_VISUAL台帳)には、実際の初代PS/SS画面から直接読み取った
事実が記録済みだった:

- V001(PS 店舗選択、CONFIRMED-VISUAL): 「上HUD: 年/月日/天候/時刻/所持金」
  表示例 `01年目01月01日 [快晴] 00:00 ¥180,000,000`
- V005(SS 店内+店舗カード、CONFIRMED-VISUAL): 「店内トップビュー」+
  「右側に店舗情報カード」「店舗名」「本店」「売上 ¥11,025」+
  「上HUD: `1年目 3月2日 [晴れ] 12:46 ¥57,903,060`」

つまり原作は、店内ビューを表示中でも画面上部に年月日・時刻・所持金を
常時表示する横長HUDバーを持ち、店舗名(「本店」)は別領域に表示される。
このクライアントはこの構造を一度も反映していなかった――タスク#77
(決定書0147)はカレンダーの「表示形式」(年/月/日の並び)だけを修正し、
「表示位置」(常時見えるHUDかどうか)は対象外のままだった。

## 決定

### トップバー(`UI/TopBar`)を新設し、時計・カレンダー・所持金をそこへ移動

`game/scenes/main.tscn`に、画面上部・全幅(`UI/Panel`アクションパネルと
`StoreView`グリッドの両方の上)に常時表示される`PanelContainer`
(`UI/TopBar`)を追加した。既存の`ui_theme.tres`をそのまま適用しており
(タスク#76の精神を踏襲、UIクロームなので証拠タグは不要)、新規デザイン
言語を導入していない。

中身は`HBoxContainer`で左から:
`本店` (StoreNameValue) → `Year 1 · Month 1, Day 1` (CalendarValue) →
`09:00` (ClockValue) → (スペーサーで右寄せ) → `¥1,000` (CashValue、
既存の金色強調を維持)。

`CalendarValue`/`ClockValue`/`CashValue`は既存ノードをそのまま
`UI/Panel/Margin/Scroll/VBox`から`UI/TopBar/Margin/HBox`へ移設した
(ノード名は変更していない――`reference_sim`のコントラクトテストと
`headless_smoke.gd`はノード名の存在/GDScriptプロパティ経由で検証して
おり、パス自体には依存していないことを事前に確認済み)。`main.gd`の
`clock_label`/`calendar_label`/`cash_label`の`@onready`パスのみ新しい
場所に更新した。表示ロジック(`_refresh_ui()`)自体は一切変更していない。

右サイドパネルの旧`ClockTitle`/`CashTitle`ラベルおよび重複していた
見出しは削除した(値は上のバーに一本化、情報の重複を避けた)。

### 店舗名ラベル「本店」を新規追加

このクライアントは店舗を1つしか実際にシミュレートしていない
(`PROJECT_MEMORY.md`第19節、2026-09-19付完成度評価6.1節「1店舗のみ
実装」)。V005のCONFIRMED_VISUAL証拠が示す実際の原作の用語
「本店」をそのまま静的ラベルとして採用した――新しい店舗名生成ロジックを
発明したわけではなく、複数店舗対応時にどう命名するかもまだ未確定
(チェーン拡張は現状「店舗数の数値のみ」)なので、`REMAKE_BALANCED_DEFAULT`
タグは付与していない(発明ではなく、確認済み原語の単純な転記のため)。

### 天候表示は今回も対象外(タスク#77の先例を維持)

V001/V005とも天候アイコン(`[快晴]`等)を含むが、`game/`クライアントには
天候シミュレーション自体が存在しない(タスク#63・#77で明示的に対象外と
された既存の決定)。今回新たに天候の値を発明して表示することは
データ整合性ルール違反になるため、引き続き実装しない。次に天候HUDを
追加するなら、まず`game/`側に天候メカニクス自体を配線するタスクが先に
必要。

### レイアウト座標の調整

`Title`(アプリ名ラベル、原作UIの一部ではない)を上部の小さい灰色テキスト
に縮小し、`StoreView`/`TownView`の開始Y座標を100→122に、右`Panel`の
開始Y座標を20→96にそれぞれシフトし、新しいトップバー(Y=40〜88)との
重なりを防いだ。ゲームロジック側の座標系(グリッドセル計算等)は
`StoreView`ノード自身のローカル座標を使っているため、この位置シフトは
描画位置のみに影響し、シミュレーション/当たり判定には影響しない。

## テスト

- このセッションで初めてGodot 4.3-stable Linuxバイナリをサンドボックス
  scratchpad配下に取得し(タスク#81と同じ手順)、実際に検証した
  (これまでのセッションの多くは「ローカルにGodot実行環境がないためCI
  で最終検証」という注記付きだったが、今回は実行して確認できた):
  - `godot --headless --editor --path game --quit` (インポート) → 成功。
  - `godot --headless --path game --script res://scripts/headless_smoke.gd`
    → `Vertical-slice headless smoke passed in 1240 steps.`
  - 追加で`xvfb-run`+ソフトウェアレンダリングで実際に`main.tscn`を
    インスタンス化しスクリーンショットを撮影し、新しいトップバーが
    意図通り描画され、グリッド/右パネルと重なっていないことを目視確認
    した(検証用の一時スクリプトはコミット対象外、確認後削除)。
- `reference_sim`: `pytest` 745 passed, 1 xfailed(既存件数から変化なし
  ――このタスクはシーン/スクリプトの構造のみの変更で、`reference_sim`
  側のPythonコードは一切変更していない)。

## 対象ファイル

- `game/scenes/main.tscn`
- `game/scripts/main.gd`
- `PROJECT_MEMORY.md`

## 明示的に対象外

- 天候HUDの実装(上記の通り、天候メカニクス自体が`game/`未実装のため)。
- 右サイドの巨大なアクションパネルをモーダルウィンドウ形式(原作の
  実際のUI方式、`PROJECT_MEMORY.md`第5節参照)へ再設計すること――これは
  独立した、はるかに大きいスコープのUI再設計タスク。
- 什器/客/床タイルのスプライト自体の画風変更(タスク#67-#71で攻略本
  アイコンを既に一部移植済みだが、フロア/壁のタイル画像は今回未着手)。
- ユーザーから見た目に関する次の要望として想定される、この2点は次
  セッション以降の候補として残す。
