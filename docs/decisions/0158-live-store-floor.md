# 0158: 客の同時入店・混雑の迂回・出入口の隣接・店員の自動補充(タスク#87)

## 背景

ユーザーがAndroid実機で遊んだ結果として、「店員は動かない、入口と出口が離れている、
客は一人ずつしか入店しない、あらゆる面で初代からかけ離れている」との指摘を受けた。
コードを調べると、いずれも原作の仕様ではなく、このクライアントの構造上の問題だった。

1. **客が1組ずつしか入らない**: `main.gd`は店内の客が全員帰った時だけ来店判定
   (`tick_idle_for_demand()`)を呼び、客がいる間は`step()`だけを回していた。`step()`は
   新しい客を入店させない。同時入店の仕組み(タスク#36、上限3人)は存在したが、
   通常のゲーム進行からは一度も使われていなかった。
2. **客同士が永久に止まる**: 同時入店を有効にすると、通路で向かい合った2人が互いの
   行き先をふさいで永久に動かなくなった。タスク#66の「ふさがれたら待つだけ」という
   実装が、既知の制限として注記していた現象。
3. **出入口が離れている**: 入口(0,0)、出口(8,0)で、前面の壁の両端にあった。
4. **店員が動かない**: 店員の自動補充(タスク#38/決定書0089)は実装済みだったが、
   既定設定で`restock_task_enabled: false`になっており、補充担当は一度も動かなかった。
   古い台本シナリオ(売り切りまでの手順を固定した試験)の再現性のためだけに
   オフにされていた。

## 決定

### 1. 実時間のゲームループ `tick()`

`VerticalSliceSimulation.tick()`を追加し、`step()`(時刻・全客・レジ待ち・補充)の後に、
同時入店の上限内なら毎分来店判定を行う。`main.gd`はこれだけを呼ぶ。原作は小さな店にも
多くの客が同時にいる(プレイ動画フレーム`video_900s.png`で店内に約8人)。`step()`と
`tick_idle_for_demand()`は既存の台本テストのために従来の意味のまま残した。

### 2. 混雑の迂回

`_try_move_along_route()`で次のマスがふさがっている時、`_try_detour()`が他の人の
いるマスを避けた別経路を同じ目的地まで探し、最初の一歩が空いていればその経路に
切り替える。根拠はCONFIRMED_COMMUNITY「複数の経路があれば客は混雑を迂回できる」
(`PROJECT_MEMORY.md`第4節、初代Wiki内装ページ)。迂回路が無い1/2マス通路では従来どおり
待つ(通路幅ルールの「すれ違えず混雑しやすい」を維持)。`store_layout.gd`に、他人の
位置を追加の障害物として扱う`find_path_avoiding()`を追加した。

### 3. 出入口の隣接

出口を(1,0)に移し、入口(0,0)の真横にした。CONFIRMED_VISUAL: 動画フレームの入口素材
`entrance_in`と出口素材`entrance_out`の切り出し座標が`[410,240,456,285]`と
`[456,240,503,285]`で、同じ行に隙間なく並んでいる(`assets/raw/
conveni_additional_assets_v1/manifest.json`)。以前の(8,0)はこのプロジェクト独自の配置。

### 4. 店員の自動補充を既定で有効化

店員が自ら棚を補充するのは確認済みの原作の挙動(`PROJECT_MEMORY.md`第3節「店員は
レジ・補充・清掃・体力回復を自律的に行う」、決定書0150の「手動補充と店員による補充」の
対比)。既定設定で有効にした。補充を始める在庫水準
(`restock_trigger_stock_units_at_or_below`)は、原典に数値が無いため既存の
`REMAKE_BALANCED_DEFAULT`値のまま変えていない。

## テスト

- `headless_smoke.gd`: 出荷設定を`tick()`で1営業日(960分)回し、同時に2人以上が
  買い物できること、10組以上が会計を終えること(詰まらないこと)、店員の自動補充が
  始まることを検証する新シナリオを追加。以降の既存の台本シナリオは、テスト側で
  自動補充をオフにしてから実行する(意図した前提条件の明示)。
  並行客シナリオの「移動中の2人が同じマスにいない」検査は、共有が意図的に許されて
  いる棚・レジの利用マスを除外するよう修正した(同じ棚で同時に買い物を終えた2人が、
  会計へ向かう最初の瞬間にそのマスにいるだけのケースを誤検出していた)。
- 契約テスト: `main.gd`が`tick()`を使うこと、自動補充が既定で有効なこと、出入口が
  隣接していること(動画素材の座標とも照合)、迂回処理が存在することを検証。
- 結果: Python 750件(期待失敗1件は既存)、Godotスモーク成功。
- スクリーンショットで出入口が並んで描画されること、客が複数同時に店内にいることを確認。

## 明示的に対象外(次の作業)

- 来客数そのもの(需要式の係数は依然`REMAKE_BALANCED_DEFAULT`で、動画の約8人に比べて
  まだ少ない)。
- 店内の什器・商品の充実(試作レイアウトは棚2つ・商品2種のまま)。
- 清掃・休憩など補充以外の店員の動き。
- 町マップ。
