# 0190: 客の種類ごとに目的・所持金・ついで買いを変える(タスク#120)

## 背景

ユーザーから「客の種類ごとに購買目的、買い増し行動に変化をつけて」という依頼があった。

これまでは、客の目的は建物の「主なほしい品物」だけで決まっていた。
客の見た目は、IDから決めた飾りだった。

## 根拠

攻略本の顧客データ(本2 pp.134-143、CONFIRMED_OFFICIAL)がある。
すでに `reference_sim/conveni_sim/baseline_data.py` に書き起こしてあった。

- 21の客層。
- 143の来店行。1行ごとに次が載っている。
  - 来店時間と滞在
  - 来店手段
  - 10の数値(スタミナ・素早さ・マナー・集中力・買物重要度・価格重視度・距離重視度・サービス重視度・平日/休日来店割合)
  - 所持金
  - 目的の品
  - ついでに買う品(3つまで)

この表は、初代専用Wikiの観察(`docs/research/customer-purchase-role-merchandising-2026-09-05.md`)とも合う。

- おでん・中華まん・温かい飲料・冷凍食品・調味料は、目的の品に一度も出てこない。ついでの品だけ。
- 弁当は、ついでの品に一度も出てこない。
- スタミナが一番低いのはおじいさん(10)とおじさん(50)。
  - 攻略本 p.35「怒りやすいお客さんは、おじさんやおじいさんに多い」と一致する。

客のスプライト customer_01〜21 は、この21客層の順に1人ずつ描かれている(manifest の name_ja)。

## 決定

`tools/build_guide_customer_types.py` で、表を `guide_customer_types` として vertical_slice.json に写した。

本プロジェクト独自の使い方(REMAKE_BALANCED_DEFAULT、`rules` と evidence_note)は次のとおり。

- どの客層が来るか:その時刻が来店時間内にある行から、平日来店割合に比例して選ぶ。
  - 700と誤植された1行は100で頭打ちにした。
  - このゲームには曜日がないので、休日来店割合は使わない。
- 目的:客層の目的の品に、住んでいる建物の欲しい品物を1つ足す。
- 所持金:超える品は買わない。
- ついで買い:1品取るたびに、もう1品取りに行くことがある。
  - 確率は 0.6 ×(100−集中力)/100 × 什器の注目度。
  - 表の「ついでの品」なら店内のどこでも取りに行く。
  - それ以外は、近く(4マス)の什器の品だけ。重みは0.3。
- 価格:値上げ率P%のとき、価格重視度/100 × P × 0.02 の確率で棚に戻す。値下げすると、ついで買いが増える。
- 素早さ:棚の前にいる時間 × 100/(50+素早さ)。
- スタミナ:レジで怒るまでの我慢 × スタミナ/70。0.25〜1.5の範囲に収める。
- 客は、その客層のスプライトで描く。
- 客のカードに、客層・目的・所持金の残りを出す。
- 今月来た客層の数を「店舗成績」に出す。

## テスト

- `_check_customer_types`:次を確かめる。
  - 21客層・143行ある。おでん等は目的にならず、弁当はついでにならない。
  - 2時の客は2時の行から選ばれる。
  - 客は客層のスプライトで描かれる。
  - 所持金を超える品は買わない。価格に敏感な客は値上げで棚に戻す。スタミナ10の客は我慢が最小。ついで買いが起きる。
- 契約テスト:`test_customer_types_come_from_the_guide`(reference_sim の表と1行ずつ一致)。
- 既存の建物需要テストは、客層を切って建物だけを確かめるようにした。
