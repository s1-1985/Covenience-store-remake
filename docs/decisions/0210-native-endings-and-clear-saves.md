# 0210 — 終了値・解除・原作の終了画像とクレジットを本体へ接続

## 問題と変更

従来は都庁・10店舗・経営者評価の条件を満たしても、クリアのラベルだけを出して営業を続けていた。原作の終了値と解除ビット、保存確認、クリア済みセーブの扱いが本体に接続されていなかった。

`ProgramProgression`へ原判定を移す。所有権bit15と稼働状態で自店を数え、モード1・10店で終了値1と解除bit2を立てる。都庁は終了値0／bit1。上級・極上は原作と同じく**年次評価通知の消費時**に100点なら終了値2／3とbit4／8を立てる。帳簿締め直後に通知順を飛ばして終了しない。解除値を保持したOR、signed8モード、signed32資金・年数、signed16通し番号を扱う。

0時の負資金・年99以上・通し番号99以上は終了値4、モードFF。終了待機またはクリア済みFF保存では、tick・step・待機更新の各入口から営業へ戻らない。終了演出中は背後の通知表示・消費も止め、待ち行列を維持する。進行値はJSONへ保存し、古いJSONは未終了の既定値で読む。壊れた進行値は本体の変更前に拒否する。

終了値0/1/2/3/4の画面選択は原表 `[0,1,2,2,3]`。元のTOTYO001、MISE000〜003/005/006、ENDSH00/01、MSG00の472〜475、STAFFの102行の字形をPNGへ抽出する。スプライトの原座標・サイズ・テクスチャ位置、窓の原矩形をデータに保持。320×240の画面を拡大して描く。上位スプライト枠から描き、64回×6フレームの上昇と原128色パレットの交替を再生する。

クレジットは原20ページの行数（合計100行）と最後の2行を使う。各ページ164フレームの1px上昇＋186フレーム保持、最後120フレームの上昇を経て、合計7120フレームで承認待ちになる。終了画像の導入4＋音声準備1フレームと固定384フレームを区別する。

成功終了は画像→クレジット→保存する／保存せずに戻る→タイトル。承諾時のみJSONの保存FFを立てて書く。一時ファイルへ全JSONを書いてflushを検査した後で差し替える。書込み失敗時は旧ファイルを維持してFFを戻し、同じ確認画面で再選択できる。辞退は既存セーブを変更しない。倒産はクレジットと保存確認を通らず、既存セーブも保存FFも変更しない。

原5A228の条件どおり、タイトルの極上はsigned-byte解除値が7のときだけ選択可能。クリア済みFFのJSONは「つづきから」で解除値を読み取り、営業へ入らずタイトルに留まる。ゲーム内ロードから同じ保存を読んだ場合も、営業を進めずタイトルへ戻す。

## 検証

独立モデル由来の198自店判定、45終了判定、全256解除byte、5画面振分けをGodotと照合。実際の町発展・所有店舗の判定・年次通知消費・0時判定から終了値と解除ORへ接続する指定条件試験も行う。通常プレイで10店舗や100点まで到達した証明とは分ける。

実シーンで原画像の読込み、固定フレーム待ち、クレジット、辞退による元ファイル保持、実際に一時ファイルを作成できないファイルシステム条件でのFF復元・旧保存保持・再選択、承諾保存、タイトル復帰、FF読込みと極上解除、倒産による保存の不変更を確認する。日本語フォントには新たに「結」の字形を追加した。
