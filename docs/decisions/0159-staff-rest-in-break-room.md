# 0159: 客がいない間、店員は休憩室で休む(タスク#88)

## 背景

ユーザーの指摘「店員は動かない」に対し、タスク#87で店員の自動補充を既定で有効にした。
ただし補充担当は在庫が減った時しか動かず、レジ担当はレジ裏から一歩も動かない。
一方、原作の攻略本には店員の居場所についての明確な記述がある。

- 攻略本 p.16「レジの場所」(PDF1 6ページ目、原文を画像で再確認):
  「お客さんがいないとき店員は休憩室で休んでいる。だからレジと休憩室の距離が近いほうが、
  すぐにレジに向かうことができて便利なのだ。」
- 同 p.17「社員休憩室」: 「休憩室は、疲れた店員のスタミナを回復する大事な場所。
  ふたつある休憩室のうち価格が高いほうが回復率も高いのだ。」
  (画面写真に「店員控え室を決定して下さい 価格 ¥7,000 維持費 ¥2,400/日」)
- 休憩室1/2の価格・維持費・大きさは`reference_sim/conveni_sim/baseline_data.py`の
  `FIXTURES`に既にCONFIRMED_OFFICIALとして入っていたが、クライアントには
  「休憩の仕組みが無い」という理由で移植されていなかった(タスク#41の除外リスト)。

## 決定

### 1. 休憩室を什器カタログと開始時の店に追加

`break_room_1`(3,000円/維持費1,200円/2×2)と`break_room_2`(7,000円/2,400円/2×2)を
`fixture_catalog`に移植し、開始時の店(既定レイアウトと見本レイアウト2種)に
`break_room_1`を1つ置いた。維持費は他の購入什器と同じく毎日の維持費に含まれる。

置き場所は店の右下(原点(6,12)、出入口(7,11))。攻略本はレジの近くに置くよう勧めて
いるが、今の試作レイアウトはレジの隣に2×2の空きが無い。攻略本に載っている店の
レイアウトへ置き換える作業(次のタスク)で位置を見直す。

### 2. 休憩のサイクル(`_step_staff_rest()`)

- 店内に客が1人もいない時、手の空いた店員は休憩室の出入口まで歩き、そこで休む
  (`rest_phase`: `to_break_room` → `resting`)。
- 客が店内にいる時は、各店員が自分の持ち場(`start_subcell`)へ歩いて戻る(`to_post`)。
- レジ担当がレジ裏に戻るまで会計は始まらない。その間、客はレジで待つ。
  攻略本が「レジと休憩室の距離が近いほうが便利」と書いている理由をそのまま再現する。
- 補充の仕事が入った店員は休憩をやめてすぐ補充に向かう(`begin_restock()`が
  `rest_phase`を消す)。
- `rest_phase`は`state`とは別の値にした。休憩中の店員も`state == "idle"`のままなので、
  「作業中は内装を変えられない」等の既存の判定を変えずに済む。
- 移動は客と同じ占有・迂回の規則(`_subcell_is_free_for()`/`_try_detour()`)に従う。
  休憩中にプレイヤーが什器を動かして経路がふさがった時は、次の分に経路を引き直す。
- 休憩室が無い店では、店員は持ち場に留まる。

### 3. 表示

休憩中の店員の論理上の位置は休憩室の出入口マスだが、休憩室の絵の中に描く。
`REMAKE_BALANCED_DEFAULT`: 原作が休憩室の中の店員をどう描くかは回収済みの資料に
無いため、室内の位置とずらし方(`store_view.gd`の`_break_room_rest_spot()`)は
このプロジェクト独自。休憩室の絵そのものは攻略本 p.48 の店舗図から切り出したもの
(`assets/raw/conveni_guide_diagram_sprites_v1/`、切り出し座標とハッシュは
`manifest.json`)。その図だけでは休憩室1と2のどちらの絵か判別できないため、
両方に同じ絵を使っている。

## 未実装(根拠はあるが今回は入れていない)

- 体力(スタミナ): 初代Wikiでは、レジ・補充・清掃で体力が減り、0になると休憩室に戻って
  原則全回復まで休む(CONFIRMED_COMMUNITY、`docs/research/behavior-rules-evidence-
  2026-09-05.md`第7節)。体力の減り方・回復の速さの数値が無いため今回は入れず、
  休憩室1と2は現状同じ動きをする。
- 清掃。

## テスト

- `headless_smoke.gd`: 出荷設定で1営業日回し、休憩の開始と持ち場への復帰が起きることを
  検証。さらに決定論的なシナリオとして、無人の店で全店員が休憩室の出入口で休むこと、
  店が無人のうちは誰も戻らないこと、客が入るとレジ担当がレジ裏に戻ってから初めて
  会計が始まることを検証。休憩室の維持費や休憩の往復を前提にしていない既存の台本
  シナリオでは、テスト側で休憩室を取り除いてから実行する。UIの入れ替えシナリオは
  休憩室と重ならない位置に什器を置くよう座標を1マスずらした。
- 契約テスト: 休憩室2種の価格・維持費・大きさが`baseline_data.py`と一致すること、
  開始時の店に休憩室があること、p.16の原文がコードに引用されていること、会計開始の
  条件にレジ担当の帰着が入っていること、表示位置の`REMAKE_BALANCED_DEFAULT`タグ、
  切り出し画像のハッシュが`manifest.json`と一致すること。タスク#41の什器移植テストの
  除外リストから休憩室を外した。
- 結果: Python 751件成功(期待失敗1件は既存)、Godotスモーク成功、Android preview
  スモーク成功。スクリーンショットで、休憩室の中で2人が休み、客が入ると歩いて出て
  いくことを確認。
