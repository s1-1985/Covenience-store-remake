# 0204: 店長のお知らせと、雑誌・コンテストを原作プログラムの仕組みに(タスク#134)

## 背景

ユーザーの依頼(2026-09-27):

> まだ入れてないものも、データを解析して抽出して

これまで、客が怒ったとき・駐車場がなくて車の客が帰ったときは、そのたびに画面にお知らせを出していた(この作品の作り)。店長からの報告、雑誌の記事、コンビニ・コンテストはなかった。

## 根拠

CONFIRMED_BINARY(SLPS_007.82)。文言はすべてプログラム内の文字列そのもの。

### 店長のお知らせ(0x8003B570、2分ごと)

- 4時間ごと(0・4・8…時の0分)に、数を数え直す。お知らせを出したときも数え直す。
- 数えるもの:レジで怒った客(店の +0x12E1)、品切れで買えなかった客(+0x12E2)、駐車場がなくて入れなかった客(+0x12E3)、床の清潔さが70%未満だった時間(+0x12E4、毎時0分)。
- お知らせを出す条件(学歴 = 店長の学歴):
  - 怒った客 > (100 − 学歴) ÷ 5 + 1
  - 買えなかった客、入れなかった客 > (100 − 学歴) ÷ 4 + 5
  - 汚れた時間が4以上で、1〜100の乱数 ≤ 学歴
- 学歴70未満の店長は短い文(「レジの混雑が解消されません」など)、70以上は人数を入れた文(「レジが混雑して/6人のお客さんに/怒られてしまいました」など)。
- まれに売れ行きの報告:乱数の下13ビットが0(1/8192)のとき。さらに1〜100の乱数 ≤ 学歴なら、前回からの一番売れた品が200個以上のときに限り、1/2で「最近、〇〇がとってもよく売れています」、もう1/2で並んでいる品のうち一番売れなかった品が6個未満なら「最近、〇〇があまり売れていません」。1/8192を引いたときは、学歴の判定に外れても、品ごとの数と上の数を0に戻す。
- 27番目の品(キャッシュディスペンサー)だけ「あまり利用されていません」。この作品の品目にはない。

### 雑誌・コンテスト(0x8003CEAC、2分ごと)

- 乱数の下14ビットが0(1/16384)で、町の人口(0x80020498:町の全マスの客の数の合計)が10000以上、町の店(自分の店とライバル店)が5軒以上のとき。
- 5種類から1つ(乱数 % 5):
  - コンビニ・コンテスト:評価(+0xC68)が一番の店。賞金は店の数 × 1000万円(表示は「1億2000万円」の形)。
  - 雑誌「人気のあるお店」:人気(+0xC6C)が一番。店長の学歴と教育が+2。
  - 雑誌「清潔なお店」:清掃の値が一番。店長の学歴と機敏さが+2。
  - 雑誌「サービスの良いお店」:サービスの値が一番。店長の学歴と社交性が+2。
  - 雑誌「安いお店」:100 − 値段% が一番。一番が0以下(どの店も定価以上)なら出ない。店長の学歴と体力が+2。
  - 上がった値は100で止まる。
- 一番の店が複数あれば、その中から乱数で選ぶ。ライバル店が選ばれても記事は出る。

### 強盗・火災・賃上げ要求の文字列について(調査の記録)

- 0x800990BC〜0x80099128 の文字列(「〇〇さんが〇〇の賃金UPを要求してきました」「強盗に入られて」「火災が発生して」)は、プログラムのどこからも参照されていない。
- 同じ文言は MSG00 の235・237・238番にもある。強盗・火災の場面(MSG 467・468)は 0x80052270 から呼ばれ、その呼び出し元は 0x8003BF28。この関数はタスク#135(決定0205)で読んだ。

## 決定

- 数値は `ps1_program_tables.manager_reports` と `town_press` に置いた(`tools/ps1/extract_program_tables.py`)。
- `VerticalSliceSimulation`(本番のゲームのみ):
  - 店ごとに `_notice_counts`(怒り・品切れ・駐車場・汚れ)と `_sold_counts`(品目ごとの売れた数)を持つ。セーブには入れない(ロードすると0から数える。4時間ごとに数え直す数のため)。
  - `_step_manager_reports()` を2分ごとに店ごとに呼ぶ(`_admit_program_group` の中)。事件 `manager_report` / `sales_report`。
  - `_step_town_press()` を2分ごとに町全体で1回呼ぶ(`tick()` の中)。事件 `town_press`。
  - 雑誌で上がった店長の値は `_candidate_raises` に持ち、セーブの `candidate_figure_raises` に入れる。店長の学歴(成長・助言・お知らせ)、成長の上限、体力の最大値は、上がった値で読む(`_candidate_figures`)。
  - コンテストの賞金は、支出の記録にマイナスで入れる(`contest_prize`)。
  - お知らせの乱数は来客の乱数と分けた(`_report_rng`)。来客の並びを変えないため。
- 画面:`manager_report`・`sales_report`・`town_press` をお知らせに出す。駐車場の都度のお知らせ(`cars_turned_away`、タスク#131)は画面に出さないようにした。原作では店長の報告でだけ知らされるため。事件の記録は残す。
- ライバル店の清掃の値は攻略本の値(2店とも30)。ゲーム中に出店した店も30(攻略本のライバル店の値)。

### この作品の決めごと(REMAKE_BALANCED_DEFAULT)

`ps1_program_tables.evidence_note`、コード、テストの3か所に記載した。

- 汚れた時間:原作は床の清潔さが70%未満の時間を数える。この作品の汚れは「歩かれたマス」の数(上限24)なので、上限の30%以上(8マス以上)を汚れた時間とした(`DIRTY_HOUR_SHARE`)。
- ライバル店の評価:ライバル店の月ごとの評価は計算していないので、新しい店の値(評価10)のままとした。

### 推論であること

- コンテストの賞金は、プログラムでは店の所持金を減らす関数(0x8001CBC4)に「マイナスの額」を渡している。これを「賞金が入る」と読んだ(推論。文言が「賞金」であることと合う)。

## 影響

- この作品の町は、開始時の人口(マスの客の合計)が828人。雑誌・コンテストは、町が10000人以上に育つまで起きない。ライバル店も含めて5軒以上が必要。
- 客が怒るたびのお知らせ(`checkout_anger_triggered`)は、これまでどおり画面に出る(変えていない)。

## テスト

- `headless_smoke.gd` の `_check_program_demand`:
  - 学歴80の店長は、怒り5人・品切れ10人・駐車場10人ではお知らせを出さず、怒り6人・駐車場16人で人数入りの文を出して数え直す。
  - 学歴20の店長は短い文。4時間ごとに数え直す。汚れた時間4で学歴100の店長が「清掃が行き届きません」。
  - 店が5軒未満では雑誌もコンテストもない。定価の店だけなら「安いお店」は出ない。値下げした店が選ばれ、店長の学歴と体力が+2。セーブ・ロードで残る。5軒の町のコンテストで5000万円。100を超えない。
  - REMAKE_BALANCED_DEFAULT の2つ(汚れた時間の30%、ライバル店の評価)。
- pytest の `test_program_demand_follows_the_program`:表が道具の出力と一致、数値、タグ3か所、画面の事件名。
