# 0202: 店の外の敷地と駐車場(タスク#132)

## 背景

ユーザーの指摘(2026-09-27):

> 初代ザ・コンビニの画像とか動画見たら分かると思うけど、店の外のスペースが存在する。そこに駐車場とかを設置する。現状は外の空間がなく店内だけだったと思うので、そこも実装して。

タスク#131では、駐車場を店内の床に置く形にしていた。

## 根拠

- CONFIRMED_BINARY:PS版ディスクの `DAT/SHOP0302.BIN`(中型・横長の店の床)は、幅12・高さ12の升目で、次の並びになっている。
  - 上から3行:外の地面(値 0x10)
  - 1行:上の壁。中央に入口(値 0x1F・0x23)
  - 7行:店内(左右が壁)
  - 1行:下の壁
- つまり原作の店の升目は「入口の前に3行の外の地面+建物」。幅は建物(壁を含む)と同じ。
- 攻略本の店の大きさ「10×10・12×12・14×14」は、この外の地面を含めた升目の大きさと合う(中型:外3行+建物9行=12)。
- 駐車場の台数は、店の升目の上にある駐車場の什器から数える(0x80024520、タスク#130で確認)。
- 小型・大型の店の外の地面が同じ3行であることは、中型のデータと攻略本の大きさからの類推。

## 決定

- 本番のゲームの店に、入口の壁の前(この作品ではどの店も入口は上の壁)に、深さ3タイル・店と同じ幅の「外の敷地」を持たせた(`VerticalSliceSimulation.outdoor_lot_rect`)。
- 駐車場(`placement: outdoor` の什器)は、外の敷地にだけ置ける。店内には置けない。試作の場面(敷地なし)は、これまでどおり床に置ける。
- 敷地の什器は、購入・移動・売却(半額)・倉庫へしまう・倉庫から置く、ができる。維持費も日ごとにかかる。セーブに含む。
- 改装で敷地が狭くなり入りきらない駐車場は、倉庫に入る。
- 画面:敷地は店の上にアスファルトの色で描き、駐車場の絵を置く。スマホ画面では、敷地も含めて表示領域に収まるように店を縮める(小型店で約0.73倍)。

## テスト

- `_check_program_demand`:敷地の大きさと位置、店内に置けないこと、置くと台数が増えること、重ならないこと、はみ出さないこと、移動、セーブ・ロード、売却。
- Android preview smoke:店と敷地が表示領域に収まること(「等倍で描く」の条件を改めた)。
- pytest:定数・根拠の記載・描画関数があること。

## この作業でしないこと

- 原作の店の升目そのもの(壁もマスとして数える升目)への作り替え。
- 敷地の地面の絵(原作のタイル画像は使っていない。スマホ向けの見た目の方針のまま)。
