# 0184: 調査の収支グラフ、店員の掃除の行き詰まりの修正(タスク#113)

## 背景

- 原作の「調査」には収支グラフがある。月ごとの売上と収支を見て経営を判断する画面で、これまで無かった。
- 収支グラフを確かめるため2か月分動かしたところ、棚がほとんど空になっていた。
  調べると、1日目のうちに店員2人が互いの立っているマスを掃除しようとして向かい合い、そのまま永久に待ち続けていた。
  このため、誰も棚を補充しなかった。9日で在庫は470個から138個に減った。

## 根拠

| 内容 | 出典 | 段階 |
|---|---|---|
| 「調査」で各店舗の売上成績・収支グラフが見られる。「調査→全店収支グラフ」 | docs/research/menu-hierarchy-evidence-2026-09-05.md 3章・5章 | CONFIRMED_COMMUNITY |
| 1か月の収支 = 4日間の収支×8 | 攻略本 | CONFIRMED_OFFICIAL |

グラフの見た目は資料にない。本プロジェクト独自のもの。

## 決定

- 月末決算の記録に、その月の売上(4日間の売上×8)を加えた(`month_sales_yen`)。
- 調査の窓に「収支グラフ」を加えた。直近12か月の売上(青)と収支(緑、赤字は赤)を棒グラフで表示する。
- 掃除の修正は次のとおり。
  - 掃除に向かう店員は、目的のマスに誰か(店員か客)が立っている時は、そのマスをあきらめる。
  - 6ティック動けなかった時も、そのマスをあきらめて別の仕事を選ぶ。
  - 6ティックという値は本プロジェクト独自(REMAKE_BALANCED_DEFAULT)。
    タグは、コード、`staff_work.evidence_note`、テストの3か所にある。

## テスト

- `headless_smoke.gd`(`_check_shelves_stay_filled`): 6日間動かし、毎日補充が始まることと、6日後も在庫が満杯の3/4以上あることを確認する。
  修正前は2日目から補充が止まっていた。修正後は9日後も在庫が455個前後を保った。
- 契約テスト: 月の売上の記録、グラフ、掃除の修正、タグ。
- 画面で確認: 2か月動かした後の調査の窓に、1月・2月の棒が出ること。
- 結果: Python 774件成功(期待失敗1件は既存)。Godotスモーク・Android previewスモークとも成功。
