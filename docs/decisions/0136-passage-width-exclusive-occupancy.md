# 0136: 通路幅・すれ違い制約を排他的サブセル占有として実装(タスク#66)

## 背景

ユーザーから、第三攻略本の再確認で得られた未実装候補のうち「通路幅・すれ違い制約」に
着手するよう明示的な指示があった。クイックリファレンス本「店舗」セクション(書籍頁5)を
400dpiで再確認し、以下を直接確認した:

- 「① 1マス通路 客や店員が2人並んで通れる幅。すれ違えるので混雑しにくい。」
- 「② 1/2マス通路 客や店員1人が通れる幅。すれ違うことができず、混雑しやすい。」

`reference_sim/conveni_sim/store_grid.py`は既に`subcells_per_tile=2`(1マス=2サブセル)を
デフォルトとしていたが、そのコメントは「0.5タイル単位が実際の挙動に影響するという研究は
あるが、原作エンジンの内部セルサイズを証明するものではない」と明記しており、これは
未確認の推測に基づく既定値だった。今回の再確認により、この0.5タイル(1/2マス)分割は
CONFIRMED_OFFICIALであることが直接裏付けられた。

しかし`game/`側の実装を調査したところ、この「すれ違い不可」というルール自体は
一切配線されていなかった——`CustomerState.move_along_route()`/`StaffState.
move_along_route()`は他のアクターの位置を一切考慮せず、複数の顧客・店員が同じ
サブセルに重なって存在できてしまう状態だった(衝突判定が皆無)。

## 決定

### 排他的サブセル占有として実装(明示的な通路幅計算はしない)

「通路の向きごとの幅」を明示的に計算するアプローチ(原典が触れていない方向依存の
幾何解析が必要になる)ではなく、**同じサブセルに2体以上のアクター(顧客・店員)が
同時に存在できない**という排他制約を実装した。この制約からは、原典の2つのルールが
自然に(創発的に)再現される:
- 1マス幅(2サブセル)の通路: 並行する空きサブセルが常に存在するため、すれ違い時に
  ブロックされることがない(=「すれ違えるので混雑しにくい」)。
- 1/2マス幅(1サブセル)の通路: 対向するアクターが避ける余地がないため、セルが
  空くまで移動がブロックされる(=「すれ違うことができず、混雑しやすい」)。

`VerticalSliceSimulation._subcell_is_free_for(mover, target)`が全アクター
(`customers.active_customers()`+`staff.all_staff()`)を走査し、対象セルが
他のアクターに占有されていないか確認する。`_try_move_along_route(mover, next_phase)`が
既存の4箇所の移動呼び出し(顧客の`to_shelf`/`to_checkout`/`leaving`、店員の
`to_restock`)をすべて置き換える。ブロックされた場合はその場で待機し、次tickに
再試行する(再ルーティングはしない——原典は「複数ルートがあれば迂回できる」ことは
確認しているが、個々のアクターがブロック時に迂回するか待機するかは述べていないため、
このプロジェクト独自の判断=REMAKE_BALANCED_DEFAULTとして「待機」を選んだ、最小限の
実装)。

### 例外1: チェックアウト担当店員の固定持ち場

CI上でのみ発見できた実装時の問題(ローカルにGodot実行環境がなく、この種の幾何的な
衝突はテストを実際に流すまで判明しなかった): 既定シナリオのレジ担当店員
(`staff-1`)は`start_subcell`がチェックアウトのインタラクションセルのすぐ隣に
固定されており、一切移動しない(状態は`idle`/`checkout`のみ)。この店員を通常の
障害物として扱うと、通常の顧客経路がこの固定位置を恒久的に塞がれ、デッドロックが
発生した。レジ担当店員はレジ台の向こう側に「常駐」しているのであって、通路を
実際に歩いて通過中の歩行者ではないため、チェックアウトインタラクションセル自体の
例外と同じ理由で、`checkout_staff_id`に一致する店員は衝突判定から常に除外する。

### 例外2: アイドル状態の店員

同じくCIで発見: 什器移動(`try_relocate_fixture`)のテストで棚を再配置した結果、
顧客の新しい経路がアイドル状態の`staff-2`の固定位置と交差し、以降のすべての来店が
デッドロックした。このプロジェクトには「アイドル中の店員がその場をどける」という
挙動が存在せず、アイドル位置は単なる待機場所のマーカーであって、モデル化された
物理的な立ち位置ではない。これを恒久的な障害物として扱うのは、原典のルール
(通路で実際にすれ違おうとする2者の間の制約)を超えた過剰な創作になる。したがって
`state == "idle"`の店員も衝突判定から除外する。補充作業中(`to_restock`/
`restocking`)の店員は実際に売り場を歩き回っている(または棚に張り付いて作業中)と
みなせるため、引き続き通常の障害物として扱う。

### 例外3: チェックアウト待ち行列セル

`_checkout_interaction`セル(レジ位置)は、タスク#36の設計上、複数の待機客が
論理的に同じ位置に収束する意図的な例外(`store_view.gd`が見た目上だけオフセット
表示している)であるため、この排他制約から明示的に除外した。除外しないと、2人目の
客が永久にレジセルへ「到達」できず、`_checkout_queue`に加われなくなってしまう
(FIFOキュー機構そのものが壊れる)。

## テスト

- タスク#36の既存シナリオ(`concurrent-a`/`concurrent-b`、同一プランで同一経路)を
  拡張。両者は同tickで入店位置に重なった状態から始まるため、この排他制約を
  自然に演習する。
  - 全tickにわたり、チェックアウト関連フェーズを除く在店客同士が同じサブセルを
    共有しないことを検証(新ルールの不変条件)。
  - `concurrent-b`が移動フェーズ中に実際に1回以上足止めされることを検証(このテスト
    が実際にルールを演習していることの確認、空振りでないことの保証)。
  - 既存のレジ待ち行列アサーション(同時サービス不可、FIFO待機)は変更なしで
    そのまま通ることを確認。

## 対象ファイル

- `game/scripts/vertical_slice_simulation.gd`
- `game/scripts/headless_smoke.gd`
- `reference_sim/conveni_sim/store_grid.py`(コメント更新のみ、ロジック変更なし)
- `PROJECT_MEMORY.md`

## 明示的に対象外

- 明示的な通路幅の事前計算(方向依存の幾何解析)は行っていない。排他的占有からの
  創発的な結果のみに依拠する。
- ブロックされたアクターの自動迂回(再ルーティング)は実装していない。原典が
  「迂回できる」ことを確認しているのは事実だが、個々のアクターが待機するか迂回するか
  の選択条件は述べられていないため、待機のみの最小実装に留めた。
- 極端に狭いレイアウト(1本しかない1/2マス幅通路で2アクターが正面から向き合う場合)
  での理論上のデッドロックは、既知の制約として受け入れ、対策していない
  (`_subcell_is_free_for`のコード内コメントに明記)。
- `reference_sim`側(`store_grid.py`)へのすれ違いロジック自体の移植は行っていない
  ——コメント更新のみ。`reference_sim`には元々このレベルの実時間衝突シミュレーションを
  駆動するランタイムループが存在しないため、`game/`側でのみ実装した。
