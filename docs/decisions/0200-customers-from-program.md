# 0200: 客の来店と店選びを原作プログラムの仕組みに(タスク#130)

## 背景

ユーザーの依頼(2026-09-26):

> 推測で作っていたアルゴリズムや、未実装のアルゴリズム等、今回得られた情報から実装して

これまでの来客(本番のゲーム):

- 毎分、「期待来客数 × 顧客独占率」から客が来るかを決めていた(DemandPolicy)。
- 客はどの建物から来るかを、店の周りの建物のマス数で選んでいた(タスク#102)。
- 客の種類は、その時刻に来られる攻略本の行から、平日来店割合に比例して選んでいた(タスク#120)。
- いずれもこの作品の創作(REMAKE_BALANCED_DEFAULT)だった。
- 同時に店内にいる客の上限も、この作品の値(3/6/8)だった。

## 根拠

CONFIRMED_BINARY(PS版の実行ファイル SLPS_007.82)。詳しくは
`docs/research/ps1-executable-formulas-2026-09-26.md` の「客の来店と店の選び方」とその追記。

- 1日に1回(0時)、町のすべてのマスの「客の組み合わせ」(来店表の行と人数)を、店に割り振る。
  - 天気の値が 行の買物重要度 + 20 より大きい日は来ない。
  - 季節外れの品が目的なら、9割が来ない。
  - 平日来店割合(休日は休日来店割合)の確率で来る。
  - 店は、人気+20% の確率で候補になり、営業中・駐車場(車の客)・目的の品の在庫・距離(徒歩20・自転車40・バイク60・車70マス)を満たすものから、点数の最も高い店。
  - 点数 = 値段の値 × 価格重視度 + 近さ × 距離重視度 + サービスの値 × サービス重視度。値段とサービスは全店の中での相対値。
- 2分ごとに、店ごとに 1/4 の確率で、今の時刻に来られる行から最大5人の組を1組入れる。
- 店内の組の上限は 小10・中15・大20。
- 組の人数 n だけ在庫が減り、売上は n 倍。
- 来店表は、実行ファイルの144行を使う(攻略本の143行とは20行で数値が違い、1行多い)。

## 決定

- 原作の表を `game/data/vertical_slice.json` の `ps1_program_tables` に書き出す道具を作った(`tools/ps1/extract_program_tables.py`)。
  - 来店表144行、組み合わせ137件、この作品の建物42種と原作の建物の種類の対応、時刻表、休日、距離の上限、季節の品、組の上限。
  - 原作の天気のしきい値が `weather.monthly_percentages` と同じであることを、道具の中で確かめている。
- 来客の仕組みを `ProgramDemand`(`game/scripts/domain/program_demand.gd`)にまとめた。
- `VerticalSliceSimulation`(本番のゲームのみ):
  - 日の区切り・出店・店の追加・ロードのときに、その日の客を全店に割り振る(`_allocate_program_day`)。
  - 2分ごとに組を入れる(`_admit_program_group`)。客は目的の品の棚へ向かう。
  - 組の人数だけ商品を取り、人数分の代金を払う。所持金は1人分だけ減る。
  - 顧客独占率は「今日この店に来る人数 ÷ 町の全員」。
  - タスク#102の建物ごとの客(`_building_customer_plan`)と、タスク#120の行の選び方(`_pick_visit_row`)を外した。
  - 店の敷地がないとき(p.48の確認用の場面)と、試作の場面は、これまでの来客のまま。
- 客のカードに「など3人」のように組の人数を出す。

### この作品の決めごと(REMAKE_BALANCED_DEFAULT)

`ps1_program_tables.evidence_note`、コード、テストの3か所に記載した。

- マスの組み合わせ:原作はマップを作るときに5つの候補から選ぶ(推測)。この作品の町は攻略本の地図から作ったので、マスの位置から決める(`square_mix`)。
- ベビーカーの女性の行は、攻略本の21種に同じ種類がないので「子供連れのおばさん」とした。
- ライバル店:営業時間・人気・サービスは攻略本の値(`guide_data`、CONFIRMED_OFFICIAL)。ゲーム中に出店した店は、攻略本のライバル店の値(AM7〜PM11、人気20、サービス30)。値段は定価、駐車場なし、許可の要る品は許可があるときだけ。
- 組が品を取るのは、棚に n 個以上あるときだけ(足りないときの原作の動きは読んでいない)。
- 組み合わせ136(電気屋)の、表の外を指す1組は除いた。
- 値段の値:原作は品ごとの利益率の平均。この作品は店全体の値上げ・値下げ率が1つなので、100 + その率とした。

## 影響

- 駐車場はまだ建てられないので、車で来る客はどの店にも来ない(原作でも駐車場のない店には来ない)。駐車場はタスク#131で入れる。
- 新しい店は人気20なので、候補に入る確率が40%。来店数は、開店直後の1日で数十組。
- 4日間の売上は、変更前と同じくらいか多かった(確認用の計算で、2か月目 約21万円 対 約7万円)。

## テスト

- `headless_smoke.gd` の `_check_program_demand`:
  - 表のタグ、144行、組の上限。
  - 天気の値、休日、季節の品(1月の冷たい飲料は9割来ない)。
  - 値段の値・サービスの値の相対化、店選び(点数・距離の上限・在庫・駐車場)。
  - 7人の残りが5人と2人の組で来ること、平日は開始時刻の1時間だけであること。
  - 本番のゲームで、町の人数・今日の客・顧客独占率、1日の間の店内の組が10以下、組の人数が1〜5。
- 小型店の1日目の確認は、売れる品の種類の下限を8から5にした(目的の品で来るため)。
- pytest の `test_program_demand_follows_the_program`:データが道具の出力と一致すること、タグ、表の範囲。
