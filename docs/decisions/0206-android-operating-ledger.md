# 0206: 解析済みの営業台帳をAndroid本体へ移し、収支内訳を表示する

2026-11-05。ユーザーは、エミュレータ駆動ではないAndroid版の完成を優先し、検証の継続自体を目的にしない方針を明示した。根本方針をルート `AGENTS.md` に記録した。

## 基点と問題

最新main `688876a` だけでなく、未マージPR #270の更新版 `0c15eeb401441c00ab48a0af13da8bd70d2a1b78` を確認した。本変更はその更新版を土台にする。main、PR #270のブランチ、解析ブランチを直接変更しない。

最新版はすでに購入費を月末倍率から除いていた。しかし計算は依然として「現金差額＋資本支出」であり、たとえばコンテスト賞金や強盗の損失が営業損益へ混入する。売上グラフも、強盗後に取り消された帳簿上の売上を反映していなかった。

## 原作の根拠と移植

CONFIRMED_BINARY、SLPS_007.82（SHA-256 `d6a167a1c9e0fe98d7e44e12968caa489ac3eb7ed3b9e46012a188af8432b1fd`）。

- `8001CA7C`: 売上・仕入の計上と現金の増減。
- `8001CCC0`: 経費4列と売上1列から営業損益を計算。
- `800297A4..80029904`: 日次台帳の繰越。
- `80029918..80029D30`: 月間台帳の各列を8倍、現金には営業損益の追加7倍分を加える。
- 原資料と既存の照合コードは [解析ブランチのr2保管資料](https://github.com/s1-1985/Covenience-store-remake/tree/2c00ba53ed5d469b406d498f3d1f9191074679a0/ps1-analysis-checkpoints/archives/20261103-r2) に保持する。復元先 `algorithm-analysis/recovered.py` の `ledger_profit` / `month_close`、`verify_finance.py`、`finance_close.py` を参照。本ブランチには巨大アーカイブをコピーしない。

`OperatingStatement` は原作の集計式をGDScriptへ移植した独立した小さなクラスである。アプリ内にCPU実行器・BIOS・ディスクは不要。4つの小さな期待値を固定テストに置いた。

本体では全店舗の売上台帳と月初以降の仕入・人件費・維持費・宣伝費を使う。強盗で取り消された売上を含めない。その他の入出金はすでに支払われた一回限りの収支として扱い、追加7倍の対象にしない。月末は内訳、追加計上前後の所持金も記録する。

これは集計の移植であり、個々の経費の発生式をすべて原作と一致させたという意味ではない。原作の経費第3列の全用途は未分類で、宣伝費をそこへ対応させるのは本体の従来の扱いを維持したもの。最初の商品の配置・返品を資本的な入出金とする既存の推論も維持する。原作の32ビット整数オーバーフローは本クラスに再現していない。

## プレイヤーが使える変更

スマホ画面の「調査→全店収支グラフ」で、今月の売上・仕入・人件費・維持費・宣伝費・営業収支と、設備・出店・臨時収支を確認できる。最初の月末を待たず現在の内訳を先頭に出す。月末後は先月の経費内訳も表示する。配置はタッチ画面用の本アプリの設計であり、原画面の完全再現とは呼ばない。

保存形式は10のままで、従来どおり9も読み込む。既存の店舗売上・月初経費インデックスから新しい集計を計算できるため、状態の追加や過去の所持金の再計算はしない。旧版で確定した月末記録は書き換えない。新しい月末記録の内訳は通常のセーブに含まれる。
