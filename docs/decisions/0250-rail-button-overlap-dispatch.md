# 0250 — レールボタンの重なり配送の是正（CSRM-008）

## 背景
`ps1_menu_dispatch_smoke.gd` が「Cancel rail must remain clickable with a menu open」で失敗していた。原因は Muse の解析（docs/muse/analysis/2026-11-22-chain-tail-review.md §2）で特定済み: レールボタンは生成時に 128×64 を指定されるが、2行ラベルとテーマ由来の最小サイズ (36, 114) に下限クランプされ実効 128×114 になる。配置間隔は縦80pxのため隣接ボタンと約34px重なり、`touch_controls.gd` の `_input` 手動配送が「最初に一致した子ボタン」を選ぶため、重なり帯では上のボタンが発火していた（smoke のキャンセルタップ (1200, 422) は ○決定の範囲にも入る）。`handle_cancel` の履歴復元自体は正しいことを直接呼び出しで確認済みであり、変更対象ではない。最下段ボタン（y=620 + 114 = 734）は画面下端（720）をはみ出していた。

## 決定
指示書 CSRM-008 の選択肢から、(a) と (c) の部分的適用を採る。

1. 配送の一致規則: タッチ点を含むボタンのうち、中心が最も近いボタンを選ぶ。重なり帯以外では従来と選択が変わらない。重なり帯では、描画上の見た目（中心に近いボタン）と発火が一致する。
2. 最下段の SELECT / START ボタンの配置を y=620 から y=606 へ移し、実効高さ114でも画面内に収める（606 + 114 = 720）。上のボタンとの間隔も確保される。

選択肢 (b)（実効高さ自体を64pxへ是正する）は、テーマとラベル全体への影響範囲が広く、視覚変更を伴うため採らない。ボタンの見た目の大きさは現行のまま維持する。

## 影響
- 変わるのは重なり帯での発火ボタンだけであり、それ以外のタップの配送、`handle_cancel` / `handle_accept` の意味論、乱数消費には影響しない。
- 実機でも、各レールボタンの上端の帯が上のボタンの動作になる問題が解消される。
