# 0173: 客は周りの建物から来て、その建物のほしい品物を買う・アンケート(タスク#102)

## 背景

これまでの客は、店にある商品から1〜3種類をでたらめに選んで買っていた。店をどこに建てても、何を並べても、客の欲しい物は変わらなかった。
攻略本のDATA4には、建物ごとの「主なほしい品物」と「深夜にも客がいるか」が載っている。

## 根拠

| 内容 | 出典 | 段階 |
|---|---|---|
| 建物ごとの主なほしい品物 | 攻略本 DATA4(p.92-95) | CONFIRMED_OFFICIAL |
| 「朝から夜だけ客のいる建物」と「深夜から早朝にも客のいる建物」の区別 | DATA4 | CONFIRMED_OFFICIAL |
| 時間帯: 朝=7〜11時、昼=12〜15時、夕=16〜19時、夜=20〜23時、深夜=24〜3時、早朝=4〜6時 | DATA4 | CONFIRMED_OFFICIAL |
| 店の近くの建物の住人が買い物に来る | 攻略本 p.6 | CONFIRMED_OFFICIAL |
| 月ごとのアンケート(買った商品/欲しかった商品) | 攻略本 p.70 の画面写真 | CONFIRMED_OFFICIAL |

## 決定

- 町マップの建物カタログに、DATA4の`wanted`(ほしい品物)と`overnight`(深夜も客がいるか)を加えた。
- 実際のゲームで土地を買った後の客の決め方:
  1. 店の周囲16×16マスにある建物から1つ選ぶ。選ばれる確率は、その建物のマス数に比例する。ライバルと取り合うマスは、店の数で割って数える。REMAKE_BALANCED_DEFAULT。
  2. 0:00〜6:59は、「朝から夜だけ」の建物からは客が来ない。
  3. その建物のほしい品物から最大3種類を選ぶ。店に在庫がある種類は、その棚の商品を買いに行く。無い種類(許可が無い、置いていない、全部売り切れ)は、今月のアンケートの「欲しかった商品」に数える。REMAKE_BALANCED_DEFAULT。
  4. 1つも買える物が無い客は来店しない。
- 会計のたびに、買った商品をアンケートの「買った商品」に数える。月末に「先月」として残す。
- パネルの街の情報の下に「アンケート(先月/今月) 買った商品：… 欲しかった商品：…」を多い順に5つまで出す。
- 実際のゲームだけで有効にする(`staff_work.building_demand_enabled`)。試作店のテストでは、これまでどおりでたらめに選ぶ。
- アンケートはセーブしない。

1日動かした結果(本店(13,21)): 「欲しかった商品」はたばこ15、酒9、イベント商品9、中華まん7。許可を取る理由が画面で分かるようになった。

## テスト

- `headless_smoke.gd`: 店の周りの建物の重みがあること。2:00には「朝から夜だけ」の建物から客が来ないこと。客はその建物のほしい品物だけを買うこと。店に無い品物はアンケートに載ること。試作店では無効であること。
- `android_preview_smoke.gd`: アンケートが表示されること。
- 契約テスト: カタログの`wanted`/`overnight`がDATA4と一致すること、すべて商品カタログに存在すること、タグ。
- 結果: Python 763件成功(期待失敗1件は既存)。Godotスモーク・Android previewスモークとも成功。

## 明示的に対象外

- DATA4の時間帯ごとの客数の表(読み取りが不確か)。
- 平日/休日の違い。
- アンケートのセーブ。
