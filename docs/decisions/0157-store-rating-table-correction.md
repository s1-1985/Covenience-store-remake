# 0157: 店舗評価(★)の月末増減表を攻略本2箇所の再照合で訂正(タスク#86)

## 背景

`PROJECT_MEMORY.md`第21.4節には、店舗評価の増減表について「書籍頁38-39と書籍頁74-75の
ほぼ同じ表で、セキュリティ/清掃の値が少し異なる。コードは頁74-75を採用」という既知の
資料間矛盾が記録されていた。このセッションにはユーザーが添付した攻略本PDF4冊があり、
両方の表を直接高解像度で読み直せる状態だった。

## 調査結果

PyMuPDFで5倍レンダリングし、両表を1セルずつ読んだ(詳細な転記は
`docs/research/store-rating-table-reverification-2026-09-25.md`)。

- **2つの表は全セル完全に一致する。** 以前の「差異」は資料の矛盾ではなく転記ミスだった。
- 出荷済みのコード(`reference_sim/conveni_sim/store_rating.py`と
  `game/scripts/domain/store_rating.gd`)は、印刷された値と**11セル食い違っていた**。
- 両表とも☆☆☆☆☆(0つ星)の行を印刷しているが、以前の転記ではこれが欠落しており、
  コードは「0つ星の店は★1の行で判定する(より易しい6段目を発明しない)」としていた。
  実際には易しい6段目が原典に存在する。

## 決定

両ファイルの閾値を印刷された値に修正し、0つ星行を追加、★1行への流用処理を削除した。
いずれもCONFIRMED_OFFICIAL(同一表の独立した2印刷で一致)。

| 行 | 項目 | 旧 | 新 |
|---|---|---|---|
| 増加★4 | 清掃 | 95 | 100 |
| 増加★3 | サービス | 85 | 80 |
| 増加★3 | セキュリティ | 90 | 85 |
| 増加☆0 | (行) | なし | -1%/50/70/80/300万円 |
| 減少★5 | サービス | 100未満 | 80未満 |
| 減少★5 | 清掃 | 80未満 | 100(下記) |
| 減少★4 | セキュリティ | 65未満 | 70未満 |
| 減少★3 | セキュリティ | 60未満 | 65未満 |
| 減少★2 | サービス | 55未満 | 50未満 |
| 減少★1 | サービス | 30未満 | 40未満 |
| 減少★1 | セキュリティ | 50未満 | 55未満 |
| 減少★1 | 清掃 | 75未満 | 80未満 |
| 減少☆0 | (行) | なし | +1%/30/50/75/50万円 |

減少側★5行の清掃セルは両表とも「100」とだけ印刷され「未満」が無い。同じ列の他セルは
すべて「N未満」で、字義通り「清掃がちょうど100なら-1」と読むと満点を罰することになる
ため、「100未満」として扱った。印刷された数値100自体は変えておらず、推定しているのは
欠けた「未満」の1語のみ(同じ列からの類推、CLAUDE.mdの区分2)。

### ゲームへの影響

- 序盤(内部評価値0〜19、☆0つ)の店は、これまで★1の条件で判定されていたが、
  より易しい☆0行で判定されるようになる。
- ★3〜★5では一部の閾値が上下する(例: ★5で「サービス100未満なら-1」だったのが
  「80未満なら-1」に緩和され、代わりに「清掃100未満なら-1」になる)。

## テスト

- `reference_sim/tests/test_store_rating.py`: 旧値を前提にしていた2件を修正
  (★5減少行、0つ星の判定)し、印刷された全セルを固定する
  `test_thresholds_match_the_guides_printed_table_cell_for_cell`を追加。
- `reference_sim/tests/test_game_vertical_slice_contract.py`: GDScriptの表が
  Pythonの表と行単位で一致すること、★1流用処理が残っていないことを検証する
  テストを追加。
- `headless_smoke.gd`: 既存の評価テスト(内部値0)のメッセージを☆0行前提に更新し、
  0つ星の店が自身の行で判定されることの確認を追加。
- 結果: Python 749件(期待失敗1件は既存)、Godotスモーク、Androidプレビュー
  スモークすべて成功。
