## 2. このセッションで決まったこと・確認されたこと(次回も踏まえるべきルール)

### 2.1 恒久的な作業ルールとして機能している事項(今回変更なし、再確認のみ)

- **PR済みブランチの扱い**: 指定ブランチ(`claude/handover-review-ff1xv7`)のPRが
  マージ済みの場合、その上に新規コミットを積まず、`origin/main`から
  `git checkout -B claude/handover-review-ff1xv7 origin/main`でブランチを作り直して
  から作業する。このセッション中、PR #203マージ後に実際にこの手順を踏んだ。
- **数式の扱い**: 研究ノートが「具体的な数式は発明するな」と明記している場合でも、
  タスク自体が数値反映を要求するなら、**この実装が原作からの回収ではなく
  このプロジェクト独自のREMAKE_BALANCED_DEFAULT仮置きであることを、コード内コメント・
  JSON evidence_note・テストの3箇所全てに明示すれば実装してよい**(タスク#33で
  確立)。基準値は可能な限り「既存の確定データの中央値/最頻値」など、恣意的でない
  根拠を持たせる。
- **不要な抽象化を追加しない**: 「〜の概念をスキーマに追加する」という指示が
  あっても、既存の実装が既にその効果を持っているなら、新しいコードを書かず
  「既存設計で既に満たされている」と判断してよい(タスク#34で確立。
  `store_layout.gd`は什器の種類を問わず既にfootprint全体を無条件でブロックして
  いたため、`blocks_pedestrian`用の新メカニクスを追加しなかった)。

### 2.2 今回判明した「ドキュメント上のルール」と「実際の運用」の食い違い(要注意)

`docs/handoff/roles-and-workflow.md`の担当領域表は、`docs/decisions/`と
`PROJECT_MEMORY.md`を**Codex(旧ChatGPT)担当**、Claude Codeは原則書き込まないと
明記している。しかし実際には、タスク#21以降(Godotクライアント`game/`の実装作業)
一貫して、Claude Codeが`docs/decisions/`(決定書0088〜0103)と`PROJECT_MEMORY.md`
第19節へ**個別の許可を都度得ることなく**直接書き込み続けている。

これは**ドキュメント上のルールが更新されないまま、実際の運用だけが変わっている
状態**であり、今回のセッションもこの既存の実際の運用パターンをそのまま踏襲した
(意図的な新規許可を得たわけではない)。次回セッションでこの領域に書き込む際は、
この食い違いの存在を認識した上で、ユーザーに確認するか、単純に既存の実際の運用を
継続するかを判断すること。少なくとも`reference_sim/conveni_sim/`(本体コード)への
書き込みは、2026-09-16の引き継ぎ記録が明記する通り、依然として**その回だけの
明示的な依頼があるときに限る**という原則がある。

### 2.3 この環境の技術的な制約(新規判明)

- **YouTube等の動画コンテンツは視聴・解析できない**。`WebFetch`でYouTube動画ページを
  取得しても、JavaScriptで描画されるSPAのため`<title>`タグ程度しか得られず、
  概要欄・コメント・字幕は一切取得不可。今後もし「動画を見て確認して」という依頼が
  あれば、この制約を正直に伝え、人間が視聴した内容をテキストで教えてもらうか、
  文字起こし済みのテキスト資料を探す方向で対応すること。
- **Godot 4.3公式バイナリはこの環境でダウンロード・実行可能**
  (`/tmp/claude-0/godot-test/`、詳細手順は5節)。ただし`/tmp`配下はコンテナと
  紐付いており、**次回セッションには引き継がれない**。
