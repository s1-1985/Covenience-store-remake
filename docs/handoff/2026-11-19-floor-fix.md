# Android0.6.3：床材選択と汚れ・清掃の修正

ユーザー指摘：営業で床が汚れず、内装で汚れ画像まで床模様として選べていた。既存未解決6件は保留し、この通常動作の実装不整合を先に修正した。

## 原仕様と原因

既存のPS原データ解析（20261113-floor-cleaning-data）では、通常床材は0/5/10の3種類。各系統の+1..4は汚れの模様であり、汚れの程度を1段階ずつ上げる画像ではない。コード15は空白で、内蔵30配置にはない。今回、既知仕様を新しい解析結果として計上しない。

不具合は`_step_source_floor_wear()`から`ProgramOperations.wear()`へ、清掃能力指標ではなく前回の床のきれいな割合を渡していた点。きれいな割合100が保存されると、次回の`previous < percentage`は100<100となり、汚れ追加が止まる。原2287C→23D98→31498で渡すべき値は、配属店員の現在清掃能力から作る指標である。

## 変更

- 現在の配属店員の清掃能力と店舗規模の分母150/165/180から、上限100の清掃指標を毎回計算して汚れ処理へ渡す。前回割合は既存保存項目として残すが、発生判定には使わない。
- 毎正時、清掃指標がきれいな床の割合を下回る場合だけ、店内の対象客の足元1枚を、その床材に対応する汚れ模様へ変更する。同じ時計で二重処理しない。負座標の入店待ち客は対象にしない。
- 内装の床材選択を0/5/10の3種類へ制限。汚れ画像12種類と空白15を新しく選べなくする。旧16候補UIも修正。既存の壁・外装コードは塗り替えない。
- PS風の内装メニューへ「床材」を追加し、3種類のきれいな原タイルをタップで選べる。これはスマホ用の追加操作であり、この項目位置までPS版そのままという主張ではない。
- 既存の店員清掃処理を接続したまま使用する。汚れ床へ移動して清掃に成功すると、同じ床材の基準画像へ戻る。床材を別系統へ変える処理ではない。

指標100なら通常の汚れ追加条件は成立しない。店内に対象客がいない場合も増えない。汚れを見せるための独自確率や強制汚れは追加していない。APIから汚れ画像を床材として指定しても拒否する。

## 必要最小限の確認

`floor_lifecycle_smoke.gd`：3床材で3正時の汚れ追加、旧保存のfloor_previous=100を無視した正しい判定、同時刻重複防止、実際の原店員状態機械による清掃成功、指標100の抑止、負座標抑止、壁/外装保持、JSON保存復元後の汚れ継続を確認した。初回はJSON数値のint/float表現差を比較していたため、数値としての比較に直して完了させた。長時間営業の回数稼ぎはしていない。

`floor_ui_smoke.gd`：AndroidプレビューのPS風UIを開き、床材3候補だけがあること、タップで床材10を適用して内装へ戻ることを確認。ヘッドレスでの動作・ヒット領域の確認であり、Android実機画面の確認ではない。

Godot4.6.3でエクスポートし、SDK build-tools36のapksignerでv2/v3署名を確認。APKのpackage/version/minSDK24/targetSDK36/arm64、テストスクリプト除外も確認した。Android実機でのインストール・長期プレイは未実施。

## APKと更新時の扱い

APK名・サイズ・SHA256・保存先は[ビルド記録](2026-11-19-floor-fix.json)参照。既存0.6.2と同じ署名鍵を引き継げないため、新しいdebug署名と別package`com.conveniremake.floorfix`を使用した。アプリ表示名は「ザ・コンビニ 床修正版」。旧版をアンインストールせず試せる。別アプリなので旧版セーブの自動移行はない。修正自体は既存保存のfloor_previous値に依存せず、互換形式を読み込めば有効になる。

ビルド環境では旧0.6.2APKの同一Godotネイティブライブラリをテンプレートに再利用した。旧ゲームassetsと旧署名を除き、ゲーム資源を全て再エクスポート。ラベルのGodot用プレースホルダーも復元し、旧名が残らないようにした。再利用手順は`tools/reuse_android_template.py`。公開Godot4.6.3の`platform/android/export/export_plugin.cpp::_fix_resources()`に従う。完成APK内のエンジン.soは旧APKとバイト一致する。

SDK・APK・署名鍵・テンプレート・インポートキャッシュはGitへ含めない。コード・回帰確認・この記録をアプリの解析反映ブランチへ保存する。原EXE・BIOS・エミュレータを実行時に使う変更はない。
