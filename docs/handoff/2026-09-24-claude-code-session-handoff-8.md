## 1. 重要な方針転換(2026-09-21付、まだ知らない場合は必読)

`PROJECT_MEMORY.md`第1節が更新され、**本プロジェクトは所有者の個人利用限定**
であり、公開配布・不特定多数への共有は行わない方針になった。この決定を受け、
従来の「原作の著作物を一切参照せず新規作成する」という制約は、**本プロジェクト
自身の素材制作(disc image解析を含む)に限り緩和**されている。ただし、本プロ
ジェクトの成果物を土台に将来作る**別のオリジナルコンビニ経営ゲーム**では、
原作由来の資産・データを一切流用しない、という条件は変わらない。

この方針転換の経緯は本セッションの会話ログにある(ユーザーから明示的な
指示・理由の説明あり)。次セッションでこの方針を覆す・再確認する必要は
基本的にない。

## 2. アセット取り込みパイプラインの現状(`assets/raw/`)

このセッションでユーザーがChatGPTで生成した画像アセットを繰り返し受け取り、
`assets/raw/`配下にzipを展開して保管する作業を何度も行った。**まだ`game/`
(Godotクライアント)へは一切配線していない** — すべて「実装時に取り出す」
ための一時置き場。

現在(2026-09-24時点)の最新版:

| ディレクトリ | 内容 | 版数 |
|---|---|---|
| `conveni_map_assets_v2/` | 町マップの地形・建物タイル | v2(変更なし) |
| `conveni_fixtures_remake_v3/` | 店内什器(ワールド表示用) | v3(最新) |
| `conveni_products_remake_v3/` | 商品オーバーレイ(ワールド表示用) | v3(最新) |
| `staff_v2/` | 店員スプライト(ワールド表示用) | v2(変更なし) |
| `customer_v2/` | 客スプライト(ワールド表示用、21客層) | v2(変更なし) |
| `conveni_menu_fixtures_v1/` | 什器選択メニュー用アイコン(攻略本切り出し) | v1(新規追加) |
| `conveni_menu_products_v1/` | 商品選択メニュー用アイコン(攻略本切り出し) | v1(新規追加) |
| `conveni_menu_staff_v1/` | 店員選択メニュー用顔アイコン(攻略本切り出し) | v1(新規追加) |
| `conveni_additional_assets_v1/` | 店舗選択・広告アイコン、入口/地面/枠パーツ等 | v1(新規追加) |
| `conveni_remaining_assets_v1/` | 上記への追加分(誘致メニュー・広告状態・火災アニメ等) | v1(新規追加) |

**世代交代の経緯**(次に差し替えが来たときの参考):商品/什器/店員/客の
ワールド表示用パッケージは当初v1で渡され(白フチアーティファクトの不具合)
→v2(白フチ除去)に差し替え→什器・商品のみさらにv3(ブリーフに基づく
作り直し)に差し替え、という順で進んだ。店員・客はv2のまま最新。

**メニューUI系5パッケージ(`conveni_menu_*`, `conveni_additional_assets_v1`,
`conveni_remaining_assets_v1`)は既存のワールド表示用パッケージを置き換える
ものではない** — 各パッケージ自身のREADMEに「メニュー表示専用、店内・
町マップのスプライトを置き換えないでください」「既存セットは上書きしない」
と明記されており、この指示に従って両方を残した。実装時には**同じ対象
(例:什器)について、ワールド表示用とメニューアイコン用の2つの画像を
紐付けて使う**ことになる(この対応付けの設計自体はまだ決めていない、
下記5節参照)。

## 3. ChatGPT発注用ブリーフ(次に新しい素材を発注するとき使う)

ユーザーがChatGPTに新しいアセットを作り直させる/追加させるたびに、
発注内容をMDファイルにまとめて渡す運用を確立した。既存の2本:

- `docs/assets/chatgpt-building-sprite-brief-2026-09-22.md`(建物52種)
- `docs/assets/chatgpt-fixtures-products-brief-2026-09-23.md`(什器44種+
  商品25種、透過要件の再発注防止項目つき)

まだ客・店員・町タイル用の同種ブリーフは作っていない(会話内で直接リスト
だけ渡した回のみ)。今後、客・店員・タイルを作り直す話が出たら、この2本
と同じ形式(共通スタイル指定+ピクセル換算ルール+対象一覧の表+発注
ワークフロー)でMDを作ること。
