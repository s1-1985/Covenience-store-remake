# v0.6.1 — 店員のレジ対応遅延

基準本体: `e365e3085bdaff10bab9fd5eb227d15e36a9538e` (`chatgpt/android-touch-build-20261118`)。
ユーザー提供動画 `1000281717.mp4` (42.94秒、×8、2〜3日目) では、客のレジ待ちと控え室にいる店員、混雑通知が続く。初日の時計バグだけで動画全体を説明したとは扱わない。

## 変更

- **CONFIRMED_IMPLEMENTATION**: `day_count` は0始まりなのに人物時計が1日を引いていた。初日が負数になり、接客能力による `%100` の仕事選択条件が成立しない。人物・滞在期限・床処理の基準を0始まりに統一。
- **REMAKE_BALANCED_DEFAULT**: 客が実際の会計位置に到着し、レジに向かう担当も不在の場合、接客の時刻条件を待たずに担当を付ける。補充・清掃中の店員も会計を優先。これは原作忠実な判定の修復とは別の、待ち時間を改善するスマホ版の方針である。
- 控え室から出る前の全回復、体力消費、レジ台数制限、会計成功率・接客能力は維持。全員の回復待ち、移動、通路の衝突、低能力で会計そのものが遅い場合まで即時完了にはしない。
- 旧時計のセーブ内期限・床処理時刻を1回だけ+1440補正 (`source_runtime.clock_epoch=1`)。JSON読込時の買物かごの個数・価格を整数へ復元し、途中セーブの人物処理を再現可能にする。
