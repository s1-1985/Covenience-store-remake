# Codexチャット・PR・マージ運用

Last updated: 2026-09-07

## 結論

- 一往復ごとにチャットやPRを切り替えない。
- 一つの目的を持つ作業を、同じCodexチャットと同じ作業ブランチで完成させる。
- 実装、修正、テスト、レビュー対応は、PRがマージされるまで同じチャットで続けてよい。
- マージ前にユーザーが「マージ前チェック」と明示し、Codexは最新 `main` との同期、競合解消、全テスト、最終コミット、PR準備を行う。
- PRをマージした後の独立した作業は、最新 `main` を基点に**新しいCodexチャット**で始める。

## 標準フロー

### 1. 作業開始

新しいチャットを最新 `main` から開始する。Codexは変更前に次を確認する。

1. リポジトリ内外の `AGENTS.md`。
2. `PROJECT_MEMORY.md` と関連するresearch/decision/handoff文書。
3. Gitの現在ブランチ、ワークツリー、直近履歴、remote。
4. 利用できる場合は最新 `main` とopen PR。既存作業と重複する場合は編集を始めない。

### 2. 作業中

一つの機能または一つの目的をPR単位とする。同じ目的に対する追加修正、テスト追加、CI修正、レビュー対応ではチャットを切り替えない。

一往復ごとの小さなPRは避ける一方、顧客、スタッフ、街、経済、UIを一度に全面変更する巨大PRにもまとめない。

### 3. マージ前チェック

ユーザーは、まとまった時点で次のように依頼する。

> ここまでをマージしたい。最新mainと同期し、競合解消、全テスト、最終コミット、PR準備まで行って。マージはしないで。

Codexは、環境で可能な範囲で次を行う。

1. 最新 `main` を取得する。
2. rebaseまたはmerge前に、作業差分と重複PRを確認する。
3. 競合を内容に基づいて解消し、競合マーカーが残っていないことを確認する。
4. 関連テストと全回帰テストを実行する。
5. 見た目を変更した場合は実行画面を確認し、可能ならスクリーンショットを残す。
6. 最終コミットを作成する。
7. GitHub連携と権限が利用できる場合はPRを作成し、CIを確認してマージ直前で止める。
8. PR作成ツール、remote、認証がない場合は、その制約とユーザーに必要な操作を明示する。

### 4. PR作成後

CI失敗やレビュー修正は同じチャット・同じPRで対応する。新しい無関係な機能を同じPRへ追加しない。

### 5. マージ後

マージ後の作業を古いチャット／ブランチへ積み増さない。特にsquash mergeでは、内容が同じでも作業ブランチと `main` のコミットSHAが異なる。古いブランチを継続すると、次のPRで同じ変更が再登場し競合しやすい。

次の作業は、マージ済みの最新 `main` から新しいチャットを開始する。履歴を継続する必要がある場合も、最初に最新 `main` へ同期してから編集する。

## 競合時の原則

- 競合画面で機械的に `Accept both changes` を選ばない。
- current/incomingの名前だけで判断せず、最新 `main` の意図と今回の差分を比較する。
- 古い説明を新しい説明が包含している場合は新しい説明だけを残し、重複段落を作らない。
- 実行コードでは、両側の処理を単純連結せず、呼び出し関係、状態遷移、テストを確認する。
- 解消後は `<<<<<<<`、`=======`、`>>>>>>>` が残っていないことを検索する。

## 初代再現の優先順位

Git運用にかかわらず、実装は初代PS/SS版『ザ・コンビニ ～あの町を独占せよ～』の再現を優先する。

1. 動画・説明書・実画面から直接読める事実と、原因・数式の推測を分ける。
2. 未回収の来客、購買、スタッフAI、時間、経済式を原作仕様として発明しない。
3. 動作確認に必要な仮値・仮操作は `PROVISIONAL` とし、原作互換ルールから分離する。
4. 原作にない現代化・独自機能は、初代ベースラインが十分に検証されるまで優先しない。
5. 動画から得た事実は `docs/research/`、意図的な互換性判断は `docs/decisions/`、実行可能な再現はテストへ残す。

## 動画解析の受け渡し

動画本体は原則として公開リポジトリへコミットしない。解析時はプラットフォーム、動画内時刻、ゲーム内時刻、見えた事実、推測、確度を分けて記録する。

「スタッフが休憩室へ戻った」は観測事実になり得るが、「スタミナが特定の閾値を下回ったため」は追加証拠がなければ仮説として扱う。複数の観測を比較してから、参照シミュレーターの再生入力またはGodotのルールへ昇格する。
