## 1. 実装の UI は2層ある

- `ps1_ui.gd`: 原作風の階層メニューを自前で描く層（320×240、所有者の実機スクリーンショット26枚に基づく CONFIRMED_VISUAL と冒頭に明記）。タッチレール（touch_controls.gd）で操作する。現在の表向きの顔。
- `phone_ui.gd`: 先行するスマホUI層（右側コマンド列＋オーバーレイウィンドウ）。ps1_ui.gd はこれを継承し、phone 側のメニューと HUD を隠して上から描く。ただし phone 側のウィンドウ部品が現行 APK でどこまで到達可能なのかは、本照合の読み取りだけでは断定できない（§4）。

## 3. 意図的な逸脱（欠陥ではない、記録済みのもの）

原作に無い要素を実装が足している箇所は、いずれも文書化されタグ付けされていた。

- **速度変更 ×1／×4／×8／×16**: 原作に速度操作は無い。decision0215 で所有者要望により実装され、phone_ui.gd 冒頭で REMAKE_BALANCED_DEFAULT と明記。引継ぎ 2026-11-19-mobile-controls に経緯あり。
- **タッチレールの追加割当**: SELECT=システム（原作では未使用）、△=表示切替、L2/R2=前後の店、×1=速度。touch_controls.gd 冒頭に「Mobile presentation only… REMAKE_BALANCED_DEFAULT」と明記。
- これらは原作再現との差異として認識済みの設計判断であり、本照合では是正対象にしない。

## 4. phone_ui 層の不整合（到達可能性が前提）

phone_ui 層単体で見ると、原作との不整合がある。

- トップレベルに 店舗 と 不動産 が無い（表示中店舗にスコープした 内装／店員／営業方針／販促／調査／システム のみ）。
- 店舗売却の入口が phone 層に無い（売却は内装の什器売却のみ）。新規出店は「販促」ウィンドウ内の「新しい店を出す」に置かれている。
- 調査の画面ラベルが 店舗成績（説明書: 店舗別詳細）で、店舗別グラフに相当する独立画面が無く、代わりに原作に無い「町と目標」が入っている。

ただし ps1_ui 層は phone 側メニューを隠して描くため、これらが現行 APK の利用者から到達可能かどうかは、コードの読み取りだけでは確定できない。到達不能（完全に ps1 層の下にある）なら実害は無く、到達可能な経路が残っているなら §2 の整合に対して実ギャップになる。**この判定を CSRM-005 の最初の作業として実装側に求める。**

## 5. 指示書化

- CSRM-005 を発行した。内容は2点のみ。(a) ps1_ui の調査ラベル「店舗別グラフ」を説明書の「店舗別収支グラフ」へ寄せる（画面上の制約で短縮が必須なら、その理由を決定記録に残す）。(b) phone_ui 層の到達可能性を確認し、到達可能なら §4 の不整合（不動産・店舗売却の入口、調査ラベル）を解消し、到達不能ならその確認結果を実装報告に記録して閉じる。
- UI のデザイン・レイアウト変更は指示しない。対象は事実（コマンドの有無とラベル）の整合のみ。

## 6. 分類のまとめ

- 整合: ps1_ui 層のコマンド体系ほぼ全体（トップレベル、調査・販促・不動産・システムの子項目、店舗パネル、ポーズ構造、□で開く操作）。
- 未反映（軽微）: 調査ラベル1件の表記差（店舗別グラフ vs 店舗別収支グラフ）。
- 検証不足: phone_ui 層の現行 APK での到達可能性と、到達可能な場合の §4 の不整合。
- 意図的な逸脱（記録済み・対象外）: 速度変更、SELECT 等への機能付与、その他タッチレール割当。
