- 日付: 2026-11-22
- 対象: ChatGPT チェーンのうち比較レビュー（2026-11-22-dual-implementation-review.md）の対象外だった後段3件（decision0244 音声フラグ持越し / decision0245 月末32bit会計 / decision0246 日次費用）と、全未マージ PR のマージ順序。
- 基準: チェーン先端 `54a76589ba`（0.8.13）。検証は同コミットのツリーを Muse がローカル取得して実施した。

## 1. 後段3件のレビュー結果

3件とも問題なし。マージを妨げる点は見つからなかった。

- 共通: いずれも新規の原解析ではなく、保管済み復元モデル（ps1-analysis-checkpoints、コミットと SHA256 で fixture を固定）への未反映分の接続である。新しい仮数値の導入はない。範囲外（全生成元・全通知・原カード形式・既存未解決6件 U-1〜U-6）は各 decision に明記され、全体 headless の source_catalog SCRIPT ERROR を「全体合格とはしない」と正直に引き継いでいた（この残件は CSRM-007 で解消済み）。
- 0244（PR #274）: SE OFF 中の音声フラグを店舗別に保持し、選択店舗かつ SE 有効時にだけ消費する。旧保存への配慮（項目がなければ0、過去ログからの推測再生なし）と、Android 独自ミュートを原仕様と同一視しない線引きが明記されている。Muse のスポットチェック: `source_audio_flags` が保存対象フィールドに含まれていることを実装で確認した。
- 0245（PR #275）: 月末会計の signed32 化と、店舗評価へ渡す売上を「8倍前」に是正（復元モデルの注記が根拠）。Python 契約テスト1件の文字列期待を根拠付きで訂正している点も decision に開示されている。
- 0246（PR #276）: 日次費用の途中積 signed32、符号反転した費用を破棄せず計上、kind53 以上を維持費表参照前に除外。Muse のスポットチェック: program_operating_costs.gd の signed32 計算と kind<53 判定が decision の記述と一致することを確認した。
- 各 decision が、検証過程で見つけたテスト側の誤り（存在しない rival ID、JSON の float 型比較、極端値の取り違え）を隠さず記録している。いずれもテスト入力の訂正であり、本体ロジックの期待値を緩めたものではない。
- テスト状態: 先端ツリーで Python 793件全成功を Muse も再確認した（CSRM-007 実施時）。APK は各版（0.8.11/0.8.12/0.8.13）とも従来署名で出力され、実機未確認である旨が明記されている。

## 2. ps1_menu_dispatch_smoke の失敗（CSRM-005 時に見つけた既存失敗）の原因特定

チェーン先端でも再現する。原因はテスト側と実装側の双方にあり、CSRM-008 として切り出した。要点:

- `handle_cancel` の履歴復元ロジック自体は正しい（直接呼び出しで realestate → root へ戻ることを実測）。
- レールボタンの実効サイズが 128×114 になっている（生成時に指定した 128×64 が、2行ラベルとテーマ由来の最小サイズ (36, 114) で下限クランプされる）。配置間隔は縦80pxのため、隣接ボタンと約34px重なる。
- touch_controls の手動タッチ配送は「最初に一致した子ボタン」を選ぶため、重なり帯では上のボタンが勝つ。smoke のキャンセルタップ (1200, 422) は ○決定ボタン（y 310〜424）の範囲にも入っており、×ではなく○が発火してメニューが閉じていた。×の中央 (1200, 460) のタップは正しく動作する。
- 実機でも、各レールボタンの上端約34pxは上のボタンの動作になる（軽微な実欠陥）。最下段ボタン（y 620 + 114 = 734）は 720 の画面下端を14pxはみ出す。
- この smoke は CI に入っていないため、失敗が長期間気づかれなかった。

## 3. マージ順序の提案

現在の未マージ PR（全て open）: ChatGPT チェーン #272→#273→#274→#275→#276（各々が前段ブランチを base とする積み重ね）、Muse 側 #279（CSRM-006、ただし配下に破棄済みの自作 CSRM-004/003 コミットを含む）、#280（CSRM-005、同様に配下を含む）、#281（CSRM-007、チェーン先端から分岐）。

推奨順序:

1. ChatGPT チェーンを #272 → #273 → #274 → #275 → #276 の順にマージする（採用済みの CSRM-001〜004 と LEGACY-0244〜0246 が候補ブランチへ入る）。
2. 次に #281（CSRM-007）をマージする。チェーンが入った後は、この PR の差分は CSRM-007 のコミットだけになる。
3. #279 / #280 はこのままマージしない。配下に破棄済みの Muse 自作 CSRM-003/004 が含まれ、チェーン側の採用版と競合する。チェーンのマージ後、CSRM-006 と CSRM-005 のコミットだけをマージ済みのラインへ積み直し（対象ファイルはチェーンと重ならないことを確認済み）、#279/#280 は積み直し版に置き換えて閉じる。この積み直しは Muse が行う。
4. 候補ブランチから main への取り込みと、無関係の旧 PR #270 は、別途の判断とする。
