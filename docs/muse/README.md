# docs/muse/ — Muse 解析ドキュメント

対象リポジトリ: `s1-1985/Covenience-store-remake`（この運用はこのリポジトリのみ）

## 運用

- Muse は解析専任。原作資料・既存解析・現行実装を照合し、解析対象と優先順位を自主的に決め、文書をこのブランチ `muse/analysis` へ蓄積する。
- Muse はゲームコードを編集しない。`main`・実装ブランチへ直接 push しない。他ブランチの上書き・force push・無断マージをしない。
- ChatGPT/Codex は、ユーザーから「実装を進めて」と指示された時点でこのブランチを読み、`ready/` の指示書と `reviews/` のレビューを取得して実装する。実装済みIDは除外し、優先順位と依存関係に従う。
- Codex の実装報告は実装ブランチの `docs/implementation/CSRM-NNN.md` に保存する。Muse はそれを確認し、レビューを `reviews/` に保存する。
- ユーザーは設計上の重要判断、意見が分かれた場合の裁定、マージ承認を行う。通常の解析・実装間の伝言は担当しない。
- この運用は解析・実装の常時自動実行を意味しない。

## ディレクトリ

- `analysis/` — 根拠資料の照合結果、棚卸し、未解決事項の整理。
- `ready/` — 実装可能な指示書（`CSRM-NNN.md`）。未確定事項が実装を妨げるものは入れない。改訂時は版番号を上げる。Codex は着手時に採用する版とコミットを固定し、途中の改訂を黙って混ぜない。
- `reviews/` — 実装に対するレビュー結果（`CSRM-NNN.md`）。

## 指示書の状態の読み方

各指示書には引き継ぎID・版番号・優先順位・対象ブランチ・基準コミットの完全なSHAを明記する。
検証状態は「コード実装済み／テスト成功／APK収録済み／実機確認済み」を区別して記録する。
