# CSRM-008: レールボタンの重なり配送の是正（ps1_menu_dispatch_smoke の失敗解消）

- ID: CSRM-008
- 版: 1
- 優先度: 7
- リポジトリ: Covenience-store-remake
- 対象ブランチ: 採用ライン（ChatGPT チェーン）の先端から分岐すること。シート作成時点の先端は `chatgpt/legacy-daily-costs-20261121`（`54a76589ba`）。チェーンがマージされた後は、そのマージ済みラインを基準とする
- 実施者についての注記: ユーザーの 2026-11-22 の役割変更により、実施は Muse でも ChatGPT でもよい。マージはユーザーの承認が必要。

## 目的

`ps1_menu_dispatch_smoke.gd` が「Cancel rail must remain clickable with a menu open」で失敗する既存不具合を解消する。原因は解析済み（docs/muse/analysis/2026-11-22-chain-tail-review.md §2）:

- レールボタンは生成時に 128×64 を指定されるが、2行ラベルとテーマ由来の最小サイズ (36, 114) に下限クランプされ、実効 128×114 になる（Godot 4.3 ローカルで実測。viewport は 1280×720 で変換なし）。
- 配置間隔は縦80px（y=110/190/310/390/490/620）で、隣接ボタンと約34px重なる。最下段は 620+114=734 で画面下端（720）をはみ出す。
- `touch_controls.gd` の `_input` 手動配送は、タッチ点を含む最初の子ボタンを選ぶため、重なり帯では上のボタンが発火する。smoke のキャンセルタップ (1200, 422) は ○決定（y 310〜424）の範囲にも入り、×戻るではなく○が実行されてメニューが閉じる。
- `handle_cancel` 自体の履歴復元は正しい（直接呼び出しと、×中央 (1200, 460) のタップで実測済み）。ここは変更しない。

## 変更内容

次のいずれか（または併用）で、重なり帯でも視覚上のボタンと発火するボタンが一致するようにする。選択した方法と理由を decision に記録すること。

- (a) 配送の一致規則を直す: 重なる場合は最後に一致した（最前面の）ボタン、または中心が最も近いボタンを選ぶ。
- (b) ボタンの実効高さを配置どおり 64px に収める: ラベルの行数・フォント・テーマのスタイルボックス余白など、最小高さ 114 の発生源を是正する。
- (c) 配置間隔を実効高さ以上に広げる（最下段が 720 に収まることも条件）。

併せて、最下段ボタンが画面内に収まることを確認する。
