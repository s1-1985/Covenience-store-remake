## 赤字継続と撤退

対象のライバル店に毎月同じ赤字帳簿を与えた6回の呼出しでは、
赤字回数1→2→3→4→5の間は残り、6回目で撤退した。
RAMと乱数は呼出し間で引き継いだ。時計全体の月送りや会計締めまで再現した連続プレイではない。

赤字→赤字→黒字→赤字の4回では、回数は1→2→0→1になった。
最後のライバルが撤退した場合、相手会社の資金は0にされた。

創業店（通番1）は相手が2店以上あると通常撤退の対象から保護される条件がある。
一方、自社9店・1月の制御状態では、創業店が黒字でも撤退した。
2月、または相手通番2の同条件ではこの強制撤退が起きなかった。
同時に撤退条件を満たす相手店を2店置いた試験では、走査順の先の1店だけを処理して戻った。

この金額はこの入力で選ばれた配置・土地・商品に対する値であり、全出店に共通する定額ではない。

元の土地を変更しないseed=0の試験は適地なしとなった。
資金が十分でも、土地条件やスタッフ・店舗枠の不足で出店できないことを個別に通した。

## 失敗時の候補データ

出店に失敗しても、候補となる非稼働店スロットの初期化やレイアウト設定が先に行われ、
その内容がRAMに残る経路がある。資金不足例でも非稼働スロットの内容は変化した。
これを「店が営業を始めた」と解釈してはいけない。
V0の残値が同じでも、成功・失敗の分岐が異なる例があるため、関数の戻りレジスタだけを成功APIとして使わない。
