配置IDは `tier×5＋ヘッダー値＋2`。原TOWNのヘッダー0/1/2は、既存30配置のうち各段階の変種2/3/4を選ぶ。店舗段階は別の符号付き制御値+0xCD994から選択幅2/4/6を得る。初期読込みではこの制御値が全稼働店数で初期化されるため、TOWN0001/0003は段階0～1、TOWN0002/TOWNPSは段階0～3が候補になる。

ライバルの土地条件は**2×2区画左上の地価係数が8以上**、かつ4セルの制限ビットに問題がないこと。4つとも地価8以上という条件ではない。原初期4マップは全3,000セルが係数5なので、いずれも適地0である。

[72組の配置/マップ接続](map-layout-siting-links.json)は、制限ビットだけを満たす件数と地価条件を満たす件数を分けて保存した。地価を人工的に上げた仮の出店を、今回の解析成果として実行してはいない。原の月次順序はライバル判定が自然発展より前なので、その月の自然発展で新しくできた適地は後の判定で利用される。

## 撤退は出店より先

月初の午前0時に、原の店舗順でライバルの前月損益を確認する。赤字で連続回数を増やし、利益0以上では0へ戻す。回数はu16として更新し、撤退判定では符号付き16bitで6以上かを読む。

通番1の創業店はライバル2店舗以上なら通常の赤字撤退から保護される。一方、**自社9店舗・1月・相手通番1**では赤字でなくても撤退する。1回の呼出しで撤退するのは原の走査順で最初に該当する1店で、処理後は出店判定に進まず戻る。

撤退時には土地と建物・設備・残存在庫を評価し、負の資本支出として返金する。最後のライバル撤退では返金後でも相手会社の資金を0にする。初期11店について条件付きの返金額を[initial-withdrawal-values.json](initial-withdrawal-values.json)に保存した。例えばTOWN0001の初期店は各23,360,745である。ただし初期の前月損益は0なので、これらが初期状態で撤退するという記録ではない。

## 採用・初期営業時間・商品設定

出店の抽選は撤退候補がなく、相手会社に店舗が残る場合だけ行う。`RNG&3==0`を通っても、店舗枠・人員・土地・資金が必要であり、「毎月25%で必ず出店」ではない。

採用人数は `RNG%3+1`。各人について35人中の開始位置を抽選し、そこから循環走査して所有ワード0の人を選ぶ。既に選んだ人は除外する。空き人員からの一様抽選へ変更すると、原の偏りと乱数列が変わる。TOWNPSの所有FFFFの人物も空き人員には含めない。[140個の開始位置と最初の採用先](staff-first-free-links.json)を保存した。

営業時間は `RNG%6`で0～5を選ぶ。元の0番「24時間」は含み、6番「臨時休業」を含まない。27商品の価格設定値は原マスターで初期化し、各商品に対する抽選 `RNG&15==0`を通ったときだけ0/5/10/15/20/25/30の値引候補を追加抽選する。候補が現在値より小さい場合だけ引く。[27商品の設定表](rival-price-initialization.json)を参照。

人員や資金が不足した失敗経路でも、非稼働の候補枠には初期化・内装・人員参照が残る場合がある。候補データを営業店として扱わず、成功時の稼働化と区別する。この月次関数には既存店の改装操作を確認していないが、ゲーム全体の別処理まで否定するものではない。
