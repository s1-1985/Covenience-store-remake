## 固定の内訳になる例

- **小学校**：客構成は20・21に分かれるが、両構成の第一商品別人数が同じため、建物全体の112人分は文房具を第一候補とする64人分と、菓子類48人分になる。この施設が供給する購買型の到着モードは全て1で、モード3ではない。
- **水族館**：同じく5枠が同じ。63人分の第一候補は冷たい飲料36人分・菓子類27人分であり、到着モード3は45人分を占める。商品別と移動区分別は同じ母集団を別々に集計した内訳なので、互いに足さない。
- **体育館**：合計30人分という人口は固定でも、5枠は複数の客構成へ分かれている。従って「人口範囲が同じなら商品内訳も固定」とは言えない。

いずれも地図の客構成上の人数で、1日あたりの実来店人数ではない。第一商品に人数を割り当てたからといって、その商品を必ず買い、追加商品を必ず全て買うことにもならない。

## 駐車条件と商品構成を分ける

モード3は原店舗選択で駐車容量が正であることを要求し、客生成にも駐車不足の分岐がある。この規則自体は既知の[駐車・到着解析](../20261114-parking-arrival-data/README.md)を再利用した。

施設人口を一括で「近くの店の需要」に加えると、商品候補や駐車条件を飛ばしてしまう。Androidでは完成時に各セルの客構成を保存し、その購買型を通常の天候・季節・時刻・店舗選択・駐車条件へ渡す。今回の平均表を常時固定需要として代入しない。

## 誘致マスター未命名項目の追跡

今回確認した原開始処理の保存バイト列は、18行×20バイトの先頭+0を建物IDとして読み、+12を基本費用の作業欄として0初期化・積算し、選択後に現金から一時的に引く。原0x8006A624、0x8006A638、0x8006A738、0x8006AE84が対応する。

この構造は既存の費用解析と一致するが、+2/+4/+6/+8/+16の意味を新たに確定する根拠にはならない。保存範囲外や間接参照まで含めた未使用の証明もしていない。R04は未解決を維持し、+8を工期や費用へ流用しない。
