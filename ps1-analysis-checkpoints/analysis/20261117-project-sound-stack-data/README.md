# 誘致完成音：未初期化比較値のスタック由来

2026-11-17 JST。R05の音29/34の選択について、完成処理0x80029020の呼出し元と前段の関数フレームを解析した。**比較値を置く場所が、前段の店舗高さや年次評価の集計欄と重なることを特定した。実際の最終値はなお未確定で、R05は未解決を維持する。**

既知だったのは、完成関数内で初期化されない32ビット値を、誘致レコード+30の符号付き16ビット値と比較すること。今回増えたのは、そのメモリ位置を呼出し元のスタックへ戻した対応である。原CPUの営業更新は0回。

## 原呼出し順

原コード0x80010000～0x80097FFF内の直接JALで、完成関数を呼ぶ位置は0x80023498の1箇所だった。この一覧は関数ポインター経由を含めた全域証明ではない。

| 順序 | 呼出し元位置 | 呼出し先 |
|---:|---|---|
| 1 | 0x8002346C | 店舗集計0x80023C20 |
| 2 | 0x80023474 | イベント処理0x8003EF44 |
| 3 | 0x80023480 | イベント処理の戻り値が1なら更新末尾へ移る |
| 4 | 0x80023490 | 前段の営業処理0x800275F8 |
| 5 | 0x80023498 | 誘致完成0x80029020 |

各関数が戻るとスタック位置は呼出し前へ戻る。各ローカル変数の名前が違っても、同じ物理的なメモリ位置を再利用する。

## 四つの関数で同じ場所になる

呼出し元のスタック位置をSとする。

| 関数 | 確保するバイト数 | ローカル位置 | Sからの相対位置 | この場所の用途 |
|---|---:|---:|---:|---|
| 完成0x80029020 | 64 | +28（0x1C） | −36 | 未初期化の比較値 |
| 店舗集計0x80023C20 | 104 | +68（0x44） | −36 | 活動店の店内高さ |
| イベント0x8003EF44 | 88 | +52（0x34） | −36 | 年次評価の集計欄 |
| 前段0x800275F8 | 96 | +60（0x3C） | −36 | 同じ場所。関数本体に直接FP相対の書込みなし |

したがって、この比較値を施設固有の属性・工期・費用と決めつける根拠はない。**同じアドレスと判明したことと、毎回どの値が最後に残るかを証明したことは別**である。[全対応](stack-aliases.json)に条件を保存した。

店舗集計は物理店スロット0～9を走査し、活動店で原0x80023F30が店+0x48の高さをローカル+0x44へ保存する。そのため、この関数内の当該欄への最後の直接書込みは、最後の活動店の高さになる。

イベント処理の該当年次評価分岐は、原0x8003F80Cで+0x34を0にし、0x8003F930で店舗+D0Cの値を積算する。正値同士の加算による符号反転を検知した場合は0x8003F910で0x7FFFFFFFへする。この分岐が毎回通るとは主張しない。

前段0x800275F8には、関数本体の直接FP相対ストアとして+0x3Cへの書込みが見つからない。ただし、間接書込み・呼出し先の影響・完成処理内の後続呼出しまで含めた値の生存は未確定なので、「直前の高さが必ず完成時まで残る」とは結論しない。

## 音の分岐は厳密な未満比較

原0x800292B4で未初期化ローカルを読み、0x800292BCの符号付き比較を使う。

| ローカル値 | レコード+30 | 音コード |
|---:|---:|---:|
| 20 | −1 | 29 |
| 20 | 0 | 29 |
| 20 | 20 | 29 |
| 20 | 21 | 34 |

比較は「以下」ではない。**高さ20が比較まで残り、かつレコード+30が0なら29**という条件付きの結論は得られる。一方、レコード+30は既存の開始処理では初期化が確認されていない。入力の生存とレコード値をまだ固定できないため、一律29・一律34や施設別の音表は作らない。[分岐仕様](sound-branch.json)に記録した。
