# 通常画面上部の原文字列・文字画像・背景の対応

2026-11-17 JST。［確実］通常HUDの原文字列11件、必要な文字画像31個、背景1領域と配置2件を接続した。原CPU実行・営業更新は0回。今回は解析データの追加で、APKは未更新である。

HUDの位置、日時計算、数値展開、文字描画式と天候選択表は既存の回収結果である。今回の追加は、それらを原MSG・PSMOJI・KYOUの実バイトと画素へ対応させた、Android向けの表示入力仕様である。新しい営業アルゴリズムの解明件数には数えない。

| 表示 | 原メッセージ | 画面上の開始位置 | 内容 |
|---|---:|---|---|
| 日付 | 60 | (8, 6) | 2桁の年＋「年目」＋2桁の月＋「月」＋2桁の区分日＋「日」 |
| 天候 | 62～70から月・天候値で選択 | (108, 6) | 快晴・晴れ・曇・雪・大雪・雨・大雨・雷雨・台風 |
| 時刻と所持金 | 61 | (152, 6) | HH:MMに続けて可変桁の金額 |

所持金は独立した固定位置の文字列ではない。原メッセージ61には時刻の直後に数値展開命令`0x4004,0`がある。金額は通貨記号、3桁ごとの区切り、負値用の原文字を使う。原文字のUnicode転写では負号用画像は「ー」、通貨画像は「¥」と対応するが、見た目の再現には[原文字画像の対応](hud-font-crops.json)を使う。

日時には`0x4009`の2桁展開を使う。原の区分日は1～4であり、通常の28～31日制カレンダーで置き換えない。2桁展開では100以上の上位桁が残らない。これらは既知の展開・カレンダー処理を表示入力へ反映したもので、今回100年目の自然プレイを観測した結果ではない。

背景は`KYOU.TIM`の(96,184)から160×24画素を切り出し、画面(0,0)と(160,0)へ同じ画像を置く。原描画レコード座標では(-160,-112)と(0,-112)である。必要な行は184～207で、原画像の高さ240行に収まる。アップロード要求の256行に合わせて原画像を水増しする必要はない。TIM内のCLUT位置と実ロード先は異なるため、描画時のCLUT(0,492)を使う。

[背景の原画素プレビュー](hud-background-source-preview.png)と[文字の原画素プレビュー](hud-glyph-source-preview.png)を保存した。合成したゲーム画面やPSのGPU描画結果ではない。文字画像は固定12×15レコード経路を対象とし、グローバル文字スタイルの自然プレイ時の値、別配置のstyle2、桁数による画面の重なりやクリッピングは今回確定していない。

## 根拠と再抽出

一次資料はユーザー提供ディスクから保存済みの原EXE、`/DAT/MSG00.OBJ`、`/TIM0/PSMOJI0.TIM`・`PSMOJI1.TIM`・`KYOU.TIM`である。

- 原EXE SHA256: `d6a167a1c9e0fe98d7e44e12968caa489ac3eb7ed3b9e46012a188af8432b1fd`。
- HUD生成: `0x8004095C～0x800411B8`、日時読出し: `0x80019EB4～0x8001A098`、固定文字経路: `0x800153EC～0x800155D0`。
- [原文字列と命令引数](hud-messages.json)、[出典と原コード範囲](source-provenance.json)、[Android接続仕様](android-hud-bridge.json)。範囲終端は非包含。
- `source-reference`は既存r2解析の保存用写しであり、今回新規にCPU検証した結果ではない。
- 再抽出: `python extract-hud.py /path/to/source.zip`。保存済みr2アーカイブのSHA256を照合する。Pillow・Capstoneと既保存の文字対応表を使用する。

検証は入力ハッシュ、命令引数と文字の分離、元メッセージ2件の一致、画像範囲・パレットの照合に限定した。全体の解析完了率は測定していない。既存の追跡課題7件のうち未解決6件という数は、このHUD接続の追加では変わらない。
