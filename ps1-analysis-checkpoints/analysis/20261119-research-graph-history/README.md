# 店舗別・全店グラフ：損益履歴・縦軸・描画境界

2026-11-19 JST。［確実］店舗別グラフの元は**月次損益の60件履歴**であり、前月・今月の売上2点ではない。縦軸は最低100万円、100万円刻みで、店舗損益だけでなく同じ期の自社全店平均の絶対値も参照する。直前のv0.6.2の仮表示との差分を原描画コードへ接続した。

## 既存成果との重複を除いた範囲

月次帳簿の8倍化、資金調整、60件履歴への書込み、保存本文の対応、買収時の履歴消去は既存r2の `finance_close.py`、`save_codec.py`、`store_lifecycle.py` と11月15～16日の成果にある。売却の主要ルールと店員+20の採用経験表示も既知であり、今回の新解読には数えない。

今回の中心は、これらの既知履歴の**読出し側** `800478F8～80048B80` を確認し、UI用の有効件数・平均値・スケール・描画位置に対応させたことにある。既存アーカイブのPython/JSON/Markdownを照合した範囲では、この描画関数とスケール関数に対応するモデル・原処理試験は見つからなかった。アーカイブ全体の未解析率を測ったものではない。

| 今回整理した項目 | 原仕様と移植上の意味 |
|---|---|
| 履歴の有効範囲 | 最大60件。先頭から、全店件数が正、全店損益が未登録値でない、店舗損益が未登録値でない、の全条件が続く部分だけ使う。途中の未登録値を飛び越して古い点を表示しない。ゼロ損益は有効 |
| 縦軸 | 同じ有効範囲で店舗損益と `全店損益÷その期の店舗数` の絶対最大値を求め、最低100万円・100万円刻みに切り上げる。負数の平均は0方向へ除算。全店グラフは全店損益そのものを基準にする |
| 棒の描画 | 最新が履歴index0。描画は有効履歴の末尾から始めて古い順に左へ並べる。240×112画素、1件4画素、正3・負2・境界/グリッド4のパレット番号。金額をまず1万円単位へ切り捨てて高さへ変換する |

### 実データへの接続（既知仕様の再利用）

- 店舗内の損益60件は `store+0x12E8`、各i32。未登録は `0x80000000`。店舗strideは5080。
- 全店損益は `0x800E3C28`、期ごとの自社店舗数は `0x800E43D0`、平均の作業配列は `0x800D6018`。
- 原月次決算が当月5帳簿を8倍にし、売上欄から4費用欄を引いて店舗履歴へ記録する。表示側でさらに8倍しない。これは既存 `finance_close.py` の規則。
- 元は新しい期がindex0に入り古い履歴を後ろへ移す。買収時の店舗履歴は未登録値へ戻すため、買収前の全店履歴をその店の履歴として埋めない。
- 保存本文の全店損益は `+0x872C`、店舗数は `+0x881C`、店舗0の履歴は `+0x9B40`、店舗slotごとに5080を足す。既存セーブ対応表から算出した位置であり、カードの物理ブロック番号ではない。

## 必要最小限の確認

原スケール関数 `80048728` を文字描画前まで4条件で実行し、独立した整数モデルと比較した。

1. 店舗400万円に対し全店平均500万円なら、軸は500万円。
2. 店舗履歴の途中が未登録なら、その後の900万円は軸に影響しない。
3. 100万1円は軸200万円へ切り上げる。
4. 損益0は欠損ではなく、有効な履歴として軸100万円になる。

原ビットマップ関数 `80047C00` は、指定した正負100万円の2点で1回実行した。5件の完了した原処理入口のみで、営業更新0回。初回の停止位置のPC表現を調整する準備再実行2回は、この5条件と別に記録する。メモリカード・UI全体・長期自然プレイは実行していない。

**［確実］この指定値では、原コードが240×112の出力範囲の前後へ各4バイト書いた。** 正の最大棒は前の行、負の最大棒は次の行へ1行はみ出す。`original-cases.json` は前側offset −236～−233、後側offset0～3を記録する。実ゲームでの表示結果やゲーム停止原因を示す証拠ではない。Androidへ移す際は、範囲外書込みを再現せず表示領域へクリップする。

[原処理の描画バッファ](original-graph-bounded.png)は元パレットで色を付けた参照画像であり、実プレイ画面ではない。

## 実装へ渡す差分

v0.6.2（commit `26d88e20812e7c540864f2c98ca41102440a779a`）の `game/scripts/ps1_ui.gd::_graph` は、店舗側に前月・当月売上を使い、軸の最低値を400万円にしている。原仕様へ合わせるには、店舗別損益履歴・全店損益・その期の店数を保存し、同じ期を照合して表示する必要がある。[Android接続表](android-bridge.json)に具体化した。今回、アプリ・APKは変更していない。

既存7項目のうち未解決6件はそのまま。今回の成果は、その7件とは別の通常UIに残っていた仕様差を解明したものである。
