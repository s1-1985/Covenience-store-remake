## 調査費と買収費を分ける

原画面の選択肢は「調査する」「買収する」「何もしない」。既存の補助コードが結果名に使っていた `lease` を、賃貸の証拠として採用していない。

調査費は50万。対象店舗の+2バイトが1なら表示上の調査費は0で、実際の50万の支払はそのバイトが0のときだけ行う。買収価格の支払とは別であり、敵会社への売上にはならない。未調査時の3択からは調査を経ずに直接買収を選べる。

+2が1のときはUI子関数が詳細情報を表示して、確認後に既定値2を返す。調査を済ませた後の子関数へ架空の「買収」戻り値を与えて、通常のUI経路が通ったと解釈しない。+2の生存期間や別処理の更新元は今回の範囲で全て追っていないため、この観察からゲーム全体で永続的に買収不能になるとは断定していない。

[原文と文字コード](transaction-texts.json)および[調査状態とUI分岐](inspection-state-routing.json)を保存した。数値制御4004に続く0は変数番号で、金額0そのものではない。

## 買収で引き継ぐもの・消すもの

代金は、旧所有権が残っている間に自社から支払い、対象店舗側へ同額を渡す。両社の現金と資本支出台帳へ逆符号で記録した後、自社の店舗通番を増やして対象店の所有フラグを書き換える。

配属店員は人物IDを維持し、新しい自社店の所有フラグへ所属を付け替える。店員本人の能力・時給・体力を初期化する処理は、この付替え関数にはない。原初期データで配属されている29件について[店員参照の引継ぎ表](initial-staff-transfer-links.json)を作成した。

付替え時に初期化するのは、日次/月次/年次の帳簿領域各80バイト、赤字連続回数、店舗別入店累計、被害等のカウンター、27商品分の実績324バイト、利益履歴60件などである。利益履歴は0ではなく原の未登録値0x80000000に戻す。

一方、この付替え関数は内装・残存在庫・店舗段階・販売許可・営業時間・商品設定・店舗評価/人気・配属店員IDを保持する。その後に町の自社用タイルを置き直し、販売制限と集計キャッシュを再構築するため、保持範囲を「後続処理後も全バイト不変」と読み替えない。

[ownership-field-policy.json](ownership-field-policy.json)に、原オフセット単位の初期化範囲と保持範囲を記録した。

## 売却は相手への所有権移転とは別

売却側は自社店舗一覧から選び、**一覧の先頭店**を本店として拒否する。敵店買収の「通番下位8bitが1」というガードとは参照値が異なる。また、店舗+0xC77が非0なら原文「開店中は売却できません」で拒否する。

確認後、土地と建物等の評価額を負の資本支出として返金する。店員を未所属へ戻し、店員参照を外してから町の建物を空き地化し、店舗レコードを初期化する。今回の売却枝には相手会社の代金負担や相手所有店への変換はなく、買収の逆向き転送として実装しない。
