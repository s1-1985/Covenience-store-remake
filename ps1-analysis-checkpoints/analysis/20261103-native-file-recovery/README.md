# 原カードファイル処理の再接続（2026-11-03）

## 実行結果

原7ADF8（書込み）と7AB2C（読込み）から、原の状態判定・イベント待ち・ディレクトリ走査へ接続し、
新規ファイル作成7B8A4とヘッダ生成7BC14も含めて、限定MIPSインタプリタで再実行した。
BIOSのファイル操作と通知、VSync、memcpyは指定した論理境界で供給する。
物理メモリーカードのブロック割当・シリアル通信、BIOS本体、描画・音声・IRQは対象外である。

| 対象 | 結果 |
|---|---|
| 初期入力 | r2に残っていた実保存ペイロード2本 |
| 新規作成 | 2ケース、元のopenフラグ0xE0200で14ブロックを確保 |
| 上書き | 2ケース、ファイルを再作成せず、先頭512バイトを完全保持 |
| 原の読書き関数呼出し | 16回（書込8、読込8） |
| 本文の転送 | 各ケース・各段階で書込892回＋読込892回、各128バイト |
| 論理ファイル | 4本、それぞれ114688バイトをGitへ保存 |
| 本文 | 114176バイト全体でRAM→ファイル→RAMが一致 |
| 乱数試験値 | 今回の境界条件の下でDEADBEEFを保存 |

「2ケース」は同じゲーム操作を実機で2回成功させたという意味ではなく、
2つの実ペイロードを入力にした制御試験である。
初期RAM・スタック・末尾9812バイトは明示した試験値を含む。
通常プレイやタイトル画面から通したロードではない。

## ファイル構成と転送範囲

- パス：bu00:BISLPS-00782CONV
- 先頭：53 43 13 0E
- 先頭512バイト：原のヘッダ生成関数によるもの
- 本文：104364バイトの実ペイロード＋9812バイトの試験用末尾
- mode 0：ファイル[512,90112)、128バイト×700
- mode 1：ファイル[90112,114688)、128バイト×192
- 対応RAM：80187E00から連続114176バイト

全転送について、ファイル位置・RAM位置・要求長・実行結果を比較した。
最初の入力から作ったファイルを読み戻した後、もう一方のペイロードへ上書きし、
再度RAMをCCで破壊してから原読込処理で復元した。

## ヘッダ余白は保持される

スタック領域をA6またはA7で初期化した試験では、ヘッダ+13..95にもその内容が残った。
したがって、この原ヘッダ生成経路が余白を一律ゼロにするというモデルは合わない。
上書き時は生成済みの512バイトのヘッダを全バイト保持した。
ヘッダ・ペイロード・ファイル全体のハッシュをresults.jsonに記録した。
同梱4ファイルは試験で生成した論理ファイルであり、元の営業時の物理カードを保存したものではない。

## 実行環境の初期化修正

最初の接続試験では、限定CPUのGPを0のままにしていた。
原書込処理はGP+0xA4にあるバッファポインタを参照するため、誤ってRAM 0から転送して比較が不一致となった。
これは試験環境の設定不足であり、ゲームのバグではない。

同梱の既存connectedハーネス等で使っているGP=800CD6C4を設定すると、
元EXEの800CD768には既に80187E00があり、ポインタを書き換える必要なく一致した。
この修正をresults.jsonのsetup_auditにも記録した。
限定CPUにはstack_pointer/global_pointerの実行引数を追加し、既定値は以前の試験と同じにしている。

ヘッダ処理は大きなスタック領域を参照するため、SP=801D0000を指定した。
この条件で全参照を2MB RAM内へ収めた試験である。
実機の高位スタックやRAMミラーを今回検証した証拠ではない。

## 保存したデータ

- native-file-analysis.py：自己完結した限定CPU・論理ファイル境界・検証コード。
- results.json：入力元・ハッシュ・呼出結果・転送数・初期化修正・全I/Oトレース。
- files/case-0-create.bin
- files/case-0-overwrite.bin
- files/case-1-create.bin
- files/case-1-overwrite.bin

results.json内のtrace_zlib_base64は、全I/O記録のJSONをzlibで圧縮してbase64にしたもの。
trace_sha256は展開後JSONバイト列のSHA-256である。
次の式で全トレースを復元できる。

```python
raw = zlib.decompress(base64.b64decode(phase["trace_zlib_base64"]))
assert hashlib.sha256(raw).hexdigest() == phase["trace_sha256"]
events = json.loads(raw)
```

試験用の全ファイルも出力JSONのfile_base64から復元できるが、
Git保存版results.jsonでは重複格納せず、saved_file_pathに示した実バイナリへ分けた。
今回の元資料はGitに全バイト保存済みのr2 ZIPである。

## 再実行

Python 3標準ライブラリのみ。作業ファイルを書き込まず、生成ファイルを含むJSONを標準出力へ出す。

```sh
python native-file-analysis.py /path/to/Conveni-PS1-Analysis-Checkpoint-20261103-r2.zip
```
