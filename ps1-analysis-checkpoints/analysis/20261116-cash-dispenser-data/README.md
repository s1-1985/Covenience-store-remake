## 通常の客からの選択経路

標準の入店処理は購買型の先頭商品を選び、追加購買は同じ購買型の最大4枠を読む。原144購買型×4枠には商品26が1件もない。棚の目的地選択も「在庫画像の商品と現在の欲しい商品が一致」を求めるため、所持金不足だけで自動的に引出機へ向かうという遷移は今回の標準経路からは見つからない。

この結論は有効な購買型0～143と回収済みの通常入店/購買/会計経路に限定する。特殊イベント・別の書込み・範囲外購買型144まで含む全経路不存在の証明ではない。

汎用購買処理は客の所持金から商品単価を引く。現金商品の元価格0からは、単価計算も0になる。仮にこの商品を汎用経路へ与えても、この計算だけでは所持金の増加や手数料は説明できない。これはゼロ単価式の条件付き読取りであり、引出機を自然利用させた実行結果ではない。

また、商品26は店の平均価格指標から明示的に除外される。ゼロ価格を平均に加えて「引出機を置けば価格評価が安くなる」と実装しない。

## 「利用されていません」の専用原文は存在する

原0x80099338には「キャッシュディスペンサ―が あまり利用されていません」という店長通知用の文がある。商品別利用実績の最小候補が26になったときに、通常の「商品があまり売れていません」と違う文章を使う。

この通知は自社店・店長の能力・まれな抽選・他商品の最多実績200以上・少利用実績6未満などの条件付きであり、引出機の存在だけで必ず表示するものではない。文章の存在は通知枝の証拠であって、出金や手数料処理の証拠ではない。[原文字コード](dispenser-texts.json)と[経路仕様](cash-route-rules.json)を参照。

## 残件の扱い

R01は**通常客候補に現金がなく、汎用の販売処理だけでは出金を説明できない**ところまで限定した。専用の引出し経路・引出額・手数料・休眠機能なのかという意図は未確定なので、解明済みへ数えない。残件台帳は7件中1件解明・6件未解決を維持する。

Androidへは確認できた什器・配置・画像・維持費等を移植し、未確認の銀行残高や現金ボーナスを追加しない。[Android接続仕様](android-cash-dispenser-bridge.json)に記録した。
