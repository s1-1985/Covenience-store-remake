# 営業時間7区分と什器53種類の維持費

2026-11-13。床・清掃の解析に続き、什器の毎日の費用と営業時間データを原ディスクから抽出した。一般的な故障・修理費として推測する代わりに、実際に費用計算へ使われる整数欄を特定した。

## 今回の追加

- 営業時間表の完全なレコード構造を読解。先頭 `0x80099DD0`、1件45バイト、Shift-JIS名21バイト＋時間別フラグ24バイト。通常の6区分に、7番目の「臨時休業」が存在する。
- 什器表の+8（第3ワード）が営業時間あたりの維持費計算に使われることを、全53種類の名前と接続した。
- 固定24時間モードと実営業時間モード、店長枠の30％加算と丸め順を移植仕様へ保存した。

時間・設備・人件費の独立式自体は、以前の `operating_costs.py` に復元済み。今回は完全な営業時間名付きデータと全什器の費用対応を抽出したもので、計算式全体を新発見として数えてはいない。原CPUの営業更新は実行していない。

## 什器の費用欄

什器レコードの先頭は `0x80099F0C`、1件196バイト、53件。+8の整数を原関数1D980・1DB5Cが読み、対象時間数を掛ける。

これらは原計算が使う額。購入価格の表示単位や別の金額変換は、このレートから推測しない。原名の復号は以前のMSG00成果を再利用し、参照先をJSONへ記録した。

全53種類について、7営業時間区分の費用を `schedule-fixture-costs.json` に保存した。什器1個を設置アンカーで数えるため、2×2の什器だから面積4倍をさらに掛けたり、在庫の残量を掛けたりしない。

## 実営業時間と固定24時間モード

費用関数のmode=0は、現在の営業時間フラグが非0の時間数を使う。modeが非0なら、現在の営業区分にかかわらず24時間として計算する。

毎日の費用差引き断片 `0x800296F0..0x800297A4` はmode=0を使い、設備費を店舗+0xD88、人件費を+0xD8Cへ保存する。その後、これらと既存の+0xD90を所有側の資金から差し引く。+0xD90の費目名や生成式は、今回新たに割り当てていない。

臨時休業ID6ではこの設備・人件費の計算結果は0になるが、既存+0xD90を含む別の費用まで全て0になるとは限らない。固定24時間モードを毎日の差引きへ流用すると、短時間営業の費用が原版と変わる。

## 店長枠の人件費は、時間を掛ける前に丸める

原関数1DD7Cは店員+12の賃金基準を読み、配属スロット0だけ `基準*130/100` の整数除算を行ってから営業時間数を掛ける。スロット1・2にはこの加算がない。

例えば基準99・8時間なら、店長枠は `trunc(99*130/100)*8 =128*8=1024`。一般枠は `99*8=792`。最後にまとめて30％を加算すると端数処理が変わる。

この費用関数には、実際にレジに立った時間、清掃中、休憩中、残り体力による補正はない。配属参照が-1でなければ対象となる。清掃能力指標の計算と同様に、「配属」と「現在の行動」を分ける必要がある。
