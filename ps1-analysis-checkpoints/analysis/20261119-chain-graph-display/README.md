# 全店収支グラフ：現在の全店ヘッダーと原履歴ビットマップ

2026-11-19 JST。［確実］全店グラフ上部の顧客独占率・総合評価は**現在の自社全店**の値である。一方、棒は既知の月次全店損益履歴を使う。現在の選択店舗だけをヘッダーへ表示したり、過去の各月の評価を棒に対応させたりしない。

既存未解決6件は保留。今回はAndroid実装・APKを更新していない。

## 星を各店で切り捨ててから平均する

原498C8は既知の原1BD78(mode0)で現在の稼働中自社店を列挙する。各店の評価C68を20で整数除算し、その星数を合計して自社店数で再び整数除算する。通常0～100の評価では次の式となる。

`全店の表示星 = floor(sum(floor(各店の評価/20))/現在の自社店数)`

| 指定した自社2店の評価 | 各店の星 | 原の全店表示星 | 点数を先に平均した場合 |
|---|---|---:|---:|
| 39・99 | 1・4 | 2 | 3 |
| 100・100 | 5・5 | 5 | 5 |

2段階の切捨てをまとめると、1行目で表示が変わる。今回、店舗slot0/3に自社、slot5にライバルを配置した指定入力で、原の列挙・計算を実行した。ライバル評価100を合算せず上表になることを確認した。評価を更新する原年次処理や星変換の単独式自体は既知であり、新規の評価機構として数えない。

総合評価はMSG462「総合評価」の星制御400Cへ渡す値。読取元は店舗C68で、人気C6Cではない。星表示要求は(168,48)である。

## 顧客独占率も現在の全店需要から

原は現在の自社店+DE0の合計に100を掛け、原20498(mode0)が数える現在の町人口で整数除算する。MSG461へ数値を渡し、位置は(24,48)。直近のレジ会計件数や月次売上ではない。DE0自体の需要生成・町のプロフィール人口計算は既存成果を再利用した。

指定入力では自社店の需要100＋50、町人口300なので50％。ライバル店の999は除外される。町は150セルだけに原mix0を与え、残る2,850セルを人口なしとした。原の町人口関数も置換せず実行した。これは原形式の診断用データであり、実マップで自然に50％になった観測ではない。

町人口0・自社店0・通常範囲を外れる評価は今回試していない。未確認のゼロ除算対策や異常値仕様を新たに原版仕様として付け足していない。

## 全店ビットマップの対応を追加

11月19日のresearch-graph-historyは店舗別48728/47C00を限定実行し、全店4965Cのスケールも静的に整理していた。今回は未実行だった**全店48CF8**のビットマップと、4965Cの対応する2入力を直接照合した。既知の履歴・軸・棒の一般規則を再発見として扱わない。

| 追加した全店入力 | 原の結果 |
|---|---|
| 新しい順に+500,000、−500,000、0。各期の自社店数2 | 軸±1,000,000、左から0、−500,000、+500,000。各店数で割らず全店合計の棒 |
| +400,000、未登録、+9,000,000。各期の店数1 | 先頭の400,000だけ有効。欠損より後ろの900万は軸・棒へ使わない |

全店損益E3C28・各期店数E43D0の共通先頭区間を最大60件使う。店数は有効性の判定に使い、棒の額を1店当たりへ割る計算ではない。個店履歴は全て未登録を与えても全店の棒を描いた。既知の月次損益計上や保存形式を今回再試験していない。

**損益0も有効であり、原は1画素の青い棒を描く。** 240×112バッファ内のrow55に色3を3画素、境界色4を1画素置く。負額はrow57側から描く。Androidの高さ0の矩形にすると、この原表示が消える。金額を先に1万円単位へ整数化してから高さを計算する規則も保持する。

[原パレットで色を付けた240×112のバッファ参照](chain-bitmap-reference.png)を保存した。これは原48CF8の出力に色を当てたもので、PSの実画面・GPU合成や生成イラストではない。

今回の値は軸の最大値より小さく、バッファ前後の各240バイトに書込みはなかった。前回の店舗グラフで記録した軸ちょうどの値による範囲外書込みは再試験していない。今回の境界無変更を全入力の安全性保証へ一般化しない。

## Androidとの差分と範囲

アプリcommit22ba479のps1_ui.gd::_graphは、全店/個店で同じs.star_ratingとdemand.customer_share_percentを描く。現在の需要割当側では各店ごとにその店の独占率を保存しているため、全店画面のヘッダーには自社全店の再集計が必要になる。

全店の棒はmonth_end_recordsを使っており、履歴があること自体は既に対応している。一方、最低400万円の軸、浮動小数の高さ、0高さの矩形は原の軸・整数化・0の描画と異なる。既に指摘した店舗別グラフとの差と分け、[表示仕様](display-rules.json)へ全店ヘッダーと全店ビットマップの対応を追加した。アプリ本体は未修正。
