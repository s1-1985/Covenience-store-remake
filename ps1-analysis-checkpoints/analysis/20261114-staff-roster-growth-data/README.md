# 店員35人の初期データ・マップ別配属・原能力名と成長

2026-11-14。初代PS版SLPS_007.82のディスクから、店員の全54バイトの保存レコードとUIの能力名を読み、採用・配属・成長・休憩・年次処理へ接続した。

## 今回の追加成果

- 4マップ×35件の店員状態を抽出した。個人の名前・年齢・賃金・初期能力は同じ35人分を共通利用できる一方、所有・配属・店内姿勢はマップ別である。
- 原画面の能力ラベルをEXE内の文字列と数値表示の行から対応付けた。旧報告で「指導力」と仮称していた+0x1Dの原名称は **学歴**。前回未命名だった+0x20は **接客**。
- 教育・敏捷性・社交性と現在の仕事能力を区別し、成長の通常到達目標と超えられない上限を対応付けた。
- 控え室2種類の回復規則、採用候補10人の抽選方法、年次の加齢・賃金更新を移植用データへ保存した。

候補抽選や成長などの単独アルゴリズム自体は以前の独立モデルにもある。今回の中心は、完全な35人のマスター・140初期状態・原UIラベルとの接続と、旧仮称の修正である。原CPUの営業更新を長時間延長する作業はしていない。

## 共通35人とマップ別の初期状態

| 元ファイル | 店員レコード | 所有フラグ0の人数 | 初期の活動店舗数 |
|---|---:|---:|---:|
| TOWN0001.BIN | 35 | 29 | 2 |
| TOWN0002.BIN | 35 | 26 | 3 |
| TOWN0003.BIN | 35 | 32 | 1 |
| TOWNPS.BIN | 35 | 23 | 5 |

この時点の活動店舗は原データ中のライバル店。人物の初期年齢は16～58、賃金基準は250～340。これらはゲーム内の値である。

TOWNPSの店員ID27（池上秀夫）は所有フラグ0xFFFFで、活動店舗の配属参照にも現れない。この値は候補抽選の「所有フラグが0」という条件を満たさないため、初期の採用候補には入らない。特殊な値になっている目的や、後の解放条件は未確定である。

共有できるのは初期プロフィールであり、プレイ開始後の能力・年齢・賃金を不変にする意味ではない。実行時には各ゲーム状態へ個別に複製し、他マップや別セッションと可変データを共有しない。

## 保存54バイトと実行時60バイトの対応

各TOWNファイルのオフセット24017から、54バイト×35件が続く。原ローダー1A0B8は、各フィールドを実行時の60バイトレコードへ展開する。

| 実行時オフセット | 内容 |
|---|---|
| +0 | 所有・店舗フラグ、u16 |
| +2 | 名前インデックス |
| +3 / +4 | 年齢 / 性別コード |
| +6 / +8 | 店内の体画像 / 顔画像 |
| +12 | 賃金基準、i32 |
| +16 | 意味未確定のi32。元値を保存 |
| +20 | 採用経験のカウンター。UIでは0/非0を「経験なし/あり」へ使う |
| +24～+39 | 基本値・現在能力・成長到達目標 |
| +40 | 行動状態 |
| +41～+46 | 現在位置・向きと目標位置・向き |
| +47～+56 | 10バイトのルート |

+5、+10～+11、+57～+59はこのローダーが書かない隙間。抽出時の一時配列は便宜上0で埋めるが、原データが0を明示している領域ではない。`packed_schema.field_map` に54→60の対応を全て保存し、書込対象を再連結すると元の54バイトへ完全一致することを確認した。

名前はMSG00.OBJの150+名前インデックスから原文字コードを読み、既存のPSMOJI転記表で復号した。今回は新しくフォントOCRをしたものではない。

## 原UI名とフィールドの修正

EXE内 `0x800B9654` の採用画面ラベルは「体力・学歴・敏捷性・社交性」。`0x800B96B0` の異動画面ラベルは「体力・教育・レジ・補充・警備・清掃・接客」。数字を描く元コードの行位置と対応させた。

| オフセット | 原名称・内容 | この経路での役割 |
|---|---|---|
| 0x18 | 最大体力 | 現在体力の回復上限 |
| 0x19 | 現在体力 | 仕事中の消耗・休憩回復 |
| 0x1A | 教育 | 現在のレジ・警備能力の成長上限 |
| 0x1B | 敏捷性 | 現在の補充能力の成長上限 |
| 0x1C | 社交性 | 現在の接客・清掃能力の成長上限 |
| 0x1D | 学歴 | 店長として部下の成長や助言の抽選に使用 |
| 0x1E | レジ | 実際のレジ処理に使用 |
| 0x1F | 補充 | 補充動作の成功と数量に使用 |
| 0x20 | 接客 | サービス指標や補充候補の閾値等に使用 |
| 0x21 | 清掃 | 清掃動作と清潔度指標に使用 |
| 0x22 | 警備 | 防犯関連の指標に使用 |

過去の「店長指導力」「leadership」「manager_value」は、この+0x1Dを機能から仮称したもの。値や計算式が変わったわけではなく、原画面名が学歴であると修正する。今後の移植データでは原名称・オフセット・計算上の役割を分ける。

前回の補充解析で未命名にした+0x20も、ここで接客と対応した。つまり **補充候補の残量閾値には接客、補充動作の成功・数量には補充** が使われる。直感的に両方を「補充」へまとめると原版と異なる。

## 採用候補は空き全員から最大10人

原6F8BCは35件を走査し、所有フラグu16が厳密に0の者だけを候補母集団へ入れる。年齢・賃金・能力でこの母集団を絞る処理ではない。0x8001等のライバル配属者や0xFFFFは除外される。

最大10人を選ぶ際は、最初の空き人数Nに対して毎回 `rand()%N` で位置を選ぶ。選ばれた要素は-1へ変わるが配列長Nは保ち、すでに-1の位置を引いた場合も乱数を消費して引き直す。選択済み要素を配列から削除する抽選へ置き換えると、同じシードでも後続の乱数系列が変わる。

採用確定には先頭枠の店長が必要。候補表示が10人であることを、ゲーム全体に店員が10人しかいないという意味に取らない。

## 顔画像と配属後の体画像は別

顔画像はプロフィールの+8を使用する。配属確定時には+6の体画像が、役割と性別から上書きされる。

| 配属枠 | 男性コード | 女性コード | 控え室内の0.5マス位置オフセット |
|---:|---:|---:|---|
| 0：店長 | 42 | 43 | (0,2) |
| 1 | 38 | 40 | (0,1) |
| 2 | 39 | 41 | (1,1) |

未採用時の+6や人物IDをそのまま店内スプライトへ使わない。名前ID・顔画像・配属時の体画像を区別し、店員が表示されない／別の人物の絵になる原因を避ける。

採用確定70F48は、所有フラグ、体画像、行動状態、休憩位置を更新し、採用経験カウンター+20を増やす。採用画面全体の費用について「一切かからない」といった新しい結論は今回出していない。

## 成長の上限と通常の到達目標

各現在能力には、上の基本値を参照する上限と、+0x23～+0x27に入る通常到達目標がある。原3AA58は最初に乱数を1回引き、`rand()%16==0` ならその呼出し内で目標を超えることを許す。ただし、基本値による上限は超えられない。

各能力について、店長の学歴による `roll1..100<=学歴` と、上限・到達目標の条件を満たす場合に1増やす。能力が上限に達していても、原順序ではその能力の乱数抽選を先に消費する。

| 成長モード | 増える対象の候補 |
|---|---|
| 1：レジ成功側 | レジ、接客 |
| 2：補充完了側 | 補充、警備。清潔度指標100以上なら清掃も |
| 4：清掃成功側 | 清掃、警備 |

同じ呼出しの各能力が共有する特別フラグであり、能力ごとに独立した1/16抽選を追加しない。実際の成功・完了条件はそれぞれの親処理に従う。

例として人物0の初期マスターでは、レジの上限80、通常到達目標52。現在値51なら通常抽選を通って52へ進めるが、52から53へは特別フラグも必要。80から先へは特別フラグがあっても進まない。これは原式からの例で、実プレイを延長した観測ではない。

モード-1は、レジ・補充・清掃・警備を、現在値が2以上のときだけ1下げる。接客はこのモードの減少対象に含まれない。この報告ではモード-1の全呼出し元まで確定したとは主張しない。

## 体力と控え室

活動中、現在体力が正なら `rand()&3==0` で1減る。体力が尽きると休憩移動以外の目標を解除するが、状態3の休憩場所への移動は続けられる。

| 控え室ID | 最大体力に達するまでの1回の回復処理 |
|---:|---|
| 48 | `rand()&1==0` なら1回復 |
| 49 | 乱数を使わず1回復 |

回復後すぐ全員一斉に仕事へ戻るわけではない。満タンで休憩中の場合、`(clock//2)%3 == 配属枠` の区間で仕事選択へ進む。これは更新回数に対する条件で、回復に何秒かかるという実機速度の測定ではない。

## 年次処理と賃金表示

年次決算の該当時点では、未採用者も含め35件の年齢を増やす。年齢127で増加は止まる。増加後80以上なら1/5条件の抽選、127なら無抽選で、最大体力・教育・敏捷性・社交性・学歴の5欄を100へする分岐がある。現在体力や現在の仕事能力まで直接全部100へする処理ではない。

賃金は、活動店舗へ配属されている人に対して `賃金*(店舗+0x12DC+100)/100` の整数計算を行う。抽出した全ての初期活動店舗では+0x12DCは3だった。未配属者はこの店舗別の乗算対象ではない。

異動画面の表示額は、賃金基準×営業時間。一方、実際の給与費計算は店長枠だけ30％を加算し、丸めてから時間を掛ける。

| 人物0・基準280・24時間の算式 | 額 |
|---|---:|
| 異動画面のプロフィール表示計算 | 6720 |
| 店長枠の実費計算 | 8736 |
| 配属中に年次3％更新を受けた後の賃金基準 | 288 |

これらは元の表示式と費用式の違いであり、表示値へ独自の店長倍率を後付けした結果ではない。詳細な費用式は [営業時間・維持費の解析](../20261113-operating-cost-data/README.md) と接続する。
