# 通常入店の音声監査：Android独自チャイムと原の駐車不足SE

2026-11-19 JST。［確実］現Android版のcustomer_entered→door_chimeは、原PS版から抽出した音ではなく、独自の合成音である。原通常生成・入店初期化を指定入力で実行した結果は音声要求0、音声フラグへの書込み0だった。

既存未解決6件は保留。祭りや特殊な客状態の追試は行っていない。今回の検証は通常の入店と駐車容量分岐の音声接続であり、Android/APK自体は変更していない。

## 現在聞こえる音の由来

Android commit22ba479のgame/data/vertical_slice.jsonにcustomer_entered:door_chimeが残る。main.gd::_play_event_soundsは原音番号に対応しないイベントをこの旧event_sfxへ流し、SoundManager.play_sfx→SoundSynth.sfx_samplesを通す。door_chimeはE6を0.42秒、C6を0.9秒、各々にE7/C7の倍音を加える独自合成である。source_audio.jsonの原SE/ボイス番号へは接続していない。

sound_manager.gdと設定のevidence_noteも、この旧イベント音をREMAKE_BALANCED_DEFAULTの合成として明記している。原音素材を導入した後も旧チャイムが残っているため、「音が鳴る＝PS版の音」という理解にはならない。

このコード監査は現22ba479の実装に基づく。ユーザー端末で再生された音を録音・波形照合したわけではないが、質問の入店イベントに実際に対応する現行音源はこの合成チャイムである。

## 原の通常入店へ接続した結果

既存の通常生成用セットアップを再利用。原TOWN0001、営業時間指定0、通常フラグ0（祭りなし）、時計44640、指定RNGを与え、原需要集計・原営業前準備を通した。原319ACの生成側を32814まで実行すると、店舗slot2の先頭にprofile60、人数2、state1の客が生成される。続いて原32814の既存客ループを1回実行し、原331B4の入口探索と初期化でstate2へ進んだ。

この生成から初期化まで、共有音声フラグCD790への書込みは0、原音声ディスパッチ64E4Cへの呼出しも0。画面合成・音声ハードウェアを置換して「無音だった」と判定したのではなく、発音要求の生成そのものを監視した。

原331B4..340FCの全入口探索処理にあるjalは乱数7E648のみ。入口が見つかった後の329BC..32ABCも、目的商品・期限・予算・カート初期値を設定するがチャイムの要求を追加しない。この静的経路と今回の通常例は、成功入店ごとに独自チャイムを鳴らす現Androidの対応を支持しない。

［可能性が高い］PS版の通常成功入店には、現Androidのような毎回の汎用チャイムはない。ゲーム全域の全特殊イベント・店員ボイスとの同時発生を否定する結論ではない。原実機の全音声出力も今回聴取していない。

## 入店付近でも、駐車不足の音は別にある

原31C28は購買型+12が3の場合、駐車容量と使用数＋到来人数を比較する。容量不足なら店舗+12E3の損失カウンター（127上限）を増やし、該当購買型の需要から元の到来人数を差し引き、音声フラグbit6（0x40）を立て、今回人数を空き容量へ縮める。この容量ルールとbit6自体は過去のcustomer_spawn_core.py/customer_capacity.pyに既にある。今回の新規作業は、現Android入店音と区別して、原分岐の発生条件→原主処理→SE11まで結び付けたことである。

| 指定した通常購買型15・人数2 | 原分岐後の人数 | 残需要 | 損失カウンター | 音声フラグ |
|---|---:|---:|---:|---:|
| 駐車容量1・使用0 | 1 | 0 | 1 | 0x40 |
| 駐車容量2・使用0 | 2 | 2 | 0 | 0 |

容量比較から31E3Cまでの限定実行であり、表の人数がその後実際に入店完了したという確認ではない。特に一部の人数が入れる場合でも不足のフラグが立つので、「入店近くで音がした」と「全員の成功入店にチャイムがある」を混同しない。

原の選択店舗ガードを通る主処理23A14..23BBCへ0x40を渡すと、元テーブル9947Cのbit6→ディスパッチ11を1回要求し、フラグを0にする。SE11の原スコア・音色は11月13日の音声抽出に存在するが、この監査では再合成・試聴しておらず、ユーザーの「ピコーン」という擬音と同一の聴感だとは主張しない。原レジ音10や店員ボイス22/23とも別条件である。

## 移植上の扱い

PS版忠実再現の通常営業では、customer_enteredへ付けた独自door_chimeを外すのが妥当。原の駐車不足bit6→11、会計bit9→10、店員の対応する発話フラグは各々の原条件で扱う。独自チャイムの代わりに毎回SE11を鳴らす変更も誤りである。

今回は解析結果を保存し、現APKの入店音はまだ変更していない。現実の端末に修正版が適用されたとは報告しない。

## 根拠と再現範囲

最終の限定入口は6件：営業前準備1・通常生成1・入店ループ1・駐車比較2・音声主処理1。準備の失敗実行0。最初の成功出力6入口後に保存する命令抜粋を絞り、同じ6入口を再実行して最終出力を保存した。命令抜粋は駐車比較・入店初期化・入口探索先頭/全jal・音声主処理に限定し、全範囲のハッシュは別に残す。別途、既知の画像表初期化・原マップローダー・集計2回・需要生成の計5呼出しを再利用し、そのマップローダーの外部資源要求だけを既存手法で置換した。営業全体を1日進める処理は0回。暦・営業時間・RNG・駐車容量は指定入力。入店ループの原処理は置換していない。最後の音声主処理の64E4Cのみ要求番号を捕捉して復帰し、SPU/XA再生はしていない。
