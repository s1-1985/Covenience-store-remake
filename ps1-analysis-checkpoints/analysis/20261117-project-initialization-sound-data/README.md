# 誘致レコードの新規初期化と原呼出し経路での完成通知音

2026-11-17 JST。R05の未解決点のうち、**誘致レコード+30の新規マップ読込み時の初期値は0**と確認した。元の4マップを原ローダーへ渡し、18施設の開始レコード書込みも接続した。さらに原呼出し元の店舗集計→イベント→営業前段→誘致完成を通し、4マップ×18施設の条件入力で通知音コード29を確認した。

ただし、完成目前の誘致は入力として設定したもので、自然プレイで購入・待機して到達した観測ではない。年次イベント・改装・店舗増減・既存セーブの全状態へ一般化せず、R05全体は未解決を維持する。

## 新しく分かった初期値

原1A0B8のマップ読込み末尾、`8001B020～8001B048`は誘致レコード先頭`800E3C00`から32バイトを原memsetで0にする。その後`8001B06C`で先頭i16の選択番号だけを-1へ変える。+30もこの32バイトに含まれる。

| 状態 | 選択番号+0 | 完成音比較欄+30 |
|---|---:|---:|
| 新規マップ読込み後 | -1 | 0 |
| 元の開始レコード書込み後 | 選択0～17 | 0を保持 |
| 今回の完成経路後 | -1 | 0を保持 |

原32バイトを事前にA5で埋めてから、4つの元TOWNを原ローダーで展開した。全て`FFFF`＋30バイトの0へ変わった。従って、エミュレーターの新規RAMがたまたま0だったことによる推測ではない。[初期化の全書込み](initialization.json)に記録した。

## 開始処理が書く範囲

原開始処理の`8006AF54～8006B038`を、18施設のページ・選択番号・原寸法に対応する矩形で実行した。

- 矩形4個のi32を+4～+19へコピー。
- 選択番号を+0へ書く。
- 原乱数から求めた4～8を+20のu16へ書く。
- +2～+3、+22～+31はこのブロックでは変更しない。新規初期化から接続した+30は0を保持する。

[開始レコードの18対応](start-record-preservation.json)を保存した。これは開始の書込みブロックと原乱数を実行した確認であり、採算判定・画面操作・支払・全呼出し先を含む開始メニュー全体の自然な通過を示すものではない。

原セーブは32バイト全体をペイロード+7D78へコピーし、読込みは逆向きに32バイト全体を復元する。したがって、**セーブから持ち込まれた+30まで常に0と決めつけてはいけない**。このコピー経路の原命令も保存した。今回セーブ媒体全体の追加往復試験は行っていない。

## 原呼出し元から比較までの値の生存

前回は同じスタック位置を使うことまで確認していた。今回は原`8002346C`から`800234A0`まで実行し、途中の呼出し先も元命令で処理した。

1. 店舗集計23C20。
2. イベント3EF44と、その原戻り値による分岐。
3. 前段275F8。
4. 完成29020。建物配置・通知文作成・通知キューへの登録・進行解除まで。

呼出し元のSPをSとすると、完成関数の未初期化ローカルFP+1CはS−36に当たる。この4バイトへ事前にDEADBEEFを置き、原処理による全書込みを追跡した。今回の全条件で、最後の書込みは店舗集計の`80023F30`だった。

| 初期マップ | 店舗集計が書いた高さの順 | 比較まで残った値 | +30 | 通知へ渡った音コード |
|---|---|---:|---:|---:|
| TOWN0001 | 20, 20 | 20 | 0 | 29 |
| TOWN0002 | 20, 20, 20 | 20 | 0 | 29 |
| TOWN0003 | 20 | 20 | 0 | 29 |
| TOWNPS | 24, 20, 20, 20, 20 | 20 | 0 | 29 |

この表の店舗高さそのものは前回も抽出済み。今回増えた証拠は、介在する関数と完成内の建物・通知文処理を実際に通しても、当該4バイトが別の値へ書き換わらないこと、及び実際の通知呼出し引数である。

原比較は符号付きの`残った値 < レコード+30`。今回の20<0は偽なので29が選ばれた。原`800292EC`で通知処理3ECD8へ渡った引数は、種別2・施設別イベント・音29・フラグ1・第5引数0だった。**音デバイスで再生して聴いた結果ではなく、原通知キューへ渡るコードを確認した結果**である。

## 入力の範囲と限界

- 4マップは元アーカイブのTOWN0001/0002/0003/PS.BINを使用し、元の初期ライバル11店を含む。
- 新規マップ読込みの外部リソースローダー140E8だけを代用し、元BINの内容を供給した。通常のCD入出力やマップ選択画面は再現していない。
- 初期マップから18施設ごとに独立した入力を作成。原配置1F1C0で(10,10)から必要寸法の誘致用地71を置き、進行レコードの選択番号・矩形・残り回数1を設定した。
- 工期の日数は進めず、資金・購入UIの可否もこの入力では検証しない。元の時刻初期値0から原イベント処理を通した結果、比較時の区分はstage1/hour0/subhour0となった。
- 実行開始は原呼出し元2346C。23438冒頭の時計+2と音声更新は含めない。これらを含む自然な更新全体を観測したとは主張しない。
- ゲームロジックの呼出し先のスキップ・結果注入・置換は0件。イベント分岐、営業前段、建物配置、通知文、通知登録は原命令を使用した。
- 年次等の別イベント、店舗の新設/撤退/改装後、外来セーブ、任意のメモリ破損は対象外。

原コードが未初期化のローカルを読む事実自体は変わらない。今回の結果から、全ゲーム状態に対して音を固定29へ置き換える仕様はまだ作らない。
