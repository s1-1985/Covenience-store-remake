# 配属確定の二段階更新と店員データの保持範囲

2026-11-17 JST。原ディスク由来の店員データ、採用候補処理6F8BC、配属確定70F48を接続した。R06/R07を追う過程で、**同じ店内の役割交換も「解除→再配属」となり、体力を最大へ戻し、経験カウンターを増やす**ことを今回明示した。

## 新規に接続した結果

70F48は旧3枠と選択中3枠を、同じ枠同士で比較する。第一巡で変更枠の旧人物を解放し、第二巡で変更枠へ新人物を配属する。

| 操作 | 旧人物 | 新人物／残る人物 |
|---|---|---|
| 同じ人物を同じ枠で確定 | 解除されない | この関数ではレコード全体が不変 |
| 店長と店員の枠を交換 | 両方を先に解除、体力を各最大へ戻す | 両方を再配属、各経験+1、役割別の体画像と休憩位置を設定 |
| 別の未所属者へ交代 | 旧人物を未所属、体力最大、行動0へ | 新人物の現在体力はこの経路では回復させず、経験+1、画像・休憩位置を設定 |
| 枠を空ける | 旧人物を未所属、体力最大、行動0へ | 枠を-1とする |

役割交換時の体力回復は「交換用の回復処理」ではなく、二巡の解除処理と再配属処理を組み合わせた結果である。人が同じなら全て無変更とする実装では、この挙動を再現できない。

採用経験+20は、今回の呼出し内では新規配属だけでなく枠交換でも増える。名前・年齢・性別・顔・時給・基本能力・仕事能力・成長目標を人物マスターから再初期化する処理はない。未所属へ戻った人の現在座標・向き・目標・ルートは解除枝だけでは一括消去されず、再配属時の原休憩処理が設定し直す。

旧人物が仕事中かつx/yが-1以外なら、その旧位置の占有セルを0へ消す。行動0または位置が無効な場合、その消去は行わない。再配属は行動0・x/y=-1を設定して原3DDA8を呼び、控え室48、見つからなければ49を探索する。
