# 店舗種類選択：未解禁6枠・建築費表示・選択時の上移動

2026-11-19 JST。［確実］原43CF4の店舗選択は、**未解禁の種類も含めて6枠を表示し、解禁状態をアイコンの明暗で分ける**。未解禁の大型店にもカーソルを合わせられ、その場合も建築費18,000,000を表示する。今回、既知の選択制御を原の描画・金額欄へ接続した。未解決6件は保留し、Android実装・APKは変更していない。

## 6枠は消さず、暗くする

表示用index/tierは0～5。入力関数44154の既知GRIDは上段1/3/5、下段2/4/6（1始まり）で、表示tierに戻すと上段0/2/4、下段1/3/5となる。

| 表示tier | 段・列（1始まり） | 原建築費 | 元画像切出しX |
|---:|---|---:|---:|
| 0 | 上段・1列 | 6,000,000 | 0 |
| 1 | 下段・1列 | 6,000,000 | 32 |
| 2 | 上段・2列 | 12,000,000 | 64 |
| 3 | 下段・2列 | 12,000,000 | 96 |
| 4 | 上段・3列 | 18,000,000 | 128 |
| 5 | 下段・3列 | 18,000,000 | 160 |

解禁数maximumは43CF4の引数で、原描画の判定は `tier < maximum`。解禁済みはRGB変調128、未解禁は64。今回はmaximum=2と6を指定した。原の上位呼出し6E998–6E9F8はCD994の符号付きバイトを3未満/5未満/それ以上で分け、2/4/6を渡す。このバイトの意味を今回新しく命名・解読したものではない。

旧premises_input.pyには、未解禁を含むカーソル移動、最大値以内だけの確定、取消時0返却が既にある。今回の限定実行は確定前までなので、未解禁建築が成立したという証拠ではない。既知の操作規則を再発見として数えず、[重複区分](reuse-audit.json)へ明記した。

## 元画像と選択中の2画素移動

画像リソース6はSHOPTYP1.TIM。既存のテクスチャ転送対応を利用すると、元切出しは(32×tier,0,32,32)。原UVは(32×tier,128)、kind13、CLUT(0,490)である。

| 要素 | 原の論理座標・仕様 |
|---|---|
| ウィンドウ | (48,32)、224×144 |
| 見出しMSG23 | (64,48) |
| 建築費MSG272 | Y64、X=`160+8×(11−原65820(金額))` |
| 非選択アイコン | (96＋48×floor(tier/2),84＋40×(tier mod 2))、32×32 |
| 選択中アイコン | 上記のYから2画素上へ移動 |

元画像のUVは選択中も変わらない。前回の控え室と同様に、実際の画面Yを書き換えて選択を示す。未解禁で暗いアイコンも、カーソルが来れば上移動する。「カーソルがあるから明るい」「暗いので配置から削除する」のどちらでもない。

maximum2・tier4の条件では、6枠すべてが存在し、tier0/1のみRGB128、tier2～5はRGB64。選択tier4のYだけ82となり、表示価格は18,000,000だった。元の41630描画レコード生成を実行して値を確認した。実GPU合成や自然な操作による到達の確認ではない。
