# 床画像・清掃能力・汚れ発生・店長の助言

2026-11-13。初代PS版SLPS_007.82の原ディスクを静的解析した。今回、既存の清掃関連アルゴリズムを実画像と初期配置へ結びつけ、**店員の清掃能力から算出する指標と、床画像のきれいな割合は別の値**だと確定した。

当初調査対象に含めた一般的な什器の劣化・故障・修理は、今回追った処理では確認できていない。以下の床の汚れを、什器の耐久値や故障システムへ読み替えない。

## 今回の追加成果

- 清潔度の生成関数 `0x8002287C` と、床を汚す関数 `0x80031498` の間にある店舗サマリー+4の受渡しを確認した。以前の床汚れモデルの引数名 `previous_cleanliness` は、前回測った床の清潔率だと読むと誤りである。ここでは配属店員の清掃能力から計算する指標を受け取っている。
- 床材3系統と各5画像を、原TIMの0～14へ対応付けた。汚れ画像1～4は累積する4段階ではなく、ランダムに選ばれる模様の違いである。
- 内蔵30配置の床データを読み、通常の床材基準は0・5・10、初期配置に汚れ画像やコード15がないことを確認した。
- 汚れを1つ追加した後も、警告カウンターは**追加前の床の割合**を使って判定することを移植仕様に含めた。

清掃能力式・床汚れ・清掃動作の単独モデルは過去成果に存在する。今回の追加は、その意味の接続、実画像・30配置の対応、値の混同を防ぐ移植データである。営業更新の長期検証は行っていない。

## 清潔度は店員の能力から算出する

原関数2287Cは、店舗+0xDD8の3配属枠を読み、参照が-1以外の店員について清掃能力の符号付きバイト+0x21を合計する。

```text
清潔度指標 = min(100, 合計清掃能力 * 100 / 店舗段階別の分母)
```

整数除算はゼロ方向への切捨て。通常の非負の能力値では小数点以下切捨てとなる。

| 店舗段階（内部値） | 分母 | 清掃能力50の店員3人の場合 |
|---:|---:|---:|
| 0 | 150 | 100 |
| 1 | 150 | 100 |
| 2 | 165 | 90 |
| 3 | 165 | 90 |
| 4 | 180 | 83 |
| 5 | 180 | 83 |

この計算では、店員の仕事状態・休憩状態・残り体力による除外は行っていない。配属された清掃能力を読む。原 `0x80023D88` で2287Cを呼び、`0x80023D98` で店舗サマリー+4へ結果を保存する。

一方、床画像から計算する値は `きれいな床枚数*100/数える床枚数` である。両者を同じ変数にしてしまうと、原版の汚れ発生条件が変わる。

## 原画像の構造

| 床材系統 | きれいな画像 | 汚れの模様4種類 |
|---|---:|---|
| 0 | 0 | 1・2・3・4 |
| 1 | 5 | 6・7・8・9 |
| 2 | 10 | 11・12・13・14 |

`floor-tiles.png` に、床・周辺に使う原タイル0～35を拡大掲載した。画像は `/TIM0/SYOP_S00.TIM` の16×16領域から切り出したもの。床材の色や見た目に独自の正式名称は付けていない。

通常の床材では、コードを5で割った商が床材系統、余り0がきれい、余り1～4が汚れである。汚れは `床材基準 + rand()%4 + 1` で選び、現在の汚れ度を1ずつ増やす処理ではない。清掃成功時は余りを取り除き、同じ床材のきれいな画像へ一度で戻す。

原床描画561CCはコード36未満を表示対象とする。ただし「描画できるコード」と「清掃対象の床」は別である。0～14以外には店舗周辺や壁・出入口の画像が含まれる。

### コード15の扱い

汚れ関数の床集計は0～15を認め、15も5の倍数なのできれいと数える。一方、清掃目標の条件は0～14。原画像の15は空白で、内蔵30配置にも現れなかった。通常の4つ目の床材として15を追加しない。集計関数の上限だけから新しい床材を推定できないためである。

## 初期配置の実データ

内蔵配置は `0x800A2074` を先頭に1件3108バイト、30件。床データは各配置+12、行間隔14バイト。実際に使う範囲は幅・高さをそれぞれ2で割った範囲となる。

| きれいな床コード | 30配置に含まれる枚数合計 |
|---:|---:|
| 0 | 1175 |
| 5 | 415 |
| 10 | 485 |

これらは配置データ中のタイル枚数で、ゲーム中の面積割合や採用率ではない。配置ごとの全コード集計と元の先頭194バイトを保存した。汚れ画像1～4・6～9・11～14は全30配置で0件だった。

## 汚れは誰の足元に発生するか

原31498は分フィールド `0x800CE618` が0の更新でだけ処理する。

1. 床コード0～15を数え、そのうち5の倍数の割合を計算する。
2. 店員能力由来の清潔度指標が、その割合より低い場合に汚れ追加へ進む。
3. 客スロット0～19を順に調べ、活動中かつ足元がきれいな対象床である最初の客を選ぶ。
4. その1か所を汚れ模様1～4のいずれかへ変更し、再描画用の店舗バイト+1を0にして終了する。

客のX・Yは0.5マス座標なので、2で割った床座標を使用する。この関数が1回の更新で複数の客の足元を汚すことはない。対象客がいなければ、ここから新しい汚れは増えない。

清潔度指標100では床画像のきれいな割合が100を超えないため、この通常追加条件は成立しない。逆に店員の能力不足で指標が低ければ、きれいな床の割合との比較によって汚れ追加が起きる。単に客が通るたびに確率で汚す方式へ置き換えない。

## 清掃の選択と成功

清掃目標39618は、コード0～14で余り1～4の床を候補にする。その床の通行可能な0.5マスを目標マークへ変換し、経路探索へ渡す。他の清掃担当が狙っている場所は、その店員の能力を使う予約判定で候補から外れる場合がある。

また、作業選択には `clock%100 <100-店員+0x20` という抑制条件がある。+0x20は清掃能力+0x21とは別の値で、ここでは確証のない能力名を割り当てない。

目標へ到着して向きも揃った後、清掃動作38894で以下を行う。

- 時計下位3bitが0なら、方向を `[1,0,2,3]` の対応で切り替える。
- 最初の乱数が `rand()%5==0` なら、次の乱数へ進む。
- 次の `rand()%100+1` が清掃能力以下なら成功し、床コードを `tile/5*5` へ戻す。

成功時は親処理が目標を解除し、清掃能力の成長処理と音声フラグ0x0800へ接続する。この音声は前回の [店員・効果音データ](../20261113-staff-sound-data/README.md) のディスパッチ24→VOS8に対応する。

## 汚れ警告の境界は追加前の値

原31498の末尾では、先に求めていた床の割合が70未満なら店舗+0x12E4を1増やす。新しく汚した後の割合を再計算しない。

例として対象床10枚のうち7枚がきれいで、清潔度指標60、対象客がいる場合：

| 項目 | 値 |
|---|---:|
| 汚れ追加前の床のきれいな割合 | 70 |
| 1枚を汚した後の実際の割合 | 60 |
| この呼出しで警告カウンターを増やすか | 増やさない |

原条件は追加前の70に対する「70未満」であり、当該呼出しでは成立しない。次回の対象更新では60を数え直す。例は原算式から導いた境界例で、実ゲームの連続記録ではない。

店長の助言3B570は自社店を対象に、このカウンターを符号付きで読み、4以上なら店長の指導力+0x1Dによる抽選を行う。カウンターは4時間区切りの処理や助言発生後などでリセットされるため、「汚れた床が4枚」や「必ず4時間後」と扱わない。
