## 座標と向きの接続

原方向テーブル `8009940C` は `[1,0,2,3]`。今回の106従業員レコードでは、従業員の外見番号・実座標・向きとグリッド画像の次の関係が一致した。

`画像番号 = 640 + 外見番号 × 4 + 方向テーブル[向き]`

| 向き | 移動方向 | 画像の方向オフセット |
|---|---|---:|
| 0 | y−1 | 1 |
| 1 | y＋1 | 0 |
| 2 | x−1 | 2 |
| 3 | x＋1 | 3 |

人物グリッド画像640〜819を描画候補とし、そのマスの下位10ビットが0であることも条件になる。36バイトレコードへの座標は基本 `x×8−160, (y−1)×8−90`。右隣マスの下位10ビットが非0ならXをさらに8減らす。端では隣を参照しない。今回この補正は従業員レコード66件で実際に通過した。

2店目では従業員ID18・34・6の移動を48回観測し、移動後のグリッド座標と実レコード座標・UVの接続を確認した。補充状態2、休憩場所への移動状態3、清掃状態4が含まれる。これは以前の移動断片と描画断片を、入力から到達した店内表示で接続した検証であり、移動式を初めて解読したという意味ではない。

従業員状態0の休憩専用追記経路は今回自然到達していない。既存の断片試験にあるその経路を今回の追加件数へ算入しない。実時間の歩行速度・GPU補間・足踏みアニメーション・画面画素・実音声も本試験の検証対象外である。

