# 商品価格UI：平均利益率と「定価／UP／OFF」の表示条件

2026-11-19 JST。既存未解決6件の保留を維持し、通常UIの価格表示側を解析した。対象は原`62CFC`の全体設定と`63714`の個別設定。**今回、Android実装・APKは変更していない**。直近の床修正版はアプリ側commit22ba479で別途実装済み。

## 全商品平均利益率の元データ

［確実］原画面の「全商品平均利益率」は、商品0～25の**価格設定値の単純平均**である。

`表示平均 = trunc(sum(店舗+C7C+商品ID×4, ID0..25) / 26)`

ここでtruncはゼロ方向への整数切捨て。通常設定0～100では小数点以下切捨てになる。この表示計算は、什器・在庫・販売数量・売上・現金26の価格設定を参照しない。原店選びの什器別価格指標とも異なる。実際の売上を加重平均して求める粗利益率へ置き換えると、PS表示と一致しない。

価格設定値から円単価を出す既知の式は、`基準価格×(原価率+設定値)/100`。今回その式を再発見として数えず、メニューが何を平均しているかを読出し側へ接続した。

## 「定価」は全商品の価格一致を示さない

原の増減表示は別に計算する。

`平均増減 = trunc(sum(現在設定[i] - 初期設定[i], i0..25) / 26)`

- 平均増減0：原文「定価」。
- 正：絶対値の数字＋%＋原文「UP」。
- 負：絶対値の数字＋%＋原文「OFF」。

初期設定は商品マスター+32。正常26件の合計は1060、平均は40となる。**平均利益率と平均増減は、それぞれの合計を別々に切り捨てる**ため、表示の変化が連動しない場合がある。`現在平均 - 初期平均`で増減表示を求める実装にもしてはならない。

| 指定した設定 | 表示平均 | 平均増減 | 原の増減表示 |
|---|---:|---:|---|
| 初期設定 | 40% | 0 | 定価 |
| 商品0を+1、商品1を−1 | 40% | 0 | 定価 |
| 商品0だけ+26 | 41% | +1 | 1%UP |
| 商品0だけ+6 | 41% | 0 | 定価 |
| 26商品を各−1 | 39% | −1 | 1%OFF |

［確実］「定価」という表示だけでは、全商品が初期価格のままだと判定できない。特に商品0だけ+6の例は、平均利益率が41%なのに「定価」と表示される原経路である。設定はすべて通常の0～100範囲内。異常メモリ値を使った現象ではない。ただし、ユーザー操作から設定を作った実プレイではなく、表示入力を指定した限定実行である。

## 個別価格と表示位置

個別画面は、既知の26件一時差分配列の**選択した商品1件**を表示する。最初の選択は商品0。表示利益率は`その商品の初期設定+一時差分`、UP／OFF／定価はその商品の差分から決まる。全体の平均増減で代用しない。

| 要素 | 原の論理座標 | 原文／参照 |
|---|---|---|
| 全体設定の見出し | (80,80) | 商品価格を決定して下さい |
| 全商品平均利益率ラベル | (80,96) | 原インライン文字列 |
| 全商品平均の数字 | (192,96) | MSG369、後ろに% |
| 定価ラベル | (180,128) | 原インライン文字列 |
| UP／OFF時の絶対値 | (164,128) | MSG369 |
| UP／OFFラベル | (200,128) | 原インライン文字列 |
| 個別の商品名 | (120,112) | MSG71+商品ID |
| 個別の利益率の数字 | (160,144) | MSG369、後ろに% |

これらは原ゲームの論理座標であり、スクリーンショットやAndroidの画素座標ではない。表示上の左右矢印、全体/個別選択と原の改行・文字制御も[捕捉した表示要求](original-cases.json)と[元文字列](inline-templates.json)へ残した。最終的な字形・色・GPU描画は確認していない。
