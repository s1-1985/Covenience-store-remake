# 内装終了の拒否理由10件とレイアウト保存確認への接続

2026-11-19 JST。［確実］原版の内装「終了」は、既知の配置検査788C8の戻り値を読み、**失敗なら案内を出して編集状態に残り、成功ならレイアウト保存確認へ進む**。現Android版の該当UI経路は配置検査を呼ばず閉じる。今回は原の数値結果と案内文・次状態を対応させた。未解決6件は保留、APKは未変更である。

## 原の案内文

戻り値0は成功で、エラーメッセージ表を引かない。1～10は800B98A4＋戻り値×4のポインターから原文字列を読む。

| 戻り値 | 原文（「／」は原の改行） |
|---:|---|
| 1 | たばこは販売できません |
| 2 | 酒類は販売できません |
| 3 | 薬類は販売できません |
| 4 | 社員控え室がありません |
| 5 | 社員控え室は／2個以上設置できません |
| 6 | レジがありません |
| 7 | レジは2個以上設置できません |
| 8 | お客さんが入れない／可能性があります／端を空けてください |
| 9 | レジが機能しない／可能性があります／レジの上下を空けてください |
| 10 | 社員が働けない／可能性があります／控え室の回りを空けてください |

元は文字制御4002による改行で、横幅から新たに折り返したものではない。「薬類」「社員控え室」「回り」といった表記を独自の言い換えへ置き換えない。[原文字コードと改行](error-message-map.json)を保存した。

戻り値0用の表位置には0x40FF0040があり、有効な文字列ポインターとして扱えない。原は成功時に表を読まないため、これを原版の異常呼出しやクラッシュとして報告しない。移植時もメッセージ0を無条件に読み込む処理にしない。

## 数値判定は既知。今回の追加は文章・上位経路との対応

旧operation_validation.pyには、販売許可、レジ・控え室の個数、入口になる店内境界、レジの通路、控え室の隣接通路の数値判定が既にある。category_parent_control.pyには結果0→state10、非0→エラー表示の経路もある。これらを新規の判定式として数えない。[再利用ファイルのハッシュ](reuse-audit.json)を記録した。

複数の条件違反がある場合は原の検査順と上書き順に従う。たとえばレジと控え室が両方ない場合、旧前段の上書き順ではレジなし6となる。UI側で見つけた違反を任意の順に表示すると一致しない。この優先順位を今回原CPUで再試験したものではない。

また、原数値モデルはレジの方向0/1では上下、方向2/3では左右の通路を要求するが、戻り値9の原文は上表の「上下」のまま。文字列側に方向による差し替えはない。原文の再現と、スマホ版独自の説明改善は別の変更として扱う。

原761B8–7620Cは戻り値を読み、0なら親state10へ進む。非0なら65080の拒否音要求、66C64への原文字列ポインター渡しを行い、親state7を保持する。描画だけ閉じて後から取り消す構成ではない。

state10の既知上位制御は、800B98D0の**「店舗レイアウトを保存しますか?」**を確認し、肯定時に既知1B8C4へ進む。これはレイアウトの保存確認であり、この文章だけをメモリーカードのゲームデータ保存と解釈しない。今回は保存処理自体を実行していない。

## 現Android版との差分

アプリcommit `22ba479999c4e025727806454b9858364ca145cc` の `game/scripts/ps1_ui.gd` は、内装メニューの「終了」をfinishへ渡し、`finish: close_window()` を呼ぶ。close_windowは画面・履歴・編集モードを解除するが、この経路に原788C8相当のチェックや上表の案内分岐はない。

したがってこのUI経路を原へ合わせるには、終了前に既知の配置検査を呼び、非0では編集を維持したまま対応する文章を表示する。0なら原のレイアウト保存確認へ進む。別の処理にある配置拒否や移動時検査が、この「終了」の検査を代替したと見なさない。[Android経路照合](android-differences.json)に該当関数とハッシュを保存した。実装は今回変更していない。
