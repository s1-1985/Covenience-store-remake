# 誘致完成音：年次評価を挟んだ呼出し元の値

2026-11-18 JST。R05の既存未解決範囲「別イベント・店舗状態での有効な最終書込み」を調査した。**［確実］原の年次評価通知を消費した更新では、共有スタック値が店舗高さではなく自社店の前年売上合計になり、誘致完成の比較まで残る限定経路を確認した。** 初期状態で得た音29を全状態へ固定する根拠にはならない。

## 既知と今回の差分

- 既知：[スタック共有の解析](../20261117-project-sound-stack-data/README.md)に、完成の未初期化値・店舗高さ・年次評価集計のアドレス一致がある。原評価と通知の単独式もr2に保存済み。
- 既知：[初期4マップ×18施設](../20261117-project-initialization-sound-data/README.md)では最後の高さ20が比較まで残り、原初期値+30=0に対して音29だった。
- 新規：年次通知の原予約→原呼出し元の集計→原年次評価消費→原前段→原完成通知、という合成で、年次の書込みが実際に残ることを確認。変更された活動店舗集合、正・零・負の診断値、通知表示中の完成予約を接続した。採点式や未初期化読出し自体の再発見ではない。

## 店舗高さから前年売上へ切り替わる

呼出し元のSPをSとすると問題の4バイトはS−36。原集計23C20が書く最後の活動店舗の高さを、原3EF44の年次評価(mode3)が上書きする。

1. 原23F30：店舗高さ24を書込む。
2. 原3F80C：年次売上集計欄を0にする。
3. 原3F930：対象の自社店の+D0C（前年売上）を加算する。
4. 原3EF44の復帰後、原275F8を経てもこの値が残る。
5. 原292B4が読み、原292BCの符号付き比較で通知音を選ぶ。

年次評価消費後は通知表示状態が1だが、原3EF44の戻り値は0であり、呼出し元23480の「戻り値1なら末尾へ」という分岐には入らなかった。評価表示開始を理由に同更新内の誘致完成を無条件に遅延させる実装とは異なる。

## 原命令で通した5条件

TOWNPSの原店1は高さ24である。今回、店2以降を診断用に非活動化し、店1を最後の活動店とした。年次条件では店1のライバル所属ビットを解除して自社店とし、前年売上を指定した。出店・撤退・買収UIからこの状態を作った実験ではない。

| 診断条件 | レコード+30 | 原年次売上入力 | 比較時の値 | 最後の書込み | 完成通知の音 |
|---|---:|---:|---:|---|---:|
| 年次通知なし・活動店集合変更 | 21 | 対象外 | 24 | 23F30 | 29 |
| 年次通知あり・同じ比較先 | 21 | 0 | 0 | 3F930 | 34 |
| 年次通知あり・原初期比較先 | 0 | 0 | 0 | 3F930 | 29 |
| 年次通知あり・負値診断 | 0 | −1 | −1 | 3F930 | 34 |
| 年次通知あり・正値診断 | 0 | 100 | 100 | 3F930 | 29 |

+30=21と前年売上−1は明示的な診断入力である。普通のプレイや実在セーブでその値になった証拠ではない。全条件で選択0の交番・同じ2×2工事を使用し、+30自体は原処理により書き換わらなかった。完成後に選択番号が−1になり、通知へ渡った引数と待ち行列内の音コードが一致した。音を実際に再生して聴いた結果ではない。

**新規マップで+30=0、今回の年次合計が0または100なら音29である。年次評価を挟むと常に34になるという結論でもない。** 比較条件は既知の `signed32(残存値) < signed16(レコード+30)` である。

## 表示中の年次評価と完成通知は別

年次条件では、元の評価通知のキュー枠1が消費され、表示状態1になった。その後の原275F8が別通知（種別3・イベント4・音30・mode1）を枠1に予約し、原完成処理は完成通知（種別2・イベント0・mode1）を枠2へ予約した。これは年次評価を表示しながら完成音が直ちに鳴るという意味ではない。

原の「現在表示中」「予約済み」「完成データの更新」を同じフラグへ潰さない。今回、年次表示状態は1のまま、交番の完成選択解除と完成通知予約が両方成立した。[結果JSON](results.json)に前後のレコード・書込みPC・5つの呼出し元観測点・残キューを保存した。

## 再現入力と範囲

原EXE、TOWNPS.BIN、MSG00.OBJは既存r2アーカイブから取得しハッシュ照合した。原マップ初期化はCD資源ローダー140E8だけを代用して原TOWNPSを供給。原予約土地配置1F1C0で4セルを置き、未完工レコードを注入した。年次の予約は原3ECD8を使い、mode3消費を直接代用していない。

マップ読込だけではユーザー入力の会社名が初期化されず、自社店を有効化した前段の文字列生成で終端が欠ける。この実験では既存TOWN0001営業診断RAMの会社名40バイトだけを供給した。原文字列の40FF終端を保持し、会社名の元位置・SHA256・実バイトを[原資料情報](source-provenance.json)へ記録。別マップ会社名とTOWNPS店舗の診断用の組合せであり、自然プレイのRAMとは扱わない。

最終再現コードの入口は14件：マップ初期化1、予約土地4セル、年次通知予約4、呼出し元5。ゲーム内の呼出し先置換0、全営業更新0、自然経過日0。原通知生成・文字列処理・年次集計・前段・完成処理を実行した。繰越決算や年初の通常操作・年次通知の自然発生までは再現していない。
