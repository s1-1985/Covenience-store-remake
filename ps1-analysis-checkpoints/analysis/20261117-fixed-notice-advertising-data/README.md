# 固定通知5・6の呼出し規約と宣伝5種の原画像

2026-11-17 JST。［確実］**通知5・6の固定テンプレートを原呼出し規約で読むと、描画幅はともに0になる。** その値を変えずに原矩形描画へ渡す場合、幅0のゲートで描画が省略される。自然プレイでこの種類へ到達するかは未確認であり、通常プレイの不具合発生を断定したものではない。

併せて通知4の宣伝5種を原PS_CM1画像へ接続した。原CPU実行・営業更新は0回。原バイトと呼出し位置・フィールド・切出し範囲の静的照合である。

## 固定テンプレートは完成済み36バイト描画レコードではない

原0x8003FF00は、0x80010974から36バイトをローカルFP+0x30へ、0x80010998から36バイトをFP+0x58へ複写する。原0x8007E57Cは指定バイト数をそのままコピーする処理で、ヘッダーの除去や構造変換はしない。

通知5は後者を、通知6は前者を使い、原0x80041630へ渡す。この関数はA0を出力スロット番号、A2をXY、A3を幅・高さとして読む。A1は入口で保存するが、その後のレコード生成で読み返していない。

| テンプレート内位置 | 実際の渡し先 | 原生成処理での意味 |
|---:|---|---|
| +0～3 | A1 | 保存のみ。この先頭値32を幅にしない |
| +4～7 | A2 | 下位16bitがX、上位がY |
| +8～11 | A3 | 下位16bitが幅、上位が高さ |
| +12～13 | 呼出し時SP+0x10 | 描画レコード種別 |
| +14～15 | SP+0x12 | U・V |
| +16～17 | SP+0x14 | レコード+16、CLUT列側の値 |
| +18～19 | SP+0x16 | レコード+18、CLUT行/参照値 |
| +20～22 | SP+0x18 | 色。今回のモード0では参照せず128へ設定 |

[全フィールドの原位置と解釈](fixed-template-argument-map.json)を保存した。生成処理が書かないレコードの+23は不定のままとし、根拠なく0埋めした完全レコードとして保存しない。

## 固定値のままなら幅0で省略される

| 通知種類 | 元テンプレート | 呼出し | X / Y | 幅 / 高さ | レコード種別 | U / V |
|---:|---|---|---|---|---:|---|
| 5 | 0x80010998 | 0x8004056C | 32 / 160 | 0 / 192 | 192 | 29 / 0 |
| 6 | 0x80010974 | 0x800406CC | 32 / 160 | 0 / 192 | 160 | 29 / 0 |

原0x80041698はA3の下位16bitから幅を生成する。原0x80084848はレコード+8の幅を読み、0x80084850で0なら0x800849A4へ進む。パケットの書込みより前の分岐なので、この幅0をGPU側の「256画素」のような表現と読み替えない。

これは**原テンプレート→原引数位置→原レコード幅→原描画ゲート**という条件付きの静的接続である。2種類の画面を実行して確認した結果ではない。別経路がテンプレートや生成後レコードを変更する可能性、自然プレイの到達性、他の画面レイヤーの表示は、この結果だけでは確定しない。

テンプレートの並びが通常の画像指定と異なって見えても、意図した値を推測してずらしたり、幅を32/256へ修正したり、架空の画像を追加したりしない。前回の直接予約34箇所には定数の画像種類5・6がなかったが、それも全コード経路で未使用だという証明ではない。

0x80041630のレコード生成規則と0x80084830の幅0ゲートは、既存r2で判明していた。今回新しく接続したのは、前回未解釈のまま保存した2つの固定値が、その実際の呼出しではどう読まれるかである。

## 通知4と宣伝5種の画像

宣伝マスターは原0x8009FE40から44バイト×5行。+28の通知パラメータ0～4を、原0x8002798Cなどが読み、種類4の通知へ渡す。費用や人気加算、時刻などの宣伝仕様は既存解析を再利用した。

通知4は画像16・PS_CM1をロードし、0x8006A304がU224・V=`96+32×パラメータ`、描画レコード種別29、32×32、CLUT行495を指定する。

| 宣伝 | 通知パラメータ | 原U / V | 元PS_CM1の切出し |
|---|---:|---|---|
| ダイレクトメール | 0 | 224 / 96 | (224,0,32,32) |
| 新聞広告 | 1 | 224 / 128 | (224,32,32,32) |
| 飛行船 | 2 | 224 / 160 | (224,64,32,32) |
| ラジオＣＭ | 3 | 224 / 192 | (224,96,32,32) |
| テレビＣＭ | 4 | 224 / 224 | (224,128,32,32) |

PS_CM1の転送先は16bit語単位(832,352)、描画ページ基点Y256である。そのためUVのV96が元画像のY0へ対応する。全5矩形が256×160の元画素内に収まった。

[宣伝名・原パラメータ・切出し・ハッシュ](advertisement-notification-crops.json)に画素番号1,024個と原BGR555/STP色ワード2,048バイトのSHA256を保存した。パレットと元TIM全体のハッシュも別に保持する。宣伝5種類や通知パラメータ自体は既知であり、今回の追加は実画素への接続である。

PNGは原色ワード0を透明とした参照画像である。原UIの色効果、点滅、文字、最終GPU合成、宣伝の自然実施を観測したものではない。
