# 人数0の客：会計0円・レジ使用・退出解放の3接続

2026-11-18 JST。**［確実］会計位置などを指定した限定入力では、人数0でも原会計が成功し、入金0円で会計完了フラグが立ち、同じ更新の後続客はレジ待ちを続けた。退出到着条件では占有が消え、枠は再利用可能になった。** 祭りで生じた客が自然にこの会計・退出位置へ達した証拠ではない。

## 既存との区別

[前回](../20261118-festival-empty-slot-lifecycle/README.md)は、原の範囲外需要書込みで人数0の枠が活動し、入店・初期移動へ進むところを確認した。そこで得た32バイトの客レコードを今回の基点とした。異常枠を作る需要処理や入店は再試験していない。

会計の `かご額×人数`、店員の同更新内使用済み判定、退出処理と空き枠探索の単独式は既存r2の `customer_queue_state.py`、`cashier.py`、`customer_position.py` 等にある。今回の新規部分は、確認済みの人数0を原会計成功・後続客・退出後の空き枠まで接続した結果である。通常ルール3件を新発見したとは数えない。

## 1. 入金0円でも会計成功の処理は進む

14×14の診断用店舗へ原レジ37のアンカーを(2,2)に置いた。原マスター上の幅2・高さ1を使用し、客は(3,4)で上向き、店員は(3,1)で下向きとした。両者の正面は同じレジへ対応する。配置UIや占有形状全体を検証した店ではない。

前回の人数0レコードを会計状態3へ変更し、目的地を現在位置へ、経路をFFへ、かご額を250へ設定した。店員はレジ状態1・レジ能力100、乱数seed0。原32814から後半の客ループを実行し、内部の原35128・3839C・1CA7Cを置換せず通した。

| 先頭客の人数 | かご額 | 自社資金 | 店舗売上増分 | 客の状態 | かごの後値 | 完了フラグ |
|---:|---:|---|---:|---|---:|---|
| 0（前回観測値） | 250 | 10,000→10,000 | 0 | 会計3→購買後4 | 0 | 0x200あり |
| 1（対照） | 250 | 10,000→10,250 | 250 | 会計3→購買後4 | 0 | 0x200あり |

原352DC～352F4は符号付き16bitのかご額と符号付き8bitの人数を乗算する。原35304が売上処理1CA7Cを呼ぶ。人数0でも呼出し自体は省略されず、引数の金額が0になる。その後、かごを0へし、フラグ0x200を立て、状態4を返す。

これは客への500円支給やATM出金ではない。所持金のフィールドは前回の予算値を保持する。0x200は原の会計完了イベント用フラグであり、音を再生して聴いた結果でもない。Android側で「売上が増えたときだけ会計完了」とすると、この限定した原挙動とは一致しない。

## 2. 人数0でも同更新のレジ担当を使用する

次の枠に、同じレジへ正面を向けた1人客を別の隣接セル(4,4)へ置いた。かご額250、待機能力100とし、同じ原ループで先頭客の後に処理した。2人が同じセルへ重なる入力ではない。

両条件とも、原3871Cが店員枠0の使用済み値を0→1にした。原3839Cの2回の入口で観測した使用済み値は順に0、1。2人目のかごは250のまま、状態3を維持した。入金処理の呼出しは先頭客分の1回だけだった。

人数0の場合でもサービス能力と条件が通れば店員を使用済みにすること、その処理が同じループの後続客を待たせることを確認した。人数0をサービス前に除外する実装との差になる。

この使用済み値は通常の主更新の店舗準備でリセットされる既知の一時状態である。ここから恒久的な店員停止、実秒の待機時間、動画で報告された遅延の原因までは導かない。

## 3. 到着済みの退出では占有と枠を解放する

人数0で会計済みとなった実レコードを使い、状態5・位置(0,1,2)・同じ退出目標へ設定した。経路をFFへし、境界セルに客の占有値を置いた。そこまでの歩行と退出先選択は今回通していない。

原後半ループは退出35770を呼び、位置・方向が目標と一致すると作業位置を全−1へし、戻り値0を客状態に保存した。原の位置反映が境界セルの占有値2621440を0へする。その後、原330E4の空き枠探索は枠0を返した。

| 項目 | 前 | 後 |
|---|---|---|
| 状態 | 5 | 0 |
| 占有値 | 2621440 | 0 |
| 記録内の座標 | (0,1,2) | (0,1,2)のまま |
| 記録内の目標 | (0,1,2) | (−1,−1,−1) |
| 人数・来客・集計内人数 | 0 | 0 |
| 原空き枠探索 | 未実行 | 枠0 |

退店した枠の記録座標まで全消去されるわけではない。活動状態・占有・座標の残存を分けて移植する。人数0のこの経路が必ず永久に枠を占める、という解釈はこの到着済み入力では成立しない。一方、自然に退出先へたどり着けるかは未確認のままである。
