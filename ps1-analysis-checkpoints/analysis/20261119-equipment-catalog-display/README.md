# 設備選択UI：39件の一覧・表示用24時間維持費・原画像と許可表示

2026-11-19 JST。［確実］原の設備選択画面67C80は、**維持費を営業時間に関係なく24時間分で表示する**。現Android版の営業時間に応じた表示とは異なる。また、既知の原一覧39件に対して現Android版の設定は37件で、欠落と別経路の設備の混入があった。今回は既知セレクターを原表示・現在の移植差分へ接続した。未解決6件は保留し、Android本体・APKは変更していない。

## 表示用の維持費と実際の費用を分ける

原68130–68174は選択した什器マスター+8の1時間分レートを24倍し、MSG296で「維持費」の右へ表示する。現在の営業時間+0xC78はこの計算に使わない。

| 指定した表示条件 | 原画面の維持費/日 | 既知の実営業時間の設備費計算なら |
|---|---:|---:|
| コピー機35、8時間営業ID1 | 1,200 | 400 |
| タワー駐車場52、臨時休業ID6 | 4,800 | 0 |

右列は11月13日の既知mode0費用式からの計算であり、今回営業を進めて引き落とした結果ではない。休業中の費用表示4,800を根拠に、休業中も同額を徴収するとは解釈しない。実費関数・レート自体を新しく解読したわけではなく、**この選択画面が固定24倍を使うこと**と表示位置を接続した。

原画面の「収納力」はマスター+12、「注目度」は+16、「価格」は+4を読む。選択名はMSG387＋什器ID。原のコピー機35では収納力20・注目度10・価格1,500で、ユーザー提示画像とも数値が対応する。画像からの推定ではなく、今回の原処理でもこの参照を確認した。

これは全什器マスター53件をそのまま並べた画面ではない。選択indexと什器IDも別で、例えば選択0はコピー機35。除外14件がゲーム内で一切使用できないという意味ではない。レジ・控え室の専用選択経路などは既存のcategory_parent_control.pyと内装取引解析にある。

## 原の配置と許可による明暗

座標は320×224の論理画面。ページ内slotは0始まりで、cは各ページの列数。

| 要素 | 原仕様 |
|---|---|
| ウィンドウ | (32,24)、256×192 |
| 見出し | (48,40)「設備を選択して下さい」 |
| 選択名 | (48,56)、MSG387＋什器ID |
| 収納力・注目度の数字 | (240,40)、(240,56)、MSG369 |
| 価格 | Y72、X=`74+8×(6−原65820(価格))`、MSG28 |
| 維持費 | Y72、X=`182+8×(8−原65820(時間レート×24))`、MSG296 |
| アイコン左上 | (60＋40×(slot mod c),88＋40×floor(slot/c))、32×32 |
| カーソル要求座標 | (83＋40×(slot mod c),111＋40×floor(slot/c)) |

原687C4はマスター+80の画像番号からUVを作る。kind25、CLUT(0,491)。全39件について画像番号・UVと配置を[equipment-ui-map.json](equipment-ui-map.json)へ保存した。画像番号を無条件に「什器ID＋1」と置換しない。たとえばタワー駐車場52の元番号は48である。ただしAndroidのアトラスがどう並べ替えられたかまでは今回調査していないため、その番号差だけでAndroid画像の誤りを断定しない。

タバコ許可+0xC74が0だと、什器27/28のRGB変調要求は64、それ以外は128。許可があれば27/28も128になる。表示枠を削除して詰めるものではない。原の許可なし/ありで同じページを実行し、対象2枠だけ変調要求が変わることを確認した。確定拒否自体は旧モデルの既知仕様であり、今回は再実行していない。GPU合成後の色や明るさ比を実測したものではない。

現Androidのps1_ui.gd::_fixturesは全ページ5列、アイコンY96、ウィンドウ(44,45,230,166)、維持費を営業時間で乗算する。[Android照合結果](android-differences.json)に設定差分とソースハッシュを保存した。スマホのタップ操作は維持し、原のページ別配置と選択可能な設備だけを対応させることが実装方針となる。
