## 原表示と採点境界

表の数値以上で対応する点数を得る。比較値は原EXEの命令即値から取り出し、原コード範囲をバイト列で添付した。

| 原項目名 | 点数が上がる境界 | 点数 |
|---|---|---|
| 店舗数 | 1～10店舗 | 1店舗につき2点 |
| 累積来客数 | 50,000 / 100,000 / 200,000 / 400,000 / 500,000 | 4 / 8 / 12 / 16 / 20点 |
| 年商 | 100,000,000 / 200,000,000 / 300,000,000 / 400,000,000 / 600,000,000 | 4 / 8 / 12 / 16 / 20点 |
| 町人口 | 3,000 / 8,000 / 14,000 / 18,000 / 20,000 | 4 / 8 / 12 / 16 / 20点 |
| 店舗評価 | 10 / 30 / 50 / 70 / 90 | 4 / 8 / 12 / 16 / 20点 |

店舗数は最初の10枠のうち稼働中・自社の店舗だけを数える。年商はその店舗の**前年度収益欄+0xD0Cの合計**、店舗評価は**+0xC68の平均を切捨て**た値である。+0xC6Cの人気とは別データになる。年商の正数加算オーバーフローは原処理どおり2,147,483,647へ飽和させる。

町人口は住宅だけでなく、町全カテゴリの客構成から計算する。学校、会社、公共施設の客構成人口も含む。累積来客数は自社への入店数量カウンターであり、買物成立件数でも、その年だけの来客数でもない。原年次帳簿繰越はこの累積値を初期化しない。原保存ペイロードでは+0x85D8の4バイトへ保存する。

[原文字列](source-labels.json)に12×16原フォントの既存対応表による転写と16bit文字コードを併記した。[採点定数](evaluation-thresholds.json)も参照。

## 合計96点以上が100点になる

5項目の素点合計が96点以上なら表示・判定値を100にする。このため、採点式から導かれる最小店舗数は**8店舗**である。

- 8店舗: 店舗16点＋他4項目各20点＝96点→100点。
- 9店舗: 店舗18点＋他4項目各20点＝98点→100点。
- 10店舗: 他4項目すべて20点、または1項目だけ16点で残り20点なら100点。

8/9店舗の場合は、累積来客50万人以上、年商6億以上、町人口2万人以上、平均店舗評価90以上が必要となる。10店舗なら4項目のうち1項目だけ1段階低くてもよい。[全7組合せ](perfect-score-combinations.json)を保存した。これは元の採点式の組合せからの導出であり、自然プレイで達成した記録ではない。

モード2/3では表示100点を条件に対応する解除ビット4/8と終了保留値2/3を設定する。モード1の「10店舗」目標は別関数の判定であり、こちらの年次評価条件へ混ぜない。

星表示は各項目 `trunc(点数/4)`、総合 `trunc(総合点/20)`。例えば店舗1件の2点は星0個、2件の4点で星1個になる。

原初期データには自社店がない。原評価関数は自社店数で除算するため、初期ファイルを直接評価して架空の総合0点を作っていない。初期11店はすべて+0xC68が10、人気+0xC6Cが20、前年度売上+0xD0Cが0であり、自社平均への集計対象ではない。

前回抽出した各マップ/誘致種類の最安地点1件ずつ、計72件について、撤去される建物全体の人口を引き、完成建物の客構成による人口範囲を加えた。例えばTOWNPSで初期最安地点(0,0)に中学校を独立に完成させる計算では2,839→3,039、人口得点0→4となる。TOWN0001の同地点で大学なら2,718～3,110で、客構成次第で3,000境界をまたぐ。

[人口と評価の接続72例](project-population-score-links.json)は自然発展や他の工事を止めた静的な置換計算である。客構成の最小・最大はセル選択からの理論的範囲であり、1つの乱数シードで両端を実現できるという主張は含めない。

## 年初の順序と通知

年初条件は原の月=1、日/区分=1、時=0、時刻内区分=0。年次決算で+0xCE8の当年度5欄を+0xCFCの前年欄へ繰越し、当年度を初期化する。その後、月次通知(mode2)、年次通知(mode3)の順で予約する。

通知の消費は各外側更新の前段、年初通知の予約は後段である。したがって新規予約した年次評価は後続更新で消費され、繰越後の前年売上を読む。町人口と店舗評価も予約時のスナップショットではなく**消費時の値**を使う。先行通知が残っている場合の遅延も維持する。
